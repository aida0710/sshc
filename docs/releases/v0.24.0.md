# sshc v0.24.0

v0.24.0では、Linuxでengineを常駐させる`sshc service`を追加しました。また、engineを再起動しても、登録済みのブラウザーやインストールしたWebアプリからsshcを開き直せるようになりました。

あわせて、Syncのスナップショットをv6へ移行し、ファイルの実行権限、競合、S3エラー、Force Pushを含む同期処理を見直しています。CLI補完、SFTP、Workspace、Settings、キーボードとAndroidの操作も改善しました。

## Linuxの常駐サービスと更新

- systemdを使用するLinuxで、`sshc service install`、`sshc service status`、`sshc service disable`を利用できるようになりました。ユーザーサービスとして動作するため、sudoは不要です。
- `service install`は、Homebrewまたは公式の`install.sh`で導入された安定した実行パスだけを登録します。手動配置やソースビルドは推測で登録せず、既存の手書きunitも上書きしません。
- unitの作成、削除、更新時の再起動を排他し、処理中にunitが書き換えられた場合は操作を中止します。インストール時は、systemdのMain PIDとsshcの状態を確認し、engineが実際に起動してから成功を返します。
- `sshc update`は、sshcが管理するサービスが動作中で、登録されている実行パスが更新対象と一致する場合だけ再起動します。停止中のサービス、手書きunit、別の場所にあるengineは変更しません。再起動後はVaultがロックされるため、`sshc vault unlock`を実行してください。

## ブラウザー登録とPWA

- 初回に`sshc`でブラウザーを登録すると、以後はブックマークやインストールしたWebアプリから直接開けるようになりました。engineを再起動してローカルセッションが切れた場合も、同じブラウザーとポートであれば自動で再認証します。
- ChromeとEdgeからsshcをWebアプリとしてインストールできるよう、アプリアイコン、Web App Manifest、Service Worker、オフライン画面を追加しました。Webアプリはengineを起動しないため、先に`sshc engine`またはOSのサービスを起動してください。
- デスクトップ版は最初に`127.0.0.1:54447`を使用し、使用中であれば空きポートを端末固有の設定として保存します。固定したURLは、ブックマークとWebアプリで引き続き利用できます。
- ポートを変更した場合や、保存していたポートを利用できずURLが変わった場合は、以前のブラウザー登録を失効します。新しいURLで`sshc`を一度実行して登録し直してください。同じポートでの再起動では登録を引き継ぎます。
- ブラウザー登録の実トークンはブラウザー側だけに保存し、端末には検証用のハッシュだけを残します。ワークスペースと同期スナップショットには含めません。
- オフライン画面の再読み込みボタンがContent Security Policyによって動作しない問題を修正しました。

## Sync

- スナップショット形式をv6へ更新しました。v5のスナップショットと同期状態は受信時に自動で変換します。受信専用端末はS3へ書き込まず、次に送信できる端末がPushしたときにv6として保存されます。
- 通常ファイルと実行ファイルを区別し、内容だけでなく所有者の実行権限もPullで復元するようにしました。権限だけが変わった場合も差分や競合として扱い、競合画面には前回、このマシン、リモートの権限を表示します。読み取り専用になったローカルファイルも受信できます。
- Pullで内容の変更がなかった場合も、確認したリモートの世代を同期状態へ記録します。次のPushで、すでに確認済みの更新を`remote moved`と誤判定しません。
- ファイルの適用と同期状態の保存を1つの復旧可能なtransactionへまとめました。途中で終了しても、更新済みファイルと古い同期基準が混在しないようにしています。未復旧のtransactionがある間は、新しい変更とスナップショット作成を拒否します。
- Force Pushの確認を、確認時のバケット設定、保存世代、同期先、リモートETagへ結び付けました。確認後にバケットやパス、資格情報、リモート内容が変わった場合は、その確認を使って別の同期先を上書きしません。
- Windowsで表現できないパスや、OSによって同じ名前として扱われる大文字・小文字、Unicodeのパス衝突を、送信前と受信前に検出します。該当するパスを表示し、別のOSで復元できないスナップショットの作成を防ぎます。
- S3互換ストレージの失敗を、認証失敗、アクセス拒否、要求制限、一時的なサービス停止へ分類しました。画面とCLIには、資格情報、バケット、リージョン、権限、再試行のどこを確認すべきかを表示します。
- `sshc sync now`と対応するHTTP APIは、内部の同期処理に失敗した場合に成功を返さないよう修正しました。自動化から終了コードとエラー種別を判定できます。
- リモート履歴の追跡を固定件数で打ち切らず、認証済みの履歴をたどって共通の同期元を確認するようにしました。履歴が数件以上進んだだけでForce受信が必要になる問題を防ぎます。
- バケットの履歴や状態を取得している間は、PushとPullの操作全体を止めないようロック範囲を分離しました。S3の応答や履歴一覧に時間がかかる場合も、同期操作を不必要に待たせません。
- ファイル権限を含む旧transaction journalを復旧できるようにし、暗号化に使用した導出済みの鍵は処理後にメモリから破棄するようにしました。

## CLI

- bash、zsh、fish向けの補完を追加しました。サブコマンド、オプション、選択肢に加え、`sshc ssh`、`sshc info`、`sshc terminal create ssh`では、現在のOpenSSH設定にある接続先を補完します。Homebrew版では補完も自動でインストールされます。
- CLIのコマンド解釈、個別ヘルプ、bash／zsh／fishの補完を、同じコマンド定義から生成するようにしました。新しいコマンドや選択肢を追加した場合に、コマンド解析、ヘルプ、補完の一部だけが古いまま残ることを防ぎます。
- `sshc service`を含むコマンド全体を補完対象にしました。
- Vaultの作成、ロック解除、マスターパスワード変更では、パスワードの入力を読み始める前に端末のechoを無効にします。入力した文字が一瞬表示される可能性をなくしました。

## Terminal、Workspace、画面操作

- 未保存のワークスペースにも名前を付けられるようになりました。名前変更は、Terminal上の操作ボタンと重ならないよう、ワークスペース一覧のメニューへ移動しました。
- 上下に分割したTerminalで、下側ペインの最終行が隠れる問題を修正しました。
- モバイルでは、ワークスペース名と現在のペインを残し、名前変更とその他の管理メニューだけを狭い画面で非表示にしました。分割したTerminalは、これまでどおり1ペインずつ切り替えられます。
- メニュー、ポップオーバー、Command Palette、モーダル、モバイルInspectorの閉じ方を揃えました。外側のクリック、Escapeキー、Androidの戻る操作で閉じ、操作後は開く前のボタンへフォーカスを戻します。
- メニューを開いたときは最初の項目へフォーカスし、上下キーとHome／Endキーで移動できます。Connectionsの設定タブは左右キーとHome／Endキーで切り替えられます。モーダル内ではTabキーの移動を最前面のダイアログ内に留めます。
- モバイルのセッション操作とTerminalツールバーのタップ領域を約40pxへ広げました。Androidのドロワーは、OSの戻るジェスチャーと競合していた画面端からのスワイプ起動を廃止し、メニューボタン、外側のタップ、戻る操作で扱います。
- macOSで別のウインドウへ切り替えたときに、画面が一瞬ちらつく問題を抑えました。

## SFTPとAPI

- SFTPで接続先を切り替えると、前の接続先の一覧と開いていたファイルをすぐに閉じるようにしました。切り替え前の通信が遅れて完了しても、新しい接続先の画面へ内容やエラーを表示しません。
- 転送ジョブで実行できる一時停止、再開、再試行、キャンセルをengineが返すようにしました。画面を再読み込みした場合も、表示中の状態から操作可否を推測せず、engineが管理している状態に従います。
- Web UIとengineの間で送受信するJSONを、OpenAPIに記載した形式と実行時に照合するようにしました。不正な値や不足した項目を画面の状態へ反映する前に検出します。
- Keys、Remote Keys、Snippets、Workspace、SFTPなどで重複していたAPIの型と検証処理を、OpenAPIから生成する共通定義へ揃えました。

## Settings

- MenuのSettingsを、Engine、Terminal、ブラウザー通知、開いている接続、マスターパスワードの個別ページへ分けました。目的の設定へMenuから直接移動できます。
- Engine設定には、固定ポートとブラウザー登録への影響を明記しました。旧Settings URLは廃止し、各設定ページを正規の導線にしています。

## 検証

- Goの全パッケージテスト、変更箇所のrace test、`go vet`、Webの1,099テスト、TypeScript、ESLint、production buildを実行しました。
- Syncでは、権限だけの変更、v5からv6への移行、transaction復旧、Force Pushの確認境界、portable path、S3エラー、履歴が長い場合を含むテストを追加しました。実S3互換ストレージのテストも、製品と同じ設定検証を通して実行します。
- systemdサービスでは、既存unitの保護、並行操作、起動確認、更新時の再起動対象を検証しています。360px幅のブラウザーでは、Workspace、メニュー、モーダル、タップ領域を確認しました。
- CLI、OpenAPI validator、埋め込みWeb UIの生成物は、再生成して差分が出ないことをCIで検査します。
