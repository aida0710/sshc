# sshc v0.39.0

v0.39.0では、VPNプロファイルを接続先から切り離しました。これまでは1つのプロファイルが1つの接続先だけを持っていましたが、今回からプロファイルはVPNへ接続するための設定とシークレットだけを持ちます。パスワードと同じように、Connectionsで接続にプロファイルを付けると、その接続の`HostName`と`Port`へVPN経由で接続します。1つのプロファイルを複数の接続に付けられます。

あわせて、macOSでVPN経路がDockerを見つけられない問題、Terminalから開いたVPN経路が30秒で打ち切られる問題、プロファイルを編集できなかった問題を直しています。Web UIの`ProxyCommand`はログインシェルの`PATH`で実行するようになり、画面の日本語の表記も揃えました。

## 接続ごとのVPN

- **VPNプロファイルは接続先を持たなくなりました。** これまでは、プロファイルに「VPN内の接続先」を1つ指定し、接続の`HostName:Port`と一致しない場合は接続を断っていました。今回から接続先は、プロファイルを付けた接続の`HostName`と`Port`です。VPN画面とプロファイルのフォームから接続先の欄はなくなりました。
- **プロファイルは接続の側で付けます。** ［Connections］の［sshc］タブの「使用するVPNプロファイル」、または`sshc vpn bind <alias> <名前>`で付けます。VPN画面では、そのプロファイルを使っている接続を一覧で確認できます。VPN画面から接続を付け外しする操作はなくしました。
- **接続先へ届かなかった理由を表示します。** VPNには接続できたが接続先へ届かない場合、「VPN内のDNSサーバーで接続先の名前解決に失敗しました」「接続先が応答しないか、接続を拒否しました」などをTerminal、SFTP、`sshc <接続先>`に表示します。`HostName`がホスト名の接続に、DNSサーバーを指定していないプロファイルを選んだ場合は、Connectionsに注記が表示されます。
- **プロファイルを編集できるようになりました。** v0.38.1では、作成済みのプロファイルを変更する操作が画面にもCLIにもありませんでした。VPN画面の「編集」と`sshc vpn edit <名前>`で変更できます。空欄のシークレットは保存済みの値のまま残ります。
- **Terminalから開いたVPN経路が、30秒で打ち切られなくなりました。** これまではSSHの接続タイムアウト（既定30秒）の中でVPN経路の起動も待っていたため、WireGuardのハンドシェイクの失敗が「タイムアウト」と表示され、スマートフォンでの承認も30秒以内に行う必要がありました。VPN経路は経路の上限（承認待ちは2分）で待ち、接続タイムアウトは経路が用意できてから数えます。
- **VPNの失敗は日本語で表示し、同じ理由では再接続を繰り返しません。** これまではVaultのシークレットが無い場合などに、Terminalに英語のエラーがそのまま表示され、再接続を5回繰り返していました。シークレットが無い、Dockerが起動していない、ハンドシェイクに失敗したなど、設定を直さない限り同じ理由で失敗する場合は、理由を表示して再接続を止めます。
- **`sshc vpn proxy`は接続先（`%h %p`）が必須になりました。** `ProxyCommand sshc vpn proxy <名前> %h %p`と書いてください。
- 接続ごとに`docker exec`でコンテナの中継を起動する仕組みに変えました。コンテナの中で作ったソケットをホストと共有しないため、macOSとWindowsのDocker Desktopでも同じ仕組みで動きます（実機での確認はLinuxのみです）。
- プロファイルの削除と名前の変更では、設定を保存してから経路を停止するようにしました。削除の途中にTerminalが再接続して、削除したプロファイルの経路が起動し直すことはありません。Dockerが止まっていても、削除と名前の変更はエラーになりません。
- 設定とシークレットの長さの上限を、画面、CLI、engineで揃えました。CLIから長すぎる値を保存すると、VPN画面が一覧を表示できなくなる問題がありました。

## macOSとDocker

- **macOSで、VPN経路がDockerを見つけられない問題を直しました。** launchdが起動したengineの`PATH`にはDocker Desktopの`/usr/local/bin`やHomebrewの`/opt/homebrew/bin`が含まれず、「docker is not available」と表示されていました。engineはログインシェルの`PATH`でdockerを探して実行します。
- Dockerが見つからない場合と、起動していない場合を分けて、日本語で表示します。

## Web UIのProxyCommand

- **Web UIの`ProxyCommand`を、ログインシェルの`PATH`で実行するようにしました。** これまでは、`.zprofile`や`.zshrc`で`PATH`に追加したコマンド（`aws`、`session-manager-plugin`など）が、ターミナルの`ssh`では動くのにWeb UIでは見つかりませんでした。取得するのは`PATH`だけで、ほかの環境変数やaliasは取り込みません。CLI（`sshc <接続先>`）は、これまでどおり起動したシェルの環境を使います。

## 日本語の表示

- 画面とAndroidアプリの日本語で、英単語の前後の空白を外して表記を揃えました（例: 「Vault のロック状態」→「Vaultのロック状態」）。

## 削除した機能

- 古いバージョン向けのAPIを削除しました。`PUT /api/v1/sync/settings`（v0.15.0で`/api/v1/sync/setup`に置き換え）と、`PUT`／`DELETE /api/v1/passwords/{alias}`（`/api/v1/credentials`に置き換え）です。Web UIとCLIは使っていません。
- v0.33.0より前のブラウザに残っているキー設定を、読み込む処理を削除しました。そのブラウザでは既定のキー設定になります。

## 更新後に必要な操作

更新後はengineを再起動して、新しいバージョンを使用してください。

**設定を同期しているマシンは、すべてv0.39.0に更新してください。** 設定ファイル（`~/.ssh/sshc/metadata.json`）の形式を更新したため、v0.38.1以前のsshcは、v0.39.0が保存した設定を読み込めません。VPNプロファイルの接続先は、読み込んだときに削除されます。プロファイルを付けていた接続はそのまま残り、同じ接続先へ接続します。

VPN機能を使用している場合、次にVPNに接続するときに、コンテナイメージがマシン上で1度だけ作り直されます。作成にはネットワークが必要です。`ProxyCommand`で`sshc vpn proxy`を使っている場合は、`%h %p`を付けてください。
