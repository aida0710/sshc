# sshc v0.43.0

v0.43.0では、SFTPのテキストエディタを改善しました。ChromeなどTrusted Typesを強制するブラウザで本文が表示されなかった不具合を修正し、検索や置換などのエディタの機能を使えるようにしました。保存が競合したときは、確認したうえで上書き保存できます。

あわせて、SFTPのコピーと移動で転送元のファイルが失われる不具合を修正し、背景画像の追加、CLIのターミナルの表示名、VPNの接続を止める処理を改善しています。

## 更新後に必要な操作

- 更新後はengineを再起動してください。`sshc update`で更新した場合、`sshc service install`で登録したサービスは自動で再起動されます。`sshc update`を使わずに更新した場合（`brew upgrade`、install.shやinstall.ps1の直接実行）、サービスは`sshc service install`で再起動します。サービスとして登録していないengineは`sshc engine --replace`で再起動してください。
- 更新の前から開いているWeb UIのタブは、engineを再起動したあとに再読み込みしてください。古い画面のままでは、SFTPのエディタの修正が反映されません。
- VPN機能を使用している場合、次にVPNに接続するときに、コンテナイメージがマシン上で1度だけ作り直されます。作成にはネットワークが必要です。

## SFTPのテキストエディタ

- **ChromeなどTrusted Typesを強制するブラウザで、エディタの本文が表示されるようになりました。** v0.24.0から、これらのブラウザではエディタの本文の欄が空になっていました。入力と保存はできましたが、開いたファイルの内容が見えませんでした。
- これまでは`Ctrl+F`を押すとブラウザの検索になり、エディタの機能は使えませんでしたが、**検索や置換などの操作ができるようになりました。** 検索は`Ctrl/Cmd+F`、置換は`Ctrl+H`（macOSでは`Cmd+Option+F`）、行へ移動は`Ctrl+G`、行のコメントの切り替えは`Ctrl/Cmd+/`、エディタのコマンドパレットは`F1`です。折りたたみや複数カーソルなど、そのほかの操作とキーは、エディタのコマンドパレットで確認できます。
- 検索欄やエディタのコマンドパレットを`Esc`で閉じても、エディタは閉じません。検索欄、エディタのコマンドパレット、右クリックのメニューは英語で表示されます。
- 補完は、入力中に自動では表示されません。`Ctrl+Space`で呼んだときだけ表示されます。改行のつもりで押した`Enter`で、入力した語がファイルの中の別の語に置き換わることはありません。
- 速く入力すると、文字が失われたり、入力した文字がファイルの先頭に入ったりする不具合を修正しました。この状態で保存すると、崩れた内容がリモートのファイルに書き込まれていました。
- JSONのファイルを開くと、書式の誤りに波線が表示されるようになりました。ChromeなどTrusted Typesを強制するブラウザでは、これまでJSONの検証が動いていませんでした。
- これまでは、エディタで開いたあとにリモートのファイルが変更されていると、保存は失敗し、［リモートから再読み込み］しか選べませんでした。**確認したうえで［上書き保存］も選べるようにしました。** 確認のダイアログは、リモートでの変更が失われ、エディタの内容に置き換わることを示します。確認しているあいだにリモートのファイルがまた変更された場合は、上書きせずにもう一度知らせます。

## SFTPのコピーと移動

- **同じサーバーを別の接続先として2つ登録しているとき、片方から、もう片方の同じパスにあるファイルへ上書きを承認して移動すると、そのファイルが消える不具合を修正しました。** 転送元のファイルそのものへのコピーと移動は、何も変更せずに「転送先が転送元のファイルそのものであるため、コピーも移動もできません。」と表示して断ります。パスの途中のシンボリックリンクを経由して同じファイルを指している場合も同じです。
- フォルダを、そのフォルダ自身か配下へコピー・移動しようとすると、「転送先が転送元のフォルダ自身かその中にあるため、コピーも移動もできません。」と表示して断るようにしました。これまでは理由の分からない失敗になり、転送先のパスの途中にあるシンボリックリンクを経由する場合は見逃していました。
- 同じ接続先で、フォルダやファイルを同じパスへコピー・移動しようとすると、上書きの確認を承認しても確認に戻り続ける不具合を修正しました。上書きの確認を出さずに、すぐに断ります。
- 2つの接続先から同じ場所が違うパスに見える場合は、転送元と転送先が重なっていても検出できません。chroot、bind mount、大文字小文字を区別しないサーバーで大文字小文字だけが違うパスがこれに当たります。この場合に移動の上書きを承認すると、転送元が失われることがあります。

## 背景画像

- これまでは、背景画像を追加するときに画像の全体をengineのメモリに読み込んでいましたが、**受け取りながらファイルへ書く方式**に変更しました。容量の上限を大きくしていても、engineのメモリが画像の大きさの分だけ増えることはありません。1枚の上限、対応する画像の種類、名前の付け方は変わりません。
- 画像を受け取っている途中でengineが終了して残った一時ファイル（`~/.ssh/sshc/backgrounds/.sshc-background-*`）は、次にengineを起動したときに削除します。

## CLI

- `sshc terminal rename <session-id> --auto`で、ターミナルの表示名の固定を外し、自動の名前に戻せるようになりました。画面の［自動の名前に戻す］と同じ操作です。`--json`の結果の`presentation.titlePinned`で、固定が外れたことを確かめられます。
- **`-`で始まる名前は、`sshc terminal rename <session-id> -- -dev`のように`--`の後ろに書いてください。** これまでは`sshc terminal rename <session-id> -dev`で`-dev`を名前として付けていましたが、未知のオプションとして断るように変更しました。

## VPN

- VPNの接続を止めるとき、コンテナの中でサーバーの応答を待っているコマンドへ、止める合図が確実に届くようにしました。これまでは、合図を`timeout`のプロセスにだけ送り、下のコマンドへ渡すのを`timeout`に任せていました。Ubuntu 26.04の`timeout`（uutils）では合図の一部しか下のコマンドへ渡らず、止める処理の持ち時間を使い切ってしまいます。L2TPでは、切断の処理を行う時間が残りません。いまのコンテナイメージ（Ubuntu 24.04）で起きる問題ではありませんが、コンテナイメージの土台を新しくしたときに備えて修正しました。
