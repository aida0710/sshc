# sshc v0.41.0

v0.41.0では、WireGuardの設定ファイル（`[Interface]`と`[Peer]`）をそのまま編集できるようにしました。VPNプロファイルの編集を開くと、保存済みのシークレットを表示するようにしています。

あわせて、VPN画面の表示が古いままになる問題と、VPNを切断しても数秒で接続し直される問題を修正し、VPN画面を開くまでの待ち時間を短くしました。

**同期しているマシンは、すべてv0.41.0に更新してください。** 設定ファイル（`~/.ssh/sshc/metadata.json`）のバージョンが上がり、v0.40.0以前のsshcでは読めなくなります。

## WireGuardの設定ファイル

- WireGuardのプロファイルは、wg-quickと同じ形の設定ファイルで入力します。複数の`[Peer]`、`AllowedIPs`、`PresharedKey`、`MTU`、`PersistentKeepalive`、`DNS`を書けます。
- 設定ファイルは鍵を含むため、全体を暗号化してVaultに保存します。
- 安全のため、コマンドを実行する指示（`PreUp`、`PostUp`、`PreDown`、`PostDown`）、経路を変える`Table`、`SaveConfig`を含む設定ファイルは使用できません。使用できない場合は、何行目のどの項目かを表示します。
- 接続先が、どの`[Peer]`の`AllowedIPs`にも含まれていない場合は、その理由を表示します。
- これまでの形で作成したWireGuardのプロファイルは、そのまま使えます。編集を開くと設定ファイルの形で表示し、保存すると新しい形になります。

## VPNプロファイルの編集

- 編集を開くと、保存済みのシークレット（パスワード、事前共有鍵、WireGuardとOpenVPNの設定ファイルなど）をVaultから取り出して表示します。パスワードの欄は、［表示］を押すと見えます。Vaultがロックされている場合は表示できません。
- 設定ファイルやパスワードを変更すると、次の接続から新しい値で接続します。起動中のVPN経路は作り直すため、その経路を使っている接続はいったん切れ、Terminalは自動で再接続します。

## VPN画面

- **VPNを切断しても、数秒で接続し直される問題を修正しました。** VPNを切断すると、その経路を使っていたTerminalが自動で再接続し、経路を起動し直していました。今後、VPN画面や`sshc vpn down`で切断した経路は、自動再接続では起動しません。［再接続］を押すか接続を開き直すと、経路を起動して接続します。
- VPNを使っている接続がある場合は、切断の前に「このVPN経路を使っている接続（2本）も切断されます」のように確認するようにしました。
- **VPN画面を開いたまま、別の画面の接続でVPNを起動しても、表示が「停止中」のままになる問題を修正しました。** VPN画面を開いているあいだは、状態を5秒ごとに読み直します。
- VPN画面を開いたとき、Dockerの確認を待たずにプロファイルの一覧を表示するようにしました。状態は「確認中」と表示し、確認が終わると表示します。Docker Desktopのようにdockerの応答が遅い環境で、一覧が出るまでの待ち時間が短くなります。

## コンテナイメージの作成

- Ubuntuのパッケージの配信が一時的に失敗した場合に、再試行する回数と待ち時間を増やしました。配信の不調で、コンテナイメージの作成が失敗しにくくなります。

## 更新後に必要な操作

- 同期しているすべてのマシンを、v0.41.0に更新してください。
- 更新後はengineを再起動してください。
- VPN機能を使用している場合、次にVPNに接続するときに、コンテナイメージがマシン上で1度だけ作り直されます。作成にはネットワークが必要です。
