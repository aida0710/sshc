# sshc v0.31.0

v0.31.0では、保存したワンタイムパスワード（TOTP）が、接続先の`Verification code:`へ自動入力されない場合がある問題を修正しました。

あわせて、OTPをTerminalから管理・確認するCLI、Vault内のOTP専用画面、認証時の診断表示を追加しています。

## TOTPの自動入力

- SSHのkeyboard-interactive認証で、接続先が認証コードの入力内容を画面に表示する設定にしている場合でも、`Verification code:`、`OTP:`、`TOTP:`、`認証コード:`など、ワンタイムパスワードであることが明示された質問へ保存済みTOTPを自動入力するよう修正しました。
- Terminal、SFTP、`sshc ssh`、`sshc run`、ProxyJumpで同じ認証処理を使用します。
- `Code:`、`Passcode:`、`Password:`のように用途が特定できない質問にはTOTPを送りません。接続先、ユーザー、ポート、ProxyJump経路が一致する割り当てがある場合に限って使用します。
- コンテナ上のOpenSSHとPAM TOTPを使い、入力内容を表示する`Verification code:`へコードが自動入力され、実際に認証が完了することを確認する統合テストを追加しました。

## OTPの管理と表示

- `sshc otp list`、`sshc otp <名前>`、`sshc otp add`、`sshc otp edit`、`sshc otp remove`を追加しました。保存済みOTPの一覧、現在と前後のコードの確認、登録、更新、削除をTerminalから行えます。
- OTPのセットアップキーは入力中も伏せ字で表示し、保存後に再表示しません。削除時は、接続先へ割り当てられていないことを確認したうえで実行前に確認します。
- MenuにVaultセクションを設け、アカウントパスワード、鍵パスフレーズ、OTPをそれぞれ専用ページへ分けました。
- OTP画面では現在の6桁コードを通常表示し、コードを選択した場合だけ前後の時間帯のコードを表示します。コードは有効期限に合わせて自動更新されます。
- ブラウザへ返すのは短時間だけ有効なコードであり、TOTPのセットアップキーはengineの外へ出しません。コード取得APIには操作トークンを要求し、応答をキャッシュしないようにしています。

## 接続診断

- 接続ログを「すべて（`-vvv`）」にすると、試した認証方式、認証コードの質問を検出したこと、保存済みTOTPを使用したか、利用できる割り当てがなかったかを確認できるようになりました。セットアップキーや生成したコードはログへ出しません。
- `sshc run`でも接続先に保存したログレベルを使用するよう修正し、`-vv`／`-vvv`相当の診断がCLI経路だけ表示されない問題を解消しました。
