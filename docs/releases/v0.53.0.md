# sshc v0.53.0

v0.53.0では、SSHの接続先で常駐しているsshcエンジンのターミナルを、このPCの画面から使えるようにしました。サイドバーの下の「実行先」で接続先を選ぶと、ターミナルがその接続先で動きます。

あわせて、ターミナルのセッションをワークスペースにまとめるようにし、`sshc terminal create`で開いたセッションを既定で非表示にしています。画面を分割するWorkspaceは削除しました。ボタンを押したときの反応と成功の知らせ方も、全画面で揃えています。

## 実行先

- サイドバーの下に**「実行先」を追加しました。** ［sshcエンジンを追加…］でSSHの接続先を選ぶと、その接続先のsshcエンジンを実行先として使えます。実行先を選ぶと、サイドバーのワークスペースとセッション、ターミナルがその接続先のものに替わります。
- 変わるのはターミナルだけです。Connections、SFTP、Vault、Settingsは、このPCのものをそのまま使います。
- ターミナルは接続先のsshcエンジンで動くので、ブラウザやこのPCを閉じても止まりません。エージェントを長時間動かしておく使い方に向いています。
- 接続先のsshcは、このPCと同じバージョンである必要があります。違う場合は、接続先で`sshc update`を実行するよう表示します。
- 接続先のSSHサーバーは、`127.0.0.1`へのTCP転送を許可している必要があります（`AllowTcpForwarding`が`yes`か`local`）。
- ポート転送、コマンドの一括送信、クイックコマンドは、このPCで動くターミナルだけで使えます。
- 選んだ接続先のVaultがロックされていると、その場でパスワードを尋ねます。パスワードは接続先のsshcエンジンへ渡すだけで、このPCには保存しません。キャンセルしたときは、Workspacesの下の［ロックを解除…］から解除できます。接続先にVaultがまだ無いときは、［別タブで画面をまるごと開く］で作ります。
- 一覧の［…］から、［sshcエンジンの情報…］、［別タブで画面をまるごと開く］、［一覧から外す］を選べます。一覧から外しても、接続先のsshcエンジンとそのターミナルは止まりません。
- ［sshcエンジンの情報…］では、接続先のバージョン、Vaultの状態、セッションの数を表示します。ここから［更新］（`sshc update --yes`）、［再起動］（`sshc service restart --yes`）、［停止］（`sshc stop`）を接続先で実行できます。どれも接続先のセッションをすべて終了させるため、実行の前に確認します。

## sshc open <alias>

- **`sshc open <alias>`を追加しました。** SSHの接続先で動いているsshcエンジンの画面を、このPCのブラウザで開きます。このPCのsshcエンジンが`127.0.0.1`で待ち受け、SSH接続の中で接続先へ中継します。
- 実行先の［別タブで画面をまるごと開く］も、同じ中継を使います。

## ターミナルのワークスペース

- これまでのサイドバーの「Sessions」を、**ワークスペースの木（Workspaces）に変更しました。** ワークスペースは名前の付いたセッションのまとまりで、行を押すと開け閉めできます。
- 見出しの［…］で、ワークスペースを作ったり、非表示のワークスペースを表示したりできます。ワークスペースの［…］からは、名前の変更、非表示、コマンドの一括送信、削除ができます。ワークスペースを削除しても、中のセッションは閉じずに「メイン」へ移ります。
- セッションの［…］→［ワークスペースへ移動］で、別のワークスペースへ移せます。
- これまでは、`sshc terminal create`でLLMやスクリプトが開いたセッションも、画面のセッションと同じ一覧に並んでいました。**既定で非表示のワークスペース「エージェント」に入るように変更しました。** `--workspace <IDか名前>`で入れ先を指定できます。`sshc terminal list`には、ワークスペースの名前の列を追加しました。
- 画面を分割して保存・復元するWorkspace（分割、Focus Mode、保存したレイアウト、ホームの［レイアウトを開く］）を削除しました。ターミナルは、選んだセッションを1つずつ表示します。保存済みのレイアウトは引き継ぎません。

## 操作の反応

- **ボタンを押したときの見た目を全画面で揃えました。** 押せないボタンは同じ濃さで表示します。デスクトップでも、押した瞬間の動きと、ダイアログやメニューが開く動きを付けました。確認ダイアログでは、処理中に回転する印を表示します。
- 成功の知らせ方を揃えました。保存やコピーが済んだときは、成功の色の知らせか、画面の下に出る共通の知らせで伝えます。名前の入力などのダイアログは、処理が終わるまで開いたまま待ちます。
- Connectionsでは、接続先を選んだ直後に「読み込んでいます」と表示します。一覧のダイアログは処理が終わるまで開いたまま待ち、失敗したときはダイアログの中に表示します。管理パネルの操作にも、処理中と成功を表示します。
- SFTPでは、転送を追加すると転送マネージャーを開きます。名前の変更などのダイアログは処理が終わるまで開いたまま待ちます。ジョブの操作とSFTPの設定の保存にも、処理中と完了を表示します。
- Settings、SSH Config、Keys、Known Hosts、Snippets、Sync、VPNの画面でも、押したボタンに処理中を表示し、成功を知らせます。Known Hostsの結果は画面の下の知らせで表示します。
- ドラッグできる所では、カーソルがつかむ形になります。落とせる所は点線で示し、真上に来ると実線になります。

## そのほかの変更

- **ターミナルに出たパスを押して［プレビュー］を選ぶと、その画像をターミナルの上に表示するようにしました。** Claude Codeが送った画像の行（`[image] /tmp/….png`）も開けます。ローカルシェルではsshcエンジンのマシンから、SSHのセッションではその接続先から、押したときだけ読みます。これまでパスを押せたのはSSHのセッションだけでしたが、ローカルシェルでも押せるようになりました。
- バージョンの表示と更新のお知らせを、サイドバーの下から左上のロゴの横へ移しました。
- Goを1.26.10に更新しました（GO-2026-6809の修正を含みます）。

## セキュリティ

2026年10月23日のセキュリティー監査で見つかった問題を修正しました。

- **実行先と`sshc open <alias>`の中継で、接続先のsshcエンジンが本物かを、接続を開くたびに確かめるようにしました。** これまでは最初に1回だけ確かめていました。そのため、接続先のsshcエンジンが別のポートで起動し直したとき、接続先の別のユーザーが古いポートで待ち受けていると、Vaultのパスワードやログインの情報がそのプログラムへ届くことがありました。確かめられない相手には何も送りません。中継は、`/cli/challenge`を持つv0.36.0以降の接続先だけで開けます。
- 実行先のターミナルの取り次ぎで、接続先が返すcookieなどのヘッダーをこのPCの画面へ渡さないようにしました。実行先のターミナルを開く要求は、このPCにログインし、Vaultのロックを解除しているときだけ受け付けます。
- ブラウザの登録が盗まれたことを、盗んだ側が続けて何度か使った後でも検知できるようにしました。これまでは直前の1回分しか覚えていませんでした。Linuxでは、エンジンの再起動の後にブラウザが入り直すときも、同じOSユーザーからの接続かを確かめます。
- Vaultのロック中でも、ロックの画面からこのブラウザをサインアウトできるようにしました。
- `sshc vault unlock`などでパスワードを入力した後、送る直前にもう一度sshcエンジンが本物かを確かめるようにしました。
- WindowsでCLIの`sshc sftp get -r`を使ったとき、SFTPサーバーが返すフォルダ名で、保存先のフォルダの外へ書き込めることがありました。サーバーが返す名前は、保存先の外を指すものを断るようにしました。
- フォルダをZIPでダウンロードするとき、setuid、setgid、stickyのビットを書かないようにしました。1つのフォルダの一覧は10万項目までにし、一覧を終わらせないサーバーでもメモリを使い切らないようにしました。
- ターミナルの画像（kittyの形式）は、宣言された大きさと展開後の大きさを先に確かめ、上限を超えるものを表示しないようにしました。画像1枚の上限は約7.5MBです（これまでは32MiB）。
- ターミナルのリンクの表示の文字と行き先が違うときは、Ctrl（Macでは⌘）を押しながらクリックしても、行き先を表示してから開くようにしました。
- WindowsのOpenSSHのssh-agentは、そのnamed pipeを作ったのがLocalSystem、Administrators、自分のどれかのときだけ使うようにしました。ssh-agentのサービスが止まっているときに、別のユーザーが同じ名前のpipeを作って鍵を受け取ることはできません。
- `sshc update`と画面からの更新で、`install.sh`も`install.ps1`と同じく、GitHub Releaseの`checksums.txt`と照合してから実行するようにしました。
- **OpenVPNの設定ファイルは、決まった指令だけを受け付けるようにしました。** これまでは危ない指令を断る方式でした。一覧に無い指令（`dns-updown`、`setenv LD_PRELOAD`など）を含む設定ファイルは、行番号を示して断ります。VPNのサーバーの欄では、`-`で始まる値を断ります。
- Vaultのパスワードの確かめ（`/cli/vault/verify`）で、間違いを並べて送っても、待ち時間が1回ずつかかるようにしました。Syncの状態のファイルに残すSnippetの文書の値も、Vaultの文書と同じく鍵付きの値にしました。
- Androidでは、リリース版の画面をスクリーンショットや最近使ったアプリの一覧に残さないようにしました。通知を開くときは、アプリが出した通知だけを受け付けます。ターミナルの通知の見出しには、接続先の名前を先頭に付けます（デスクトップのブラウザの通知も同じです）。
- リリースのビルドで、mainのビルドのキャッシュを使わないようにしました。

## 更新後に必要な操作

- 実行先として使う接続先も、同じv0.53.0に更新してください。接続先では`sshc update`を実行します。
