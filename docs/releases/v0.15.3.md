# sshc v0.15.3

vault の形式変更を段階的かつ原子的に適用する migration 基盤を追加しました。v0.15.2 の保護タグは GitHub Actions 障害中に push workflow が欠落して公開できなかったため、同じ製品変更とrelease復旧経路の修正を v0.15.3 として公開します。

## vault schema migration

- schema 4 を migration 保証の起点とし、今後は `N → N+1` の変換を registry へ一段ずつ登録します。
- `SchemaVersion` を上げる変更には、直前 version の変換と旧版 fixture が必須です。chain が欠けると contract test が失敗します。
- 変換後の文書を現行 schema で厳密に再検証し、journal 付き transaction が完了するまで、ディスク上にも実行中の状態にも新しい vault を公開しません。
- 更新前の vault は暗号化された世代バックアップへ残します。変換や書き込みに失敗した場合は元の vault を維持し、失敗した版の組だけを安全な診断情報として表示します。
- migration 完了後は、更新前後の版を画面上部へ一度だけ通知します。

## 形式不一致の診断と復旧

- 古い vault と新しい vault を区別し、「必要なバージョン: 4、現在: 3」のように双方の版を表示します。
- ローカルの世代履歴から、現在の sshc で開ける最新の vault バックアップを復元できます。
- 互換バックアップがない場合は、確認後にSSH設定と鍵ファイルを残して空の現行 vault を作成できます。

## release復旧

- GitHubのpush webhookが欠落した場合でも、同じmain SHAに対する手動CIが全件成功していればrelease sourceとして認めます。
- tagのmain祖先性、CIのworkflow、branch、commit SHA、成功状態は従来どおりすべて照合します。別branchや別commitの手動runは利用できません。

## 検証

- Go通常／race、Windows・macOS・Linux、Android APK、dependency security、生成物、dead code、SFTPとS3のintegration testをCIで確認しました。
- Web unit test 906件とChromium E2E 118経路を確認しました。
- 360×800の日本語画面で、版差、復旧操作、migration完了通知に横overflowがないことをスクリーンショットで確認しました。
