# sshc v0.28.0

v0.28.0では、VaultにTOTPのセットアップキーを保存し、SSHのワンタイムパスワードを自動入力できるようにしました。

あわせて、SFTP画面を開いたときや保存済みタブを復元したときに、自動で接続しないよう動作を変更しています。

## TOTPの自動入力

- ［Vault］の［ワンタイムパスワード（TOTP）］へ、Base32形式のセットアップキーまたは`otpauth://totp/...` URIを保存し、接続先へ割り当てられるようになりました。セットアップキーは、アカウントパスワードや鍵のパスフレーズと同じくVault内で暗号化されます。
- Terminal、SFTP、`sshc ssh`、`sshc run`、ProxyJumpの各接続で、保存したTOTPを利用できます。`OTP`、`TOTP`、`Verification code`、`認証コード`など、ワンタイムパスワードであることが明確な非表示の質問にだけ、その時点のコードを自動入力します。
- 曖昧な`Code`、`Passcode`、通常のパスワード入力にはTOTPを送信しません。パスワードとTOTPを同時に求められた場合も、質問の用途を安全に判別できる場合だけ両方を自動入力します。
- TOTPの割り当ては、接続先、ユーザー、ポート、ProxyJump経路を含む現在の認証経路に紐付きます。これらを変更した場合は自動入力を停止するため、Vaultで接続先への割り当てをやり直してください。
- SHA-1、SHA-256、SHA-512と、6桁または8桁のTOTPに対応しています。更新間隔は5〜300秒の範囲で、URIに指定された値を使用します。Base32形式のキーだけを保存した場合は、SHA-1、6桁、30秒を使用します。

**認証要素の分離:** アカウントパスワードとTOTPのセットアップキーを同じ端末のVaultに保存すると、その端末を失った場合に両方の認証要素を同時に失う可能性があります。組織のセキュリティ方針で許可されている場合だけ使用してください。

## Vaultの更新

- 既存のVaultは、schema 4からschema 5へ開いたときに自動変換されます。保存済みのアカウントパスワード、鍵のパスフレーズ、割り当てはそのまま引き継がれます。
- TOTPの名前変更、編集、削除と、接続先への割り当て解除は、既存の資格情報と同じVault画面から行えます。秘密の値は編集時だけ復号して表示し、保存または画面を閉じたときに破棄します。

## SFTPの接続

- これまではSFTP画面でホストを選ぶと接続していましたが、**ホストを選んでから［接続］を押す方式**に変更しました。画面を開いただけではSSH接続を開始しません。
- 保存済みのタブを復元した場合は、接続先と前回のパスだけを表示します。非表示のタブや、1ペイン表示中の右ペインもバックグラウンドでは接続しません。
- Terminalから「SFTPで開く」を選んだ場合は、接続先とパスを指定した明示的な操作として、そのままSFTPへ接続します。

## ドキュメントと検証

- 日本語・英語の認証情報ガイドへ、TOTPの保存、割り当て、自動入力の条件と安全上の注意を追加しました。
- 日本語・英語のSFTPガイドへ、ホスト選択後に［接続］が必要になったことを追記しました。
- RFC 6238のテストベクターに加えて、OpenSSHとPAM TOTPを使用するコンテナで、暗号化されたVaultからTOTPを取得し、非対話CLIでSSH接続できることを確認しました。
