# sshc v0.13.2

Android版のengine起動を単一app process前提へ単純化し、再インストール後や強制停止後にも二重起動エラー画面が出る問題を修正しました。

## 変更内容

- Android版からdesktop／CLI用のOS file lockを外しました。Androidでは同一packageの単一app processだけがengineを所有します。
- Service再生成などで`Start`が重複した場合はエラーにせず、現在のengineの停止完了を待って新しいengineへ置き換えます。
- `Another sshc engine is already running on this device.`の失敗種別と画面文言を削除しました。
- private stateのsymlink拒否を起動外殻のlockからengine共通の初期化処理へ移し、Android、desktop、CLIで同じ検査を行います。
- desktop／CLIでは別processを起動できるため、従来の`engine.lock`を維持します。

## 検証

- 重複`Start`、`Stop`後の再起動、private storage path、private state symlink拒否をGo testとrace detectorで確認しました。
- Go全package、Android arm64クロスbuild、dead-code検査、Web test、TypeScript型検査を確認しました。
- AndroidのAAR、APK、Java unit test、署名はRelease前のrequired CIで確認します。

## 互換性

保存形式と同期形式の変更はありません。Androidの起動制御だけを単一process前提へ変更しました。v0.13.1で二重起動エラー画面が出る端末はv0.13.2へ更新してください。
