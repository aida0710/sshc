# sshc v0.13.1

Androidの起動時にengineの二重起動と誤判定される問題を修正し、終了したSSH terminalを同じ画面から明示的に再接続できるようにしました。

## 変更内容

- Android frameworkが返すprivate storage pathの別名をアプリ境界で正規化し、アプリ用rootより下のsymlink拒否を維持したままengineを起動できるようにしました。
- engine lockの取得失敗を分類し、実際の二重起動だけを`Another sshc engine is already running on this device.`として表示します。storage pathを開けない場合は別の案内を表示します。
- Android Serviceの破棄とengine起動完了が競合しても、旧Serviceが所有するengineを停止してから次のServiceを開始するようにしました。
- 終了済みSSH terminalの終了表示へ「再接続」を追加しました。同じsession ID、Workspace pane、scrollbackを維持したまま新しいremote shellを開きます。
- 明示再接続にもhost key確認、認証、同時session上限を適用します。local shell、live session、手動で閉じたsessionは再接続できません。
- 再接続中の重複操作を防ぎ、処理中表示と失敗表示を追加しました。closeまたはengine停止が先行した接続は破棄し、閉じたsessionを復活させません。

## 検証

- Goの全package通常testとrace test、Android arm64クロスbuild、dead-code、vetを確認しました。
- Webの877 test、TypeScript型検査、lint、i18n、production buildとPlaywright 113 testを確認しました。
- Android Serviceのengine所有権を純Java unit testで固定し、Android向けbuildとAPK unit testはCIで確認します。
- desktopとmobile幅で終了表示と再接続操作をPlaywrightで確認しました。

## 互換性

保存形式と同期形式の変更はありません。v0.13.0のAndroid APKで起動時の誤表示が出る端末は、v0.13.1へ更新してください。
