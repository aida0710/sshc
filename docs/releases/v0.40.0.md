# sshc v0.40.0

v0.40.0では、VPN経路の方式にOpenVPNとIKEv2/IPsecを追加しました。これまでのWireGuard、L2TP/IPsec、OpenConnectと同じく、選択した接続だけをDockerのコンテナの中のVPN経由で接続します。このマシンのルーティングとDNSは変わりません。

OpenConnectでは、プロトコルを製品名で選べるようにしました。

**同期しているマシンは、すべてv0.40.0に更新してください。** 設定ファイル（`~/.ssh/sshc/metadata.json`）の版が上がり、v0.39.7以前のsshcでは読めなくなります。

## OpenVPN

- プロバイダや組織が配布する設定ファイル（`.ovpn`）を、貼り付けるか［ファイルを選択］で読み込んで使います。設定ファイルには鍵が含まれることが多いため、中身はシークレットとしてVaultに保存します。
- 設定ファイルの`remote`から、VPNサーバーを読み取って表示します。設定ファイルが`auth-user-pass`でユーザー名とパスワードを求める場合は、それも入力します。
- 安全のため、次の指示を含む設定ファイルは使用できません。使用できない場合は、何行目のどの指示かを表示します。
  - コマンドやプログラムを実行する指示（`up`、`plugin`、`script-security`など）
  - 経路やDNSを変更する指示（`route`、`redirect-gateway`など）
  - コンテナの中に無いファイルを指す指示（`ca`などのファイル名）。証明書と鍵は`<ca>`〜`</ca>`のように設定ファイルに埋め込まれている必要があります。
- サーバーが配布する既定経路とDNSは設定しません。ルーティングは、接続に使った接続先の分だけを作ります。
- 認証の失敗、証明書の不一致、サーバーの無応答を区別して表示します。

## IKEv2/IPsec

- 認証方式は、ユーザー名とパスワード（EAP-MSCHAPv2）と、事前共有鍵（PSK）から選びます。ユーザー名とパスワードは、Windows、macOS、スマートフォンの標準のVPNと同じ方式です。
- ユーザー名とパスワードで認証する場合、パスワードを送る前にサーバーの証明書を検証します。CAの証明書を貼り付けた場合はそのCAで、空欄の場合は公的な認証局で検証します。検証できないサーバーには接続しません。
- 古いVPN機器と暗号スイートが合わない場合は、IKEとESPの暗号スイートを指定できます。
- サーバーが配布する経路とDNSは設定しません。
- 認証の失敗、サーバーの証明書を検証できない場合、暗号スイートの不一致、サーバーの無応答を区別して表示します。
- IKEv2/IPsecは、LinuxカーネルのXFRMインターフェースを使います。Docker Desktop for Macで使用できるかは確認できていません。使用できない場合は、その旨を表示します。

## OpenConnect

- プロトコルを製品名で選べるようにしました（例: Palo Alto Networks GlobalProtect、Fortinet FortiGate、Ivanti Connect Secure）。これまでは`gp`や`fortinet`などのプロトコル名だけが表示されていました。
- ブラウザでログインする方式（SAMLなどのシングルサインオン）には対応していません。

## 更新後に必要な操作

- 同期しているすべてのマシンを、v0.40.0に更新してください。
- 更新後はengineを再起動してください。
- VPN機能を使用している場合、次にVPNに接続するときに、コンテナイメージがマシン上で1度だけ作り直されます。作成にはネットワークが必要です。
