# sshc v0.22.0

v0.22.0では、SFTP Transfer Managerの状態管理をブラウザーからengineへ移しました。SFTP画面を開き直した場合も、転送キューと進捗、再開情報を同じ台帳から確認できます。

あわせて、Serialのフロー制御、CLIの個別ヘルプ、同期方向ごとの操作、Vaultのパスワード編集、日本語・英語ドキュメントを改善しています。

## SFTP Transfer Manager

- 転送キュー、バッチ名、進捗、同時実行数、上書き確認、再開用チェックポイントをengineが管理するように変更しました。複数の画面を開いた場合も2秒ごとに同じ状態へ揃います。ローカルファイルの読み書きは引き続きブラウザーやWebViewが行うため、画面を閉じると実際の送受信は停止します。
- ブラウザーやWebViewを再読み込みした後のアップロードは、「再開待ち」として保持されます。名前、サイズ、更新日時が同じローカルファイルを選び直し、リモート側の一時ファイルが残っていれば、転送済みの位置から続行します。
- 「完了分を消去」では、完了またはキャンセル済みの項目だけをengineの台帳から除去します。待機中、転送中、一時停止中、失敗した項目は残ります。engineを終了するとメモリー上のキューも終了するため、再起動後は転送を登録し直してください。

## Sync

- Sync画面を送受信、受信のみ、送信のみの各設定に合わせて整理しました。送信しない端末に送信操作を表示せず、受信しない端末に受信操作を表示しません。
- 受信専用でリモートの履歴が分岐した場合は、作成日時、作成元、変更されるファイルを確認し、現在のリモートを正として明示的に受信できます。この操作はS3へ書き込みません。
- S3の履歴は最近5件を先に表示し、必要な場合だけ残りを開けるようにしました。暗号化キーがあれば、世代の関係とファイル差分も確認できます。

## SerialとCLI

- Serial接続のフロー制御に`none`、`rtscts`、`xonxoff`を追加しました。Linux、macOS、BSD、Windowsで、OSのSerial APIへ設定を反映します。
- `sshc <command...> --help`と`sshc help <command...>`を追加しました。`sshc sync push --help`や`sshc help terminal send`のように、サブコマンドごとの引数を確認できます。
- Settingsに、ブラウザーだけに保存する設定と、SSHワークスペースへ保存するTerminal設定の範囲を表示するようにしました。

## Vaultとドキュメント

- 保存済みパスワードの編集画面で、値を最初から平文表示しないよう修正しました。値は入力欄に設定されており、表示操作の後に確認、編集できます。
- 日本語・英語のPagesを現在の実装に合わせ、SyncとSFTP Transfer Managerの実画面を追加しました。スマートフォンではトップページの左右余白を縮めています。
- GitHub ActionsのArtifact処理をNode.js 24対応版へ更新し、使用しないSerial列挙APIを削除しました。

## 検証

- S3互換ストレージ、OpenSSHサーバ2台、独立したLinuxクライアント16台を使い、同期方向、競合、削除、同時Push、S3停止後の復旧を確認しました。変更がない16台の確認で、新しい履歴が作成されないことも確認しています。
- SSHは16並列の公開鍵認証、保存パスワード認証、Local Forward、Dynamic SOCKSを検証しました。SFTPは64 MiBの一時停／再開／キャンセルと8本並列の送受信でデータの一致を確認しています。
