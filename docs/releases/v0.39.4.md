# sshc v0.39.4

v0.39.4では、L2TP/IPsecで一部のVPNサーバに接続できない問題を修正しました。SSHとVPNの接続ログも詳しくし、接続がどこまで進んだか、何が原因で止まったかを調べやすくしました。

あわせて、AWS SSOの認証切れの案内と、ターミナルで折り返された長いURLの操作を改善しています。

## SSHの接続ログ

- `-vv`・`-vvv`に、採用された鍵交換・暗号・MAC、サーバが受け付ける認証方式、失敗した方式、追加認証待ちの状態を追加しました。`-vvv`では、提示するアルゴリズムの候補も確認できます。
- ProxyCommandの実行シェル・PID・失敗時の終了コード、SSHチャンネル・PTY・シェル起動の結果と所要時間を表示します。
- keepaliveを設定している場合、応答時間、連続失敗回数、無応答による切断理由を表示します。セッション終了時には終了コード・シグナル・実行時間も記録します。

## AWS SSOの認証切れ

- SSOトークンの失効や不足を検出すると、**再ログインの方法を表示して自動再接続を止めます。** sshcのengineが動くマシンで、同じOSユーザー・プロファイルを使って`aws sso login`を実行してください。
- ProxyCommandのプロセスが起動しただけで「TCP接続を確立しました」と表示していた問題を修正しました。

## VPNの接続とログ

- L2TP/IPsecのESPを未指定にしたとき、AESとHMAC-SHA1を使うサーバへ接続できない問題を修正しました。SHA-256の候補を優先し、HMAC-SHA1の候補も提示します。ESPを明示している場合は、その設定を使います。
- IPsecの制御用接続だけが成立し、データ通信用の接続に失敗した場合は、L2TPを開始せずIPsecのエラーとして表示します。
- L2TP/IPsecでIPアドレスを取得できない場合、一律に「PPPの認証に失敗しました」と表示していました。今後は、認証拒否を確認した場合にだけ認証失敗として扱い、タイムアウトと区別します。
- IPsec・L2TP・PPPの通常ログを各60行まで回収します。VPN画面の「ログ」や`sshc vpn logs <プロファイル名>`で、コンテナが削除された後も確認できます。
- Linux上のDockerで、接続に失敗していた実際のVPNを通してSSHログインできることを確認しました。macOSのDocker Desktopでの実接続は未確認です。

## 折り返されたURLの操作

- 長いURLが複数行に折り返されても、**URL全体を開いたりコピーしたりできるようになりました。** 折り返し先の行からも操作できます。日本語や絵文字を含む行でもリンクの位置を正しく扱います。

## 更新後に必要な操作

更新後はengineを再起動してください。VPN機能を使用している場合、次にVPNへ接続するときに、新しいコンテナイメージをマシン上で作成します。作成にはネットワークが必要です。
