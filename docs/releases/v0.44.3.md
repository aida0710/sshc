# sshc v0.44.3

v0.44.3では、L2TP/IPsecのVPNプロファイルで、一部のVPN機器に接続できなくなっていた不具合を修正しました。v0.40.0以降、IKEの暗号スイートを空欄にしていると、MODPとSHA-1だけを受け付けるVPN機器がIPsecのネゴシエーションに応答せず、接続に失敗していました。

あわせて、L2TP/IPsecの接続に失敗したときに、VPNサーバーとのやりとりをログで確認できるようにしています。

## 更新後に必要な操作

- 更新後はengineを再起動してください。`sshc update`で更新した場合、`sshc service install`で登録したサービスは自動で再起動されます。`sshc update`を使わずに更新した場合（`brew upgrade`、install.shやinstall.ps1の直接実行）、サービスは`sshc service install`で再起動します。サービスとして登録していないengineは`sshc engine --replace`で再起動してください。
- VPN機能を使用している場合、次にVPNに接続するときに、コンテナイメージがマシン上で1度だけ作り直されます。作成にはネットワークが必要です。

## VPN（L2TP/IPsec）

- これまでは、IKEの暗号スイートを空欄にすると、strongSwanの既定の候補から1組だけを提示していました。v0.40.0でコンテナに追加したstrongSwanのプラグインにより、この1組がAES-128・SHA-256・ECP-256に変わり、MODPとSHA-1だけを受け付けるVPN機器は応答しなくなっていました。**空欄のときは、L2TP/IPsecのVPN機器でよく使われる組み合わせを1つずつ提示する**ように変更しました。AESとSHA-256またはSHA-1を、DH群はMODPの3072・2048・1024ビットを組み合わせます。これまで提示していた1組も、そのあとに提示します。
- IKEの暗号スイートを指定しているプロファイルは、これまでどおり指定した値を使います。この不具合を避けるために指定した値は、空欄に戻しても接続できます。
- これまでは、IPsecのネゴシエーションに失敗すると、コンテナのログにIPsecサービスを起動した行しか残りませんでした。**VPNサーバーへ送ったパケット、応答が無いときの再送、サーバーからの拒否などを、失敗したときのログに表示する**ように変更しました。
