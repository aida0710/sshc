# sshc v0.59.2

v0.59.2では、マスターパスワードを設定したVaultを使っているマシンで、v0.59.1へ更新するとsshcエンジンが起動しなくなる不具合を修正しました。

あわせて、取り消したコマンドの子プロセスが、macOSでまれに止まらずに残る不具合も修正しています。

## 更新後に必要な操作

- **v0.59.1へ更新してsshcエンジンが起動しなくなったマシンは、v0.59.2へ更新すると起動します。** 設定もそのまま引き継がれます。v0.59.1の起動で止まった変更の記録は、v0.59.2のsshcエンジンが起動するときに自動で片付けます。`sshc update`はsshcエンジンが動いていなくても使えます。
- まだv0.58.1以前を使っているマシンは、v0.59.1を飛ばしてv0.59.2へ更新してください。設定の形の変更と「更新後に必要な操作」は、[v0.59.1のリリースノート](https://github.com/aida0710/sshc/releases/tag/v0.59.1)にあります。

## 修正

- **v0.59.1は、起動するときにmetadata.jsonを新しい形（schema 10）へ書き直す際、前の内容の控えをVaultの鍵で暗号化しようとしていました。** マスターパスワードのあるVaultは起動の時点ではまだロックされているため、ここで失敗してsshcエンジンが止まりました（ログには「the password vault is locked」と出ます）。2回目からは、止まった変更の記録が残っているため「a pending transaction must be recovered first」で止まりました。これからは、起動時の書き直しでは控えを取らないので、ロックされたままでも書き直してから起動します。前の形の控えは、このバージョンでは読み込めないため取りません。
- 前のバージョンの`engine-settings.json`からポートを移して消すときも、同じ理由で控えを取らないようにしました。
- VPNのイメージの作成やログインシェルのPATHの読み取りを取り消したとき、macOSでは、ちょうど起動しかけていた子プロセスが止まらずに残ることがありました。取り消しから戻るのが1〜2秒遅れ、残った子プロセスはそのあとも動き続けていました。これからは、残ったものが無くなるまで止め直します。
