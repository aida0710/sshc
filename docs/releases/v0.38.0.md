# sshc v0.38.0

v0.38.0では、選んだSSH接続だけを専用のVPNへ通せるようにしました。トンネルはsshcが作るコンテナの中にあり、この端末の既定経路、DNS、すでに使っているVPNクライアントの設定は変わりません。**別のVPNに繋いだままで、そのVPNの外にしかいないホストへ接続できます。**

この機能はDockerが動いている機械で使えます。Dockerが無い場合や、方式に必要なデバイスが無い場合は、機能を隠さずに理由を表示します。

## 接続ごとのVPN

- **VPN画面を追加しました。** 経路の定義、いまの状態、その経路を通る接続を1つの画面で扱えます。`sshc vpn`から同じことをコマンドラインでも行えます。
- **1つのプロファイルは1つの接続先へ届きます。** VPNの向こうのネットワーク全体を引き込まないため、経路とパケットフィルタが接続先ひとつで閉じます。接続設定の接続先とプロファイルの接続先が食い違う場合は、どちらが正しいかを推測せずに接続を断ります。
- **方式はWireGuardとL2TP/IPsecから選べます。** WireGuardは秘密鍵、L2TP/IPsecはVPNのパスワードとIPsecの事前共有鍵を使います。古い装置と暗号方式が合わない場合だけ、IKEとESPの候補を指定できます。
- **接続先への通信はfail closedです。** トンネル以外から接続先へ出ようとする通信をコンテナ内で拒否します。トンネルが落ちているあいだ、接続先への通信がふだんの回線へ流れることはありません。L2TP/IPsecでは、IPsecのポリシーが無いままのL2TPも拒否します。
- **SSHの処理はこれまでどおり端末側で行います。** 握手、認証、ホスト鍵の照合、ssh-agentの利用はsshc本体が行い、コンテナへ渡すのは「どこへTCPを接続するか」だけです。SSH秘密鍵とVaultの鍵はコンテナへ渡りません。
- **結び付けた接続は、Terminal、SFTP、`sshc <接続先>`のいずれからでも同じ経路を通ります。** 経路を用意できないときは、ふだんの回線へ落とさずに接続を断ります。

## VPNの設定と秘密の保存先

- プロファイル（方式、サーバー、接続先、接続との紐付け）は`~/.ssh/sshc/metadata.json`に保存します。`~/.ssh/config`には書きません。OpenSSHが解釈する設定ではないためです。
- VPNのパスワード、IPsecの事前共有鍵、WireGuardの秘密鍵はVaultに保存します。画面にもAPIの応答にも戻りません。設定だけを直すときは、保存済みの秘密をそのまま残せます。
- プロファイルを削除すると、その秘密と、そのプロファイルを指していた接続の紐付けも同時に消えます。動いている経路も止めます。
- **Vaultの保存形式を更新しました（schema 6）。** 解錠時に自動で移行し、既存の秘密には触れません。移行前のVaultは暗号化したまま履歴へ残ります。

## 制約

- 1つのプロファイルにつき接続先は1つで、IPv4アドレスを指定します。VPN内のDNSは使いません。
- 踏み台（ProxyJump）の向こうのホップには使えません。2ホップ目以降は手前のSSH接続の中を通るためです。`ProxyCommand`との併用もできません。
- 端末の`ssh`、`scp`、`git`からは使えません。sshcのTerminal、SFTP、CLIから使います。
- 現在はLinuxで動作を確認しています。

## 更新後に必要な操作

更新後はengineを再起動して新しい版を利用してください。VPN機能を使わない場合、追加の操作はありません。

VPN機能を初めて使うときは、コンテナのイメージをその端末で1度だけ作成します。作成にはネットワークが必要で、1〜2分かかります。
