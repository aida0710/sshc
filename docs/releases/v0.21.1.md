# sshc v0.21.1

v0.21.1では、1分おきのポーリングでPushしないよう自動同期を変更しました。ローカルに変更がなければ、S3に新しい履歴は作られません。

あわせて、受信専用端末の同期操作、Vaultの自動ロック設定、Androidの戻る操作、利用者向けドキュメントを改善しています。

## 自動同期

- これまでは1分おきのポーリングでPullとPushの両方を行っていました。v0.21.1からはリモートの更新確認と必要なPullだけを行い、Pushはローカルに変更がある場合に限ります。
- 設定、接続先、鍵、Known Hosts、保存パスワード、スニペットなどを変更すると、**最後の変更から5秒後に自動でPush**されます。5秒以内に続けて変更した場合は、最後の変更から再び5秒待ってPushします。
- Pullによって反映された変更や同期状態の更新を、ローカルでの変更として扱わないよう修正しました。これにより、Pullした内容をそのままPushし返したり、同じ内容の履歴が繰り返し作成されたりすることがなくなりました。
- engineを再起動した場合でも、Sync画面を開くことなく、Vaultに保存されているバケット設定を読み込んで自動同期を再開するようになりました。
- Sync画面と日本語・英語ドキュメントに、1分おきのポーリングと変更後5秒のPushについて追記しました。

## 受信専用モード・画面操作

- 受信専用端末でリモート側の履歴が分岐している場合に、現在のリモート状態を確認したうえで、明示的にPullできるようになりました。受信専用端末からリモートへの書き込みは行われません。
- 同期設定画面を整理し、バケットと暗号化キーの設定を管理する画面と、スナップショット・履歴を操作する通常の同期画面を分離しました。
- Androidの戻る操作で、アプリ内の画面履歴に沿って前の画面へ戻れるよう修正しました。

## Vaultの自動ロック

- これまで12時間固定だったVaultの自動ロック時間を、Settingsから変更できるようになりました。**1〜999分／時間**、または**「自動ロックしない」**を選択できます。設定していない場合は、これまでどおり12時間でロックされます。
- 自動ロック時間を変更すると、現在動作しているengineにもすぐに反映され、次回起動時にも設定が引き継がれます。
- より短い時間に変更した時点ですでに自動ロックの期限を過ぎている場合は、その場でVaultをロックします。
- 「自動ロックしない」を選択している場合でも、手動ロックやengine終了時の鍵の破棄はこれまでどおり行われます。また、手動でロックしない限りengineを終了するまでVaultが解除されたままになることを画面上に表示します。
- 状態確認、Terminalへの出力、バックグラウンド同期などでは、自動ロックまでの時間は延長されません。
