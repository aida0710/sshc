# sshc v0.15.0

リモート同期の初期設定を、保存してから失敗に気付くフォームから、接続先と暗号化キーを実証してから保存する導線へ作り直しました。通常利用時は同期操作だけを表示し、S3資格情報・履歴・鍵交換・force pushは管理画面へまとめています。

## 安全な初期設定

- endpoint、bucket、path、region、資格情報を入力後、まず接続先を確認します。この段階では資格情報も同期鍵も保存しません。
- 指定したbucketとpathに既存の同期データがあれば、同じ同期暗号化キーの入力を必須にしました。現在のリモートスナップショットを実際に復号し、schemaと内容の整合性を確認してから保存します。
- 空のpathでは強い同期鍵を自動生成できます。自分で決めた鍵も使用できます。
- 履歴だけが残り現在のスナップショットがないpathは、不完全な同期先として拒否します。新しく始める場合は別の空pathを案内します。
- 接続確認後にリモートのETagや履歴状態が変わった場合は保存せず、再確認を求めます。
- S3資格情報、同期先、端末ロール、同期鍵は、すべての検証が成功した後に一つの暗号化設定トランザクションとして保存します。

## 端末ロールと通常画面

- 初期設定では「メイン端末（送信と受信）」と「受信専用端末」を主要な選択肢にしました。「送信専用端末」は詳細ロールにまとめています。
- 設定後の通常画面は、同期状態、端末ロール、自動同期、今すぐ同期、リモートから受信だけを表示します。
- endpoint、bucket、path、資格情報の変更、鍵交換、バケット状態、履歴、force pushは「同期設定を管理」にまとめました。
- 停止理由や失敗理由は同期カード上に表示します。

## 同期操作

- 「今すぐ同期」は自動同期が無効でも実行できるようになりました。実行しても自動同期の設定は変えません。
- 自動同期を有効にした直後、その場で最初の同期を一度実行します。
- 受信専用端末には「リモートから受信」を主要操作として表示し、適用前の変更確認へ進みます。

## 検証

- 誤った同期鍵、確認後に変化した接続先、履歴だけ残った不完全なpathで設定が保存されないことをGoテストで確認しました。
- 自動同期が無効でも手動同期が動作し、自動同期設定自体は変わらないことを確認しました。
- React unit test、Chromium E2E、360×800のスマホ表示で、既存データの検出、鍵入力、通常画面、詳細管理を確認しました。
