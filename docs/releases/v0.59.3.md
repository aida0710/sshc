# sshc v0.59.3

v0.59.3では、左のナビや一覧の欄の幅を変えるたびに設定の保存が走り、動きが重くなっていたのを改善しました。欄の幅、Homeの表示形式、SFTPの左右の分割は、ブラウザごとに覚えるように変更しました。

あわせて、設定の保存が、変えていない設定の検査で失敗したときに、通らない所を画面に表示するように変更しています。

## 欄の幅と画面の並び

- v0.59.1から、左のナビの幅、Connectionsの一覧とグループの欄の幅、Homeの表示形式はプリセットに、SFTPの左右の分割の比率はマシンの状態に保存して同期していました。このため、ドラッグするたびに、設定全体の検査、変更の記録、Vaultの鍵で暗号化した控えの作成、同期が走っていました。**これからは、この5つをブラウザごとに覚え、sshcエンジンには送りません。**
- 保存先は、v0.58.1以前にブラウザへ保存していたときと同じです。そのころにこのブラウザで決めた幅が戻ります。v0.59.1とv0.59.2で変えた幅は引き継がれません。
- ブラウザごとに覚えるので、ほかのマシンやブラウザには同期されません。ブラウザの保存はアドレス（ホスト名とポート）ごとに分かれるため、sshcエンジンのポートを変えると既定の幅に戻ります。

## 設定の保存の失敗

- 設定を保存すると、sshcエンジンはmetadata.json全体を検査します。これまでは、変えていない所（VPNプロファイル、接続先のOS、ショートカットのプリセット）が検査に通らないとき、理由を示さずに`internal_error`（HTTP 500）で断っていました。**これからは`invalid_request`（HTTP 400）で断り、通らない所と理由を「診断情報を表示」の`Detail`に表示します。**
- 原因がこの3つ以外のときは、これまでどおり`internal_error`です。理由はsshcエンジンのログ（`~/.ssh/sshc/logs/engine.log`）に残ります。

## 同期

- v0.59.1とv0.59.2のマシンは、SFTPの分割の比率をマシンの状態に書いて同期します。v0.59.3はこの値を使いませんが、届いたマシンの状態にこの値があっても読み飛ばして同期します。全部のマシンを一度に更新しなくてもかまいません。
