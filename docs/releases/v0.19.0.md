# sshc v0.19.0

TerminalをClaude Code、Codex、OpenCodeの作業状態まで理解できるようにし、AndroidとWindowsのネイティブ体験も改善した更新です。

## Coding Agentを理解するTerminal

- Terminal paneのheaderを、作業名と接続aliasを中心にした二層表示へ変更しました。
- Claude Code、Codex、OpenCodeから共通Agent Bridge protocolを受信し、作業中、入力待ち、完了、状態不明を表示します。
- 非表示中のpaneで入力待ちまたは処理完了になった場合、控えめな通知音を鳴らします。OS通知はすでに許可されている場合だけ使用し、promptやremote pathを本文へ含めません。
- Agent自身が持つsession IDを利用して、同じpaneとscrollbackのまま、または新しいpaneで明示的に再開できます。任意commandの自動再実行は行いません。
- session IDはengine memoryだけに保持し、Web API、診断情報、Workspace、Syncへ公開しません。接続aliasの解決先が変わった場合は再開を拒否します。
- Agent由来の名前より利用者が固定したpane名を優先し、「自動の名前に戻す」操作も追加しました。

Agent連携はopt-inです。Claude Code／Codex向けpluginとOpenCode adapterは、公開リポジトリ [sshc-agent-bridge](https://github.com/aida0710/sshc-agent-bridge) から導入できます。連携を導入しない通常のTerminalは従来どおり動作します。

## Android

- Android 13以降の戻るgestureをWeb画面の履歴へ接続し、dialog、Command Palette、navigation drawer、Inspectorを先に閉じます。
- Android標準のfile pickerとStorage Access Frameworkを使い、SFTPのupload／downloadを端末の保存先と連携しました。
- 外部URLをsystem browserへ渡し、転送結果の通知permissionとsystem barのlight／dark同期を追加しました。
- WebView renderer異常時に白画面のままにせず、診断情報と再読み込みを表示します。

## Windows installer

- GitHub Releaseの`install.ps1`をPowerShellから一行で実行できるようにしました。
- platformとarchitectureに一致する署名対象artifactを選び、checksumを検証してからユーザー専用directoryへ導入します。
- CIとRelease workflowでWindows installerの導入smoke testを実行します。

## 安定性

- Agent Bridgeのprivate OSCは文字コード変換とscrollback投入より前に、4 KiB上限のstate machineで解析します。壊れたmessageやchunk分割でTerminal streamを停止しません。
- Agent eventをprocess generationへ束縛し、再接続前の遅延eventが新しいshellを上書きしないようにしました。
- バックグラウンド中も低頻度の状態確認を継続し、通知対象のsignalを取りこぼさないようにしました。
