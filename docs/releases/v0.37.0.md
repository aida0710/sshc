# sshc v0.37.0

v0.37.0では、Terminalの接続ログを`ssh -vv`／`-vvv`に見合う内容にし、各行にその行を出した深さを付けました。あわせて、ブラウザーのセッションに期限を設けてMenuからサインアウトできるようにし、ホストのaliasを改名したときにVaultのパスワードとTOTPの割り当てが旧名に取り残される問題を直しています。

## 更新後に必要な操作

v0.36.0以降から更新する場合、追加の操作はありません。v0.35.0以前から更新する場合は、[v0.36.0のリリースノート](v0.36.0.md)にあるブラウザーの再登録とengineの再起動が必要です。

## Terminal：接続ログ

［Settings］→［Terminal］→［接続のログ］を［鍵・経由地・所要時間（-vv）］や［すべて（-vvv）］にしても、これまで出るのは接続先、タイムアウト、認証方式の件数、ハンドシェイクの所要時間だけでした。接続の各段階で分かっていることを、その深さで表示します。

- **各行に深さの印が付きます。** OpenSSHの`debug1:`／`debug2:`／`debug3:`と同じく、`[sshc][debug1]`〜`[sshc][debug3]`で始まります。印の無い`[sshc]`は、設定に関係なく出る行（ProxyCommandの実行、再接続の通知）です。
- **サーバーの案内（banner）を表示します。** これまでは認証前にサーバーが送る案内を捨てていました。［基本情報（-v）］以上で表示し、制御文字を落とし、行数と長さに上限を置きます。
- **-vvで表示するもの**: 認証方式の候補（試す順）と試さない理由。鍵ごとのパス、種類、SHA256指紋、復号の仕方（パスフレーズ無し／保存済み／入力）。読めなかった鍵（他の鍵で接続できた場合、これまでは誰にも報告されませんでした）。agentの鍵の件数と、`IdentitiesOnly yes`でagentを使わなかったこと。サーバーのホスト鍵の種類と指紋、`known_hosts`の何行目と一致したか、一致しない場合はどの行にどの鍵があるか。パスワードの出どころ（保存済みを送った／拒否されて入力を求めた）と、keyboard-interactiveの質問に保存済みの資格情報で答えた件数。どの方式で認証されたか。端末の要求（列×行、TERM）、送った環境変数の名前と**サーバーに拒否された環境変数**、シェルかリモートコマンドか、keepaliveの間隔と回数、文字エンコーディング。読むが適用しない設定（`RemoteForward`など。これまでは`sshc info`でしか見えませんでした）。
- **-vvvで表示するもの**: 名乗るホスト鍵アルゴリズム、TCPのローカル／リモートアドレス、鍵交換までの時間、agentの鍵の指紋一覧、keyboard-interactiveの質問ごとの文と入力表示。
- パスワード、パスフレーズ、TOTPコード、環境変数の値はログへ出しません。鍵は指紋で、秘密は出どころだけを表示します。keyboard-interactiveの質問文は制御文字を落としてから表示します。
- 「認証コード質問の入力表示」の行は、-vvvの質問ごとの行に含まれるため無くなりました。

```
[sshc][debug1] bastion.example:22 へ接続します（ユーザー：ops）。
[sshc][debug2] 認証方式の候補（試す順）：publickey, keyboard-interactive, password
[sshc][debug2] サーバーのホスト鍵：ssh-ed25519 SHA256:cRQ56FY6+EK/d6EHLpxA+YbH9ZaaHS47Ek6GKpBlTW8
[sshc][debug2] ホスト鍵は known_hosts の 14 行目と一致しました。
[sshc][debug2] 認証方式を試します：publickey
[sshc][debug2] 鍵 /home/me/.ssh/id_ed25519：ssh-ed25519 SHA256:td9Bg78u...（保存済みパスフレーズで復号）
[sshc][debug2] 鍵 /home/me/.ssh/id_old は使えません：open ...: no such file or directory
[sshc][debug2] 認証方式 publickey で認証されました。
[sshc][debug1] bastion に接続しました（1/2）。
```

## ブラウザーのセッションとサインアウト

- ブラウザーのセッション（cookie）は、これまでengineの再起動まで無期限でした。**12時間使われないか、発行から7日**で切れます。切れたセッションは、登録が有効なら次の読み込みで自動的に入り直すので操作は変わりません。cookieが盗まれた場合の有効期間だけが区切られます。
- ［Menu］の末尾に［サインアウト］を追加しました。「このブラウザーからサインアウト」は、セッションとブラウザーの登録の両方を消します。その後に開くには`sshc`（または`sshc open`）が表示するURLが必要です。開いているTerminalのセッションはengine側で動き続けます。
- HTTP APIに`POST /api/v1/session/sign-out`を追加しました。

## Connections と Vault

- **ホストのaliasを改名すると、そのaliasに割り当てたパスワードとTOTPが旧名の下に取り残される問題を直しました。** Vaultが開いていれば、改名の保存時に割り当ても新しいaliasへ移します。Vaultがロック中は設定の改名だけを行います。
- Syncの適用時、リモートのスナップショットが削除されていた場合に「プレビューが古い」ではなく「リモートが削除された」と報告します。

## CLI

- `sshc vault change-password`が、現在のパスワードの確認後に空行を出力していたのをやめました。

## 内部の変更

- CIの`go test -race`をPRではLinuxだけで走らせ、mainへのpushでは従来どおり3 OSで走らせるようにしました。PRのCIは約18分から8分前後になっています。Windowsの`go test`には20分のtimeoutを与えました。
- テストからしか呼ばれない公開API 35件を削除し、テストは製品と同じ経路を通すようにしました。残る7件は時計・sleep・シリアルbackendの注入と、本番serverを組み立てる入口です。
- symlinkをたどらないファイル操作を`internal/platform/nofollow`に集め、engineの引き継ぎファイルの書き込みもワークスペースの他のファイルと同じ原子的な書き込みに載せました。
- Syncの接続先の検証を、CLIの対話入力とHTTPの設定APIで1つにしました。VaultのパスワードとTOTPの割り当てで同じ形だった処理も1つにしています。
- SFTPの転送とCLIのrunnerで8〜10個の位置引数を渡していた関数を名前付きの構造体にし、Webの設定の読み込みを生成されたvalidatorに載せ替え、ConnectionsとKeysの画面で繰り返していた処理をまとめました。動作は変えていません。
