# sshc v0.13.4

Android 16でprivate workspaceを初期化できない起動障害を修正し、Web UIの操作失敗を安全な診断レポートとして共有できるようにしました。

## Android 16の起動修正

- Linux／Androidの安全なpath walkerが、中間directoryをread可能であると仮定しないようにしました。Android 16で`/`や`/data`の一覧取得を拒否されても、既知のapp private directoryをdescriptor-relativeに辿れます。
- 中間directoryはLinuxの`O_PATH`で開き、symlinkを辿らない`openat`境界を維持します。最終workspaceだけをread/write可能なdescriptorとして開くため、安全性を緩めていません。
- directoryを検索できるが一覧取得できないAndroid相当の権限fixtureを追加し、mobile engineの起動経路とfilesystem単体の両方で再発を検出します。
- Linuxの`O_PATH | O_NOFOLLOW`がsymlinkに返す`ENOTDIR`を検査し、従来どおり`ErrSymlinkPath`へ分類します。Linux以外のUnixは従来のreadable descriptor方式を維持します。

## 共通エラー診断

- APIとstreaming transferの予期しないserver／network失敗をApp shellで通知し、version、安定したerror code、HTTP status、method、pathname、安全確認済みdetailを表示します。入力不備や競合は従来どおり各操作画面だけで具体的に説明します。
- 診断レポートは一操作でコピーでき、通常画面を離れずに閉じられます。起動途中のhealth request失敗にも同じ表示を使用します。
- request body、query parameter、fetch例外本文は診断情報へ含めません。鍵、S3認証情報、host alias、remote pathなどを意図せずreportへ混ぜないためです。
- CSRFの自動更新で回復したrequest、vault lock／session終了、任意のbackground update確認は操作エラーとして重ねて表示しません。

## 検証

- Android相当のexecute-only ancestorを使ったGo単体testとrace detector、Android arm64 cross buildを確認しました。
- API失敗、network失敗、raw response、query除去、session lifecycle除外、診断画面のWeb単体testを追加しました。
- Playwrightで実際のengineを起動し、失敗responseから診断画面が表示されることと、reportにqueryが含まれないことを確認します。
- Android AAR／APK、Java unit test、APK署名、全platform成果物とattestationはrelease前のrequired CIで確認します。

## 互換性

設定、Workspace、Snippet、同期snapshot、SFTP転送queueの保存形式は変更していません。Android起動時のfilesystemアクセス方法とWeb UIのエラー表示だけを変更しています。
