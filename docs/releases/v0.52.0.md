# sshc v0.52.0

v0.52.0では、SFTPとCLIの`sshc sftp`で、`~`から始まるパスを使えるようにしました。

あわせて、SFTPで開けないパスを入力したときの表示と、SSH Configの画面（Config Explorer）でのパスの扱いを修正しています。

## SFTPのパスと~

- これまでは、リモートのパスの欄に`~/logs`と入力すると、不正なパスとして開けませんでした。**`~`と`~/`で始まるパスを入力できるようにしました。** SFTPサーバーのログイン先（通常はホームディレクトリ）から数え、移動すると絶対パスで表示します。ローカルのパスの欄では、これまでどおり`~`を使えます。
- ［フォルダへ移動］の移動先でも、`~`と`~/`で始まるパスを使えるようにしました。移動する前にその場所を読み、フォルダであることを確かめます。
- `~user`の形（ほかのユーザーのホームディレクトリ）には対応していません。
- これまでは、パスの欄に`logs`のような`/`も`~`も無いパスを入力すると、接続できているのに「接続できませんでした。」と表示していました。「パスを開けませんでした。絶対パスか、~/で始まるパスを入力してください。」と表示するように修正しました。

## CLIのsshc sftp

- これまでは、`sshc sftp get`と`sshc sftp put`のリモートのパスに絶対パスしか指定できませんでした。**`'~/logs/app.log'`のように、`~/`で始まるパスを指定できるようにしました。** SFTPサーバーのログイン先から数えます。
- `~`は引用してください。引用しないと、シェルが手元のホームディレクトリに置き換えてからsshcに渡すため、リモートでは手元のホームディレクトリと同じパスを探します。
- これまでは、手元のパスに引用した`~`を書くと、作業ディレクトリの下に`~`というフォルダを作っていました。手元のホームディレクトリとして読むように修正しました。
- `sshc vpn`で設定ファイルのパスを入力するとき、`~`だけのパスと、Windowsの`~\`で始まるパスも、ホームディレクトリとして読むようにしました。これまでは`~/`で始まるパスだけでした。

## SSH Config（Config Explorer）

- 「~/.sshのファイル」の欄と、ファイル名の変更の欄は、`~/.ssh`からの相対パスを受け付けます。これまでは`~/.ssh/conf.d`と入力すると、`~/.ssh`の中に`~`というフォルダを作り、その下に`.ssh/conf.d`を作っていました。**`~/.ssh/`で始まるパスを、`~/.ssh`からの相対パスと同じ場所として扱うように修正しました。**
- `~/.ssh`の外を指すパス（`~/notes`など）は、作らずに欄の下に理由を表示します。
