# 文章と用語のガイド

このリポジトリの README、ドキュメント、コードコメント、CLI、Web UI、リリースノートには、同じ文体と用語を使用します。

## 基本方針

- 比喩よりも、実際に行う処理を記述します。
- 主語がなくても明確な文では、アプリケーションを擬人化しません。
- 強調は警告や重要な前提に限定し、段落全体を太字にしません。
- 実装の経緯は、現在の挙動を理解するために必要な場合だけ記載します。
- エラー文は、発生した事象、影響、利用者が行える対処の順に記述します。

## 推奨する用語

| 使用する表現 | 避ける表現 |
| --- | --- |
| URL を表示する | 入口を刷る |
| エンジンを起動する | エンジンを起こす |
| エンジンを常駐させる | エンジンを生かしておく |
| 実行ファイル、バイナリ、プロセス | 実体 |
| パス、名前、文字列 | 綴り |
| 値、結果、応答、資格情報 | 答え |
| 暗号化する | 封じる、封をする |
| SSH 接続を確立する、SSH プロトコルを実装する | SSH を話す |
| 指定する、参照する、表示する | 名指しする |
| 検査、回帰テスト | 見張り |

コード内の識別子や OpenSSH の正式な用語は、既存の英語表記を維持します。日本語と英数字の間には半角スペースを入れます。
