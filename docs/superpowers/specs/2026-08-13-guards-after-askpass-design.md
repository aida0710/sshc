# askpass のあとの守りと継ぎ目を棚卸しする

## 目的

`SSH_ASKPASS` が消えたあとに何が余っているかを確かめ、余っているものを消す。
**残す守りには、残る理由といつ消せるようになるかを書く。**

外殻（Electron）を作る前にこれをやるのは、**外殻が何を不要にするのかを、
外殻を書く前に知っておくため**である。

## 行き先

決まっていること。

- **Electron がブラウザを置き換える。** 窓を足すのではなく、入り口をひとつにする
- **Go のエンジンは Electron の子プロセスである。** アプリを閉じればエンジンも止まる

この spec はそこへ着く前の一歩であり、**この spec の中で外殻は作らない。**
行き先を書くのは、いま残す守りが「いつ消せるか」を言うためである。

## 調べて分かったこと

**このアプリケーションは OpenSSH のプログラムを一つも実行しない。**

B4 の README は「残る OpenSSH のプログラムは `ssh-keygen` ひとつ」と書いたが、
**不正確である。** `ssh-keygen` は名前を出すだけで、走らせるのは利用者である
（`HardwareCommand` が返すのは画面に表示する引数の並びで、このアプリケーションは
それを実行しない）。`Toolchain.KeyGen()` を呼ぶのは、**その項目を一覧に出して
よいかを決めるため**だけである。

このプロセスが起こす子は 3 つで、どれも SSH ではない。

- 既定ブラウザの起動（`open` / `xdg-open`）
- ログイン時起動の登録（`launchctl` / `systemctl`）
- ローカルシェル（PTY の中）

**その結果、OpenSSH の子プロセスのために作った仕組みが宙に浮いている。**

| 余っているもの | 何のためにあったか |
| --- | --- |
| `platform.MinimalEnvironment` | `ssh` と `ssh-add` から `SSH_ASKPASS` を取り除く。**読み手が居ない** |
| `platform.Command.StopAfter` | `ssh -v` の出力に `Authenticated to` が現れた時点で止める。**渡す側が居ない** |
| `platform.Command.Stdin` | 公開鍵を `ssh` の標準入力へ流す。**渡す側が居ない** |
| `app.Dependencies.Runner` | 診断と登録と keyscan が使っていた。**読み手が居ない** |

コメントも古い。`Dependencies.Lookup` は「このプロセスが起動する OpenSSH
プログラムが……」と書いてあるが、いまはログインシェルを探すためだけにある。
`Options.TerminalEnvironment` も「検査が使う最小環境ではなく本人の環境を継ぐ」
と、比べる相手がもう無いものと比べている。

## 決定事項

**1. 読み手の居ない継ぎ目は消す。** 上の 4 つ。**「いつか使うかもしれない」で
残さない**——使うときに書けばよく、その日の要求は今日の想像とは違う。

`platform.Command` から `Stdin` と `StopAfter` が消えると、
`internal/platform/process` の `boundedBuffer` からマーカーの分岐も消える。

**2. 守りは一つずつ、残る理由と共に書く。**

| 守り | いま残る理由 | いつ消せるか |
| --- | --- | --- |
| loopback の TCP listener | レンダラーと CLI が到達する必要がある | 両方が別の経路になったとき |
| bootstrap トークン | 最初のセッションを画面へ一度だけ渡す | **残る。** 外殻も同じ手を使う |
| セッション cookie | どの窓からの要求かを言う | 残る |
| CSRF ヘッダー | **他のオリジンのページが、ブラウザにこの port へ POST させられる** | **ブラウザ経路が消えたとき。** レンダラーが自分のものだけなら、そのページは存在しない |
| handoff の秘密 | CLI が TCP で来るので、誰が来たかを言う手段が要る | CLI が別経路になったとき |
| ストリームのチケット | ブラウザは WebSocket のアップグレードにヘッダを付けられない | **残る。** Electron のレンダラーも Chromium である |
| action トークン | 実世界に効く操作を、表示した内容へ縛る | **残る。B は何も変えていない** |

**この表は、いま何も消さない。** 消せるようになる条件を書くのがこの節の仕事で
ある。**条件を書かずに「まだ要る」とだけ言うと、要らなくなった日に誰も気づかない。**

**3. 「何も実行しない」を検査で言う。**

`internal/acceptance` に `TestNoConnectionRouteStartsAnExternalProgram` が既に
あるが、あれは接続の経路だけを見ている。**このアプリケーションが起こしてよい
プログラムの一覧**を持つ検査を足す——ブラウザ、`launchctl` / `systemctl`、
ログインシェル。それ以外が継ぎ目に届いたら失敗する。

一覧を持つ形にするのは、**増えたときに気づくため**である。「OpenSSH が無い
こと」を検査すると、OpenSSH でない何かが増えても緑のままになる。

## 構成

```
internal/platform/command.go          MinimalEnvironment、Stdin、StopAfter を削除
internal/platform/process/command.go  マーカーの分岐を削除
internal/app/run.go                   Dependencies.Runner を削除、コメントを直す
internal/httpserver/server.go         Options のコメントを直す
internal/acceptance/programs_test.go  起こしてよいプログラムの一覧（新）
README.md                             「一つも実行しない」へ訂正、守りの表
```

## エラー処理

削除だけなので新しい失敗は増えない。**`Dependencies.Runner` を消すと
`cmd/sshc` の組み立てが 1 行減る**が、ブラウザとログイン項目は自分で
ランナーを受け取っているので、それらは変わらない。

## テスト

- **起こしてよいプログラムの一覧**（上記）。正のコントロールとして、ブラウザの
  起動が実際にその継ぎ目へ届くことを見る——全部拒否されていたら「一覧の外が
  来なかった」は当たり前の話になる
- 既存の検査はそのまま通ること。**消すのは読み手の居ないものだけ**なので、
  振る舞いは変わらない

## README の書き換え

- 「残る OpenSSH のプログラムは `ssh-keygen` ひとつ」→ **「一つも実行しない」**。
  `ssh-keygen` は名前を出すだけで、走らせるのは利用者であること
- 守りの表を足す。**それぞれが何から守っているか**と、いつ要らなくなるか

## 未解決

- **Electron の外殻**（次）。ブラウザ経路を落とすと CSRF が消せる
- **CLI の経路。** エンジンが Electron の子になると、アプリが動いていないときの
  `sshc <接続先>` は保存済みパスフレーズを得られない。**端末で尋ねれば繋がる**
  ので壊れはしないが、そこは外殻の spec で決める

## 実装者への注意

  必ず `git diff --cached` で staged 内容そのものを読む
- Linux は Docker で確かめること
