# ホーム操作・既定端末・同期結果の明確化

## 目的

Web UI の三つの導線を、操作の作用範囲と実際に起きたことが画面から分かる形へ直す。

1. Home の各接続カードは、直ちに Terminal を開く一つのボタンではなく、接続設定と実接続を選べる入口にする。
2. 全接続に共通する既定の端末アプリを、個別接続の詳細ではなく Settings で設定する。
3. S3 互換ストアへの push、取得プレビュー、適用について、対象データ、スナップショット、実転送量、時刻、変更件数を明示する。

この三つは独立した機能だが、いずれも「ボタン名だけでは作用範囲または結果が分からない」という同じ問題を解く。秘密情報モデル、SSH 設定の意味、同期の競合解決方法は変更しない。

## 現在の問題

### Home

各カードには `接続` しかなく、同じ接続の設定を開くには Connections へ移動して探し直す必要がある。カードのボタンを押すと即座に Terminal を起動するため、管理したい人と接続したい人の入口が分かれていない。

### 既定の端末

Terminal、iTerm、Kitty、カスタムアプリの選択は全接続で共有する `metadata.json` の値である。しかし現在の選択欄は個別接続の詳細に置かれており、その一台だけに適用される設定に見える。さらにクライアントが読み込んだ metadata 全体を書き戻す形では、別タブで行われたタグやお気に入りの変更を古い値で上書きし得る。

### リモート同期

push 成功後の応答は最後の時刻とファイル数を持つ `SyncStatus` だけで、元データ量、暗号化後のオブジェクト量、実際の PUT 回数と転送量を伝えない。取得応答は変更パスを返すが、ダウンロード量、スナップショット作成時刻、展開後のデータ量を返さない。画面の成功文も `push しました`、`適用しました` に留まる。

一回の push は同じ暗号化済みスナップショットを二つのオブジェクトへ PUT する。日付付き履歴と、条件付き更新されるライブスナップショットである。オブジェクトサイズだけを「送信量」と表示すれば、実転送量を半分に見せることになる。

## 検討した選択肢

### UI 文言だけを変更する

差分は小さいが、クライアントは圧縮前、暗号化後、転送済みの正確な byte 数を知らない。推測値を成功結果として表示することになるため採用しない。

### 操作結果を API の明示的な契約にする

サーバーが実際に扱った byte 数とスナップショットの manifest を基に構造化結果を返し、最後の成功結果だけを既存の同期 state に保存する。正確さを保ちながら、監査ログ一式を新設せずに済むため採用する。

### 全同期操作の履歴を新設する

長期的な転送統計や失敗監査には使えるが、今回必要なのは直前の操作と現在適用されているスナップショットの説明である。新しいログ、保持期間、削除 UI を必要とするため非採用とする。

## Home の接続メニュー

各接続カードの右上に、`<alias> の操作` というアクセシブル名を持つ `…` ボタンを置く。開くメニューの項目は次の二つだけとする。

1. `接続設定を開く`
2. `接続`

`接続設定を開く` は `connectionLocation` を使って server 一覧内のその identity と Basic panel を名指す正規 URL を生成する。identity は alias だけでなく設定ファイルの相対 path も含める。同名 alias が複数ファイルに存在しても、別の接続を推測して開かない。

`接続` は現在と同じ `terminalLaunch(alias)` を呼ぶ。この項目を選ぶまでリモートホストへの通信は始めない。メニューを開くことと設定を開くことは、SSH 接続の action token を発行しない。

同時に開くメニューは一つだけとし、項目選択、外側の pointer 操作、Escape で閉じる。キーボードでボタンへ focus し、メニュー項目を選べるようにする。接続中は全カードの接続操作を二重送信できないよう無効化するが、設定を開く操作まで不要に無効化しない。

直接の `接続` が一段深くなるため、頻繁な接続は一クリック増える。これは、設定への入口を同じ場所に置き、誤接続を減らすこととの明示的な交換条件として受け入れる。

## Settings の既定接続アプリ

Settings に `既定の接続アプリ` セクションを追加する。既存の terminal options API が返す次の情報をそのまま使う。

- 現在選択中の端末
- Terminal、iTerm、Kitty など既知の端末とインストール状態
- カスタム端末として選べる、このマシンで検出済みのアプリケーション

既知の端末を選んだ場合はその場で保存する。未インストールの選択肢は消さず、名前とともに利用できない理由を示す。カスタムを選んだ場合はアプリケーションと argv の追加引数が揃ってから保存する。シェル文字列は導入せず、現在と同じ検証済み argv として扱う。

`PUT /api/v1/terminal/preference` を追加する。要求は terminal ID と、custom の場合だけ application path と arguments を持つ。応答は保存後の terminal options とする。

サーバーは要求を受けた時点で最新の metadata を読み、terminal と customTerminal の二項目だけを置き換え、既存の storage transaction と precondition で保存する。クライアントが metadata 全体を送り返す方法にはしない。これにより、別タブで更新された host/group metadata を古い Settings 画面が上書きしない。

Connections の詳細から端末選択欄とカスタム引数欄を削除する。接続ボタンは引き続き全体設定を使用する。選択中の端末が利用できない場合は接続詳細にも失敗理由を表示できるが、変更先は Settings に一本化する。

## 同期操作の計測

共通のスナップショット要約は次を持つ。

- `createdAt`: manifest が示すスナップショット作成時刻
- `fileCount`: manifest に含まれるファイル数
- `sourceBytes`: manifest 対象ファイルの内容 byte 数の合計
- `snapshotBytes`: gzip 圧縮後、暗号化 envelope を含む一オブジェクトの byte 数

push 結果はこれに次を加える。

- `objectCount`: 成功した PUT の数。通常は履歴とライブの 2
- `uploadedBytes`: 各 PUT body の byte 数の合計。通常は `snapshotBytes * 2`
- `completedAt`: 操作が成功した時刻

取得結果は次を加える。

- `downloadedBytes`: GET で受け取った暗号化オブジェクトの byte 数
- `written`: 書き込む、または書き込んだ path
- `removed`: 削除する、または削除した path
- `conflicts`: 適用を止める競合
- `applied`: ローカルへ適用したか
- `completedAt`: 取得または適用が成功した時刻

`sourceBytes` は tar header や manifest 自身を含めず、利用者が管理しているファイル内容の総量とする。`snapshotBytes` は S3 が実際に保持する暗号化オブジェクト一個の大きさとする。`uploadedBytes` と `downloadedBytes` は HTTP body として実際に移動した量とする。この三つを混ぜずに表示する。

`remotesync.Service.Push` は、収集した contents、構築した archive、封印した bytes、成功した PUT を基に結果を組み立てる。`PullResult` は取得した object body と展開済み contents から同じ要約を組み立てる。推測やファイルシステムの再走査で値を作らない。

## API と永続状態

push endpoint は `SyncStatus` 単体ではなく、更新後の status と push 結果を持つ `PushResponse` を返す。pull endpoint の `PullResponse` にはスナップショット要約、downloadedBytes、completedAt を追加する。秘密の内容、秘密鍵の bytes、パスフレーズ、S3 credential はどの応答にも含めない。

既存の `sshc/sync-state.json` へ、最後に成功した書き込み操作の要約を任意フィールドとして追加する。

- push 成功時は `push`
- pull の適用成功時は `apply`
- 取得プレビューはローカル状態を変えないため永続化しない

古い state には新しいフィールドがない。デコード時は従来の ETag、key、base、origin だけで正常に動作し、画面は従来どおり時刻とファイル数を表示して容量を `不明` とする。state の schema 移行や破壊的な書き直しは行わない。

取得プレビューと適用は別リクエストであり、適用時にはライブスナップショットを再取得する。これはプレビュー後に remote が変わった場合、古い確認で新しいデータを適用しないための現在の安全境界である。画面は各リクエストの downloadedBytes を別の操作として表示し、適用時に再取得したことを隠さない。

## 同期画面

一行の成功文ではなく、操作直後の構造化された結果カードを snapshot 操作欄の近くへ表示する。

push 成功例:

```text
12ファイル・4.8 MB
暗号化スナップショット 1.9 MB
S3転送 3.8 MB（履歴＋ライブ）
2026年8月12日 01:30に作成
```

取得プレビュー例:

```text
1.9 MB取得・展開後4.8 MB
2026年8月12日 01:30のスナップショット
書き込み5件・削除1件・競合0件
```

適用成功時は `2026年8月12日 01:30のスナップショットを適用` と、書き込み・削除件数、適用時に再取得した量を表示する。pull は三者比較であり、manifest に無いローカル固有ファイルを保存する場合があるため、ワークスペース全体をその時刻へ戻したという意味の `完全復元` は使わない。

byte 数は API では整数の bytes とし、画面で B、KB、MB へ変換する。MB は 1,000,000 bytes とする。同じ値は現在の locale で一貫して整形し、丸め前の値で計算する。

再読み込み後は status の最後の成功操作を `前回の成功` と明示して表示する。新しい操作が失敗しても以前の成功を消さず、失敗は別の danger notice として表示する。失敗した操作を最後の成功として state に書かない。

push は履歴 PUT の後にライブ PUT を行う。履歴が成功しライブの条件付き更新が拒否された場合、日付付きコピーが残り得る。この失敗を `何も送信しなかった` とは表示せず、ライブは更新されておらず履歴コピーが残っている可能性を既存の remote-moved エラーに明記する。二オブジェクトを一つの原子操作にすることは S3 の契約上できないため、この境界は隠さない。

## エラー処理

- Home の接続失敗は対象 alias と、端末未導入または起動失敗の区別を表示する。メニューは再操作できる状態へ戻す。
- 既定端末の保存失敗時は選択表示をサーバーが返した値へ戻し、保存済みと誤認させない。
- 同期の失敗は既存の原因別エラーを維持する。以前の成功カードと今回の失敗を同じ status 文へ上書きしない。
- push の部分成功ではライブ更新の成否を成功扱いにしない。同期 state と `前回の成功` は更新しない。
- pull の競合時もスナップショット時刻、取得量、変更候補を表示し、なぜ適用されなかったかを同じカードで説明する。

## セキュリティ境界

- Home のメニューを開く、設定を開く、Settings で端末候補を読む操作は SSH 接続を開始しない。
- Terminal preference は metadata の UI 設定であり、秘密情報を持たない。
- カスタム端末の起動はシェルを経由せず、既存の application path と argv 検証を再利用する。
- 同期応答は容量、時刻、件数、既に表示している相対 path だけを返す。ファイル内容、鍵素材、S3 credential、パスフレーズを返さない。
- snapshot の容量は認証済み localhost API の内側だけで表示し、ログへ新たに書かない。

## テストと完了条件

### Web unit

- Home の `…` は開いただけで launch せず、設定項目が正しい path、alias、Basic panel の URL へ遷移する。
- 接続項目だけが terminal launch を行い、二重送信を防ぐ。
- メニューは Escape と外側操作で閉じ、アクセシブル名を持つ。
- Settings は現在値、未導入端末、custom application と引数を表示し、保存成功・失敗を正しく反映する。
- Connections 詳細には全体端末の編集欄が残らない。
- push、取得、適用、競合、旧 state の各結果を byte 単位から正しく整形して表示する。

### Go unit / API

- terminal preference は最新 metadata の二項目だけを変更し、host/group metadata を保持する。
- 同値保存は不要な journal を作らず no-op として扱う。
- push は sourceBytes、snapshotBytes、二 PUT 分の uploadedBytes、createdAt を実測値から返す。
- pull は downloadedBytes、sourceBytes、createdAt、変更・削除・競合を返す。
- preview は last operation を保存せず、push と apply の成功だけを保存する。
- 古い sync-state.json を読み、新しい任意フィールドなしで従来どおり同期できる。
- API の runtime validator は新しい必須フィールドを検査する。

### End-to-end / integration

- Home から設定を開く正規 URL と、明示的な接続だけが Terminal を開くことを Playwright で確認する。
- Settings で選んだ端末が Home と Connections の接続に共通して使われることを確認する。
- 実 S3 互換コンテナで push の二 PUT、object size、取得時刻、apply 後の永続 status を検証する。
- OpenAPI 生成物、Go normal/race、Web tests/typecheck/build、Playwright、Docker-backed S3/OpenSSH integration をすべて通す。
- production build の `internal/ui/dist` を更新する。
- パッケージ追加は行わない。

## 非目標

- ホストごとの端末アプリ override
- 同期操作の無期限な監査ログやグラフ
- S3 の日付付き履歴を列挙、選択、削除する UI
- push の二つの PUT を原子的に見せること
- pull の競合を自動解決すること
- ワークスペースに無関係なローカルファイルをスナップショットへ含めること
- 秘密情報やスナップショット内容を API response に含めること
