# 接続概要と編集導線の再設計

## 目的

既存接続を開いた人が、保存済みの接続先と認証状態を最初に理解し、その場で基本設定を編集し、保存済み状態に対して接続確認または接続を実行できる画面にする。

TUI の機能追加や全画面の外観刷新ではなく、Web の最頻出経路である次の一連の操作を完成させる。

1. 接続を選ぶ。
2. 保存済み状態を理解する。
3. 基本設定を編集する。
4. 保存済み状態に対して到達性・認証を確認する。
5. 接続する。

## 現状の問題

- 接続名と保存済み状態より先にターミナル選択、接続、管理操作が現れ、対象と状態より操作が強く見える。
- 基本、踏み台、詳細、Raw、実効値、診断の六つが同じ強さのタブとして並び、日常操作と高度な編集の差がない。
- 基本設定の一括保存、組織情報の個別保存、インスペクターの即時保存が一つの流れに混在する。
- `ConnectionBasicForm` は鍵、vault、資格情報という補助データの取得と、HostName、User、Port の config 編集可否を一つに束ねている。そのため、解錠済みのセッションでも補助データの一部を読めないだけで、秘密を変更しない基本編集まで巻き添えになる。サーバー側の config-only update は秘密変更を要求しないため、画面側も部分失敗を分離できる。
- 基本フォームはタブを離れると unmount され、未保存の入力を保持できない。
- 診断の中に認証テストが入り、「認証設定」と「保存済み設定で認証できるか試す操作」の関係が分かりにくい。

## 採用する構成

既存のデスクトップ二ペイン構成を維持する。左側は接続一覧、右側は選択した接続の詳細である。スマートフォン専用画面は作らない。

右側は上から次の順にする。

1. 保存済み概要
2. 保存済み状態に対する操作
3. 編集領域
4. 未保存状態と保存操作

表示モードと編集モードは分けない。概要の直下に基本編集フォームを常時表示し、編集開始のための追加クリックを要求しない。

## 保存済み概要

`ConnectionSummary` は下書きではなく、最後にサーバーから確認できた保存済み状態だけを表示する。

- alias
- `user@hostname:port`
- 保存済み IdentityFile
- その鍵のパスフレーズ状態
- ログイン用保存済みパスワードの割り当て状態
- 所属グループ
- 保存済み状態か、未保存変更があるか

鍵とログインパスワードは独立した項目として表示する。OpenSSH は両方を試しうるため、一つの「認証方法」へ畳み込まない。

vault が開いている場合は、専用・名前付き・割り当てなしを安全なメタデータだけで表示する。vault が施錠中または資格情報一覧を読み込めない場合は「なし」と推測せず、「施錠中のため確認できない」または「読み込めない」と表示する。秘密値は概要、DOM、URL、ログ、API 応答へ出さない。

フォームの下書きが変化しても概要を先回りで書き換えない。代わりに「未保存の変更あり」を概要と保存バーの両方へ表示する。

## 接続、到達性、認証確認

概要に次の明示的な操作を置く。

- 接続
- 到達性を確認
- 保存済み設定で認証を確認

到達性と認証は「診断」ではなく、保存済み接続を実際に使えるか確かめる接続操作として扱う。結果は `ConnectionChecks` として概要直下へ展開する。パネルを開くだけでは、ネットワーク接続、`ssh -G`、認証、Terminal 起動を一切開始しない。

認証確認は既存の action token、実行可能ディレクティブ確認、出力上限、秘密情報の非表示を維持する。危険なディレクティブがある場合は現在と同じ確認を必要とする。

未保存変更中は三つの操作を無効化し、「保存または破棄してから、保存済み設定を使用してください」と理由を表示する。保存と接続を一つのボタンへ結合しない。設定保存と外部 SSH 起動は失敗境界が異なるためである。

到達性・認証結果は現在のブラウザーセッションにだけ保持し、永続化しない。接続変更または保存成功後にリセットする。未実行状態を成功・失敗のどちらにも見せない。

## 編集領域の情報設計

日常操作は次の三つの表示領域とする。

### 基本

- HostName
- User
- Port
- IdentityFile
- 鍵専用パスフレーズの保存・付け替え
- ログイン用保存済みパスワードの割り当て・解除

基本設定は一つの「基本設定を保存」で扱う。config と秘密の両方を変える場合は、既存のサーバー側一トランザクションを維持する。

アプリケーション全体の vault gate は維持する。施錠中またはセッションが時間切れになった状態から config を更新できる例外 route は作らず、現在と同じ入口へ戻す。

解錠済みのセッションでは、保存済みパスワードまたは鍵パスフレーズの変更だけが資格情報 metadata の正常な取得を必要とする。資格情報一覧の読み込みに失敗しても、HostName、User、Port と、秘密変更を伴わない既知の IdentityFile は編集・保存可能なままにする。鍵 inventory 自体を確認できない場合は IdentityFile の新規選択だけを unavailable とし、既に保存されている値を消したり「なし」と推測したりしない。config-only request は資格情報を `unchanged` として送り、読み込めなかった割り当てを解除する request に変換しない。

### 設定解析と詳細設定

六つの同格タブは次の階層へ整理する。

- 基本
- 設定解析
- 詳細設定

設定解析は、説明用実効値、値の出所、設定上の notice、権威ある `ssh -G` の明示的実行を扱う。`ssh -G` が `Match exec` を評価しうる現在の確認境界は維持する。

詳細設定の内部に、踏み台、任意ディレクティブ、Raw を置く。既存の高度な編集能力は削除しないが、基本設定と同じ視覚的優先度では並べない。

## 接続管理操作

基本タブ下部に混在している整理操作は `ManageConnection` へまとめる。

- alias の変更
- 所属グループの変更
- コメントの保存
- 複製
- 保存ファイルの高度な変更
- 削除

これらは基本設定の保存へ見かけ上統合しない。現在のサーバー側トランザクションと履歴の境界を維持し、それぞれが独立して保存されることを操作の近くへ表示する。

いずれかのエディターに未保存変更がある場合、identity または base snapshot を変える管理操作は無効化する。先に保存または破棄させ、rename、move、delete 後の再読み込みで下書きが失われないようにする。

お気に入り、色、タグ、並び順などのアプリ内 metadata と、グローバルなターミナル選択は従来どおり個別に即時保存する。ただし、それらの保存成功で `ConnectionEditorState` の snapshot を置き換えたり、基本・詳細設定の下書きを消したりしない。identity と config の base snapshot を変えないため、config の下書き中も操作できる。

## 下書きと画面遷移

接続詳細は選択中の `identity + base snapshot` に属する編集状態を一つだけ持つ。

- 基本、設定解析、詳細設定の表示切り替えでは下書きを保持する。
- 一つの編集領域が dirty の間、別の編集領域は閲覧できるが、新しい下書きを開始できない。
- 別接続の選択、別セクションへの移動、Back/Forward で別 identity へ移る操作は破棄確認を出す。
- 確認を取り消した場合、選択と URL を現在の接続へ戻し、下書きを保持する。
- ブラウザーの reload または close には、dirty の場合だけ `beforeunload` の保護を付ける。
- 破棄は明示的な操作とし、秘密入力を含む下書きは破棄時、保存成功時、接続変更時に消去する。

URL、history、localStorage、sessionStorage へ下書きや秘密を入れない。

保存バーは右ペイン下部に追従表示し、active editor の状態、検証エラー数、「破棄」「保存」だけを扱う。dirty でない場合は操作を強調せず、別領域の独立保存をこのバーへ混ぜない。

## コンポーネント境界とデータフロー

### `ConnectionSavedState`

接続詳細、鍵 inventory、vault status、資格情報一覧から、概要とフォームが共有する安全な保存済み view model を作る。鍵 inventory、vault status、資格情報一覧は接続ごとに一度だけ取得し、概要と基本フォームで重複取得しない。

資格情報を読めない場合も、config detail と鍵 inventory を捨てない。各部分を `available`、`locked`、`failed` として区別し、全体を空状態へ落とさない。

### `ConnectionEditorState`

保存済み snapshot、active editor、draft、dirty、busy、saved revision を所有する。`ConnectionSummary`、`ConnectionBasicForm`、`ConnectionChecks`、`ManageConnection` はこの状態から必要な値だけを受け取る。

`ConnectionBasicForm` が現在内部で行っている鍵・vault・資格情報の取得は共有ロード層へ移す。フォームは下書きの作成、検証、保存 request の構築に集中する。

### 保存後

保存成功時はサーバー応答を受けた後、接続 detail と安全な資格情報 metadata を再取得する。その双方を確認してから概要を置き換え、saved revision を進め、接続確認結果を消す。

config または vault の commit は成功したが再取得に失敗した場合は、成功を失敗へ言い換えない。「保存済みだが表示を更新できない」と表示し、下書き内の秘密を消去する。再読み込みで保存済み状態を確認できるまで接続・確認・管理操作を無効化する。

## URL 互換

接続 identity と表示領域を URL に残し、reload、bookmark、Back、Forward を維持する。既存 URL は次のように互換処理する。

- `tab=basic` は基本を開く。
- `tab=diagnostics` は基本を開き、`ConnectionChecks` を展開する。検査は自動実行しない。
- `tab=effective` は設定解析を開く。
- `tab=jump`、`tab=advanced`、`tab=raw` は詳細設定の対応する内部領域を開く。

URL 正規化で秘密、下書き、検査結果を運ばない。互換 route の置換は画面を開けたことに依存せず、未知の identity を勝手に一覧へ戻さない既存の原則を維持する。

## エラー表示

- 初期 detail の取得失敗は接続を空と見せず、再試行可能なエラーを表示する。
- 鍵、vault、資格情報の部分取得失敗は、その部分だけを unavailable とし、config-only edit を残す。
- field validation は該当 field の近くに表示する。
- 保存の競合、外部変更、鍵変更は既存の具体的エラーと preview を維持し、下書きを勝手に破棄しない。
- 到達性と認証の失敗は `ConnectionChecks` 内で区別する。保存エラーとして表示しない。
- 接続起動失敗は概要の接続操作の近くに表示する。
- 失敗した操作の後に、古い別接続の結果を現在の接続名の下へ残さない。

## テスト

### Component / unit

- 概要が保存済み snapshot を表示し、下書き値へ先行しない。
- 鍵とログインパスワードを独立して表示する。
- vault locked、partial failure、confirmed empty を区別する。
- 解錠済みセッションで secret inventory が失敗しても、HostName、User、Port の config-only draft を保存できる。
- secret inventory failure では秘密変更だけが unavailable になり、既存の割り当てを「なし」と推測しない。
- config-only save が読み込めない資格情報の割り当てを `unchanged` のまま保持する。
- vault timeout 後の保存は gate を迂回せず、下書きを秘密ごと消去して現在の入口へ戻る。
- dirty 中は接続、到達性、認証、identity-changing management を無効にする。
- タブ移動で下書きを保持し、別 identity への移動で破棄確認する。
- 保存成功、接続変更、失敗した確認の後に check results を正しく reset する。
- 保存成功後の refresh failure を保存失敗と言い換えない。
- metadata の即時保存が active editor の下書きと saved snapshot を置き換えない。
- 旧 tab URL を新しい表示領域へ対応させ、検査を自動実行しない。

### End-to-end

- 接続を開くと概要と編集可能な基本 fields が同時に見える。
- 基本 field を変更すると概要は保存値のまま dirty になり、接続操作が止まる。
- 保存後に概要が更新され、接続操作が戻る。
- 解錠済みセッションで資格情報一覧または鍵 inventory の API を部分失敗させても、利用可能な config-only fields を編集・保存できる。
- セッションを時間切れにした後の保存は global vault gate に拒否され、施錠された入口へ安全に戻る。
- 概要から到達性・認証確認を明示的に開始し、別接続へ移ると結果が消える。
- dirty draft の接続切り替え、section navigation、Back を確認または取り消しできる。
- `tab=diagnostics` の deep link は確認パネルを開くが、ネットワークや外部 process を開始しない。

最終検証は生成物整合性、Go normal/race、Web unit、TypeScript、production build、Playwright、Docker-backed SeaweedFS/sshd integration を含む。

## 非目標

- スマートフォン専用 UI または responsive redesign
- TUI の機能追加
- global vault gate の例外 route を追加すること
- 自動診断、自動認証、自動接続
- 保存と接続を一操作へ結合すること
- 下書きまたは確認結果の永続化
- 秘密値を概要、URL、history、storage、ログへ載せること
- SSH config をアプリケーション所有の別形式へ移すこと
- 高度な Raw 編集能力を削除すること
- rename、group move、comment、metadata を基本設定の一トランザクションへ見せかけて統合すること
