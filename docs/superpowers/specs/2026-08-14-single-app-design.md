# ひとつのアプリにする

## 目的

外殻とエンジンを、利用者から見てひとつのアプリにする。**メニューバーに常駐し、
終了すれば全部止まる**という、macOS の普通のアプリの形へ寄せる。

## なぜ

**誰からも見えないエンジンが溜まっていた。** 一日のうちに 8 台が同時に生きて
いるのを実測した。

持ち主が二人いるからである。外殻は `sshc engine start` でエンジンを detach して
起こし、launchd も `RunAtLoad` + `KeepAlive` で別に起こす。どちらが起こしたかを
記録するのは `~/.ssh/sshc/cli`（handoff）ただ 1 行で、**新しいエンジンがそれを
上書きした瞬間、前の 1 台は誰からも見えなくなる。** 止める術も、次の起動で
見つける術も無い。

見えないまま残るのは、生きた SSH 接続・PTY・転送したポート、そして解錠された
vault である。README は転送 1 本について「**開いていることが見えないまま
開かない**」と書いている。エンジン自身がその規則の外にあった。

## この spec の範囲

外殻の生死、ログイン項目、`sshc <接続先>` がエンジンを見つける経路、そして
それらのために Go 側から消えるもの。設定エンジン・vault の中身・埋め込み
ターミナル・同期には触れない。

**下位互換は取らない。** 配布はまだ行っていないので、移行のためのコードは
書かない。既にログイン項目を置いている開発機は手で外す。

## 決定事項

**1. 持ち主はアプリひとつである。**

```
sshc.app（Electron）
 ├─ メニューバーの項目 … 居ることの証拠。施錠状態・開いている本数・終了
 ├─ ウィンドウ（開いていなくてもよい）
 └─ 子プロセス: sshc（エンジン）… 親と一緒に死ぬ
```

エンジンは `spawn` した子であり、detach しない。二重起動は
`app.requestSingleInstanceLock()` が止める。

**実装で変えた（設計時の前提が誤っていた）。** ここには当初「エンジンが 2 台に
なる道が構造上無くなるので、ロックファイルも名簿も要らない」と書いていた。誤り
だった——**起こし手はアプリだけではない。** 端末で裸の `sshc` を打てば、そこにも
エンジンが 1 台上がる（usage の 1 行目がその使い方を勧めている）。Electron の
ロックが数えるのは外殻であって、エンジンではない。

そこで `~/.ssh/sshc/engine.lock` を残した。エンジンは起動から終了まで `flock` を
握り、握れなかった側はエンジンにならない。**握れなかった側がどうするかは、誰が
打ったかで違う。**

- 端末で打った人 … 走っている方の入口を 1 行出して 0 で終わる。「入口が出る」
  という自然な結果であり、handoff を上書きする 2 台目はどこにも生まれない
- 外殻が起こした子（`--own-engine` 付き） … 入口を出さず、3 で終わる。外殻は
  それを見て**窓を開かずに理由を出す**。他人のエンジンの入口を受け取ると、窓は
  開くのに Cmd+Q でそのエンジンが残る——**決定 2 を守れなくなる**。相乗りより
  断る方を選んだのは、持ち主がひとつであること（決定 1）が、窓がその場で開く
  ことより重いからである

名簿は要らないままである。**2 台目が生まれないなら、数える物が無い。**

**2. 生死の規則は 3 行である。**

- **窓を閉じてもアプリは残る。** `window-all-closed → app.quit()` を撤回する。
  メニューバーの項目がその意味である
- **Cmd+Q でアプリが終わり、エンジンも終わる。** 開いているコンソールがあれば
  本数を出して一度だけ確認する——SSH のセッションは閉じたら戻らない
- **アプリが異常終了してもエンジンは残らない。** 子側で親を見張り、親が居なく
  なったら自分で終わる。見張り方は `os.Getppid()` を 1 秒ごとに読み、**起動時と
  変わったら**畳む。通常経路では親が `kill` するので、これは SIGKILL やクラッシュ
  のための最後の網である

  **実装で変えた（設計時の前提が誤っていた）。** ここには当初「1 になったら
  畳む」と書いていた。誤りだった——**引き取り手は init とは限らない。** Linux で
  `systemd --user` が child subreaper を立てていれば、孤児の ppid はそちらの pid に
  なり、1 にはならない。そこでこの網は静かに効かなくなる。「起動時と変わった」は
  どちらの引き取り手でも等しく真である（`cmd/sshc/watch.go`）

「ウィンドウを閉じたあとも動かし続ける」設定は消える。**メニューバーに居ること
がそれそのものである。**

**3. ログイン時起動は OS に任せる。**

普通のアプリになるなら、利用者は Dock アイコンを右クリック →「オプション」→
「ログイン時に開く」で登録できる。**このアプリケーションが plist を書く理由が
無くなる。**

`internal/platform` のログイン項目、`sshc service` サブコマンド、設定画面の
トグル、そして `KeepAlive` をどう書くべきかという問い自体が、まとめて消える。

**4. 端末からの経路。**

```
sshc <接続先>
  handoff を読む → エンジンが答える？
    答える  → 使う
    答えない → アプリを隠しで起こす
               （macOS: open -g -b com.github.aida0710.sshc --args --hidden）
               → handoff が書かれるまで待つ
    起こせない（開発中の electron .、束が無い、GUI が無い）
             → 保存済みを使わずに繋ぐ
```

束の場所を覚える必要は無い。**bundle ID で起こせば、どこにあるかは
LaunchServices が知っている。** 一度も起動していない機械では失敗し、そのときは
最後の道へ退く——これは今日の既定（「動かし続ける」オフ）と同じ振る舞いであり、
接続そのものは常にできる。

`--hidden` は「窓を作らずに ready を終える」という意味だけを持つ。メニュー
バーの項目はいつもどおり出るので、**上がったことは見える。**

**5. マスターパスワードは端末でも答えられる。**

施錠されていたら、`sshc <接続先>` が端末で聞く。`POST /cli/unlock` を足し、
handoff の秘密で認可する。**解錠はエンジンの中に残るので、あとで窓を開けば
解錠済みである。**

- 間違えたら、その場で聞き直さない。**保存済み無しで繋ぐ**——繋げることの方が
  強い要求であり、誤りの遅延（Argon2id、最大 4 秒）を端末で待たせる価値が無い
- 「今は要らない」の入口は**空のまま Enter だけ**である。Ctrl-C は ssh・sudo・
  git と同じく中断として扱う——`term.ReadPassword` は ISIG を立てたままなので
  SIGINT がそのまま届き、この経路にハンドラは無い。ここだけ特別扱いして
  「Ctrl-C で止まらないコマンド」にする方が、端末の作法から外れて驚きが大きい

秘密の通り道は増えない。マスターパスワードは**いまもブラウザから同じ loopback を
通っている**。`~/.ssh/sshc/cli`（0600）を読める者は既に保存済みパスフレーズを
引き出せるので、**増えるのは「解錠を試せる」ことだけで、それには本人が
マスターパスワードを知っている必要がある。**

**6. 画面の無い機械でエンジンだけを動かす道は無くなる。**

`sshc engine start|stop|quit` と detach を消すので、エンジンはアプリの子として
しか上がらない。**Linux のサーバーで常駐させる使い方は失われる。** `sshc
<接続先>`・`sshc list`・`sshc connect` はどれも画面を必要としないので、端末から
使う道は残る。

**7. アプリは入口をエンジンの標準出力から受け取る。**

`engine start` が消えるので、待つのはアプリ自身になる。**handoff を読みに行くの
ではなく、起こした子の標準出力から入口の行を読む。** 起こした本人だけがその
パイプを持つので、ファイルを経由するより届く先が狭い——README が「あの出力には
有効な bootstrap トークン付きの URL が乗るので、ログの置き場所としては不適切
である」と書いているのは、まさにこの行のことである。

`sshc open`（人が別のブラウザで開くための口）はそのまま残る。起動の経路が
そこを通らなくなるだけである。

## 消えるもの

| 何 | なぜ |
| --- | --- |
| `internal/platform` のログイン項目一式 | OS に任せる |
| `sshc service refresh\|disable` と検査 | 同上 |
| `httpserver.LoginItemController`・API・設定画面・i18n | 同上 |
| `cmd/sshc/detach_{unix,other}.go` | daemon 化しない |
| `sshc engine start\|stop\|quit` | アプリが直接起こす |
| metadata の `Desktop.KeepRunning` と API と設定画面 | メニューバーに居ることがそれ |
| Makefile の `service refresh` と `engine stop` | 起こす物も止める物も無い |

## 足すもの

Tray とテンプレート画像、`--hidden` 起動、`POST /cli/unlock`、親の見張り、
終了時の確認、`requestSingleInstanceLock`、`engine.lock` と `--own-engine`
（決定 1 を参照）。

## 残るもの

handoff（CLI がエンジンを見つける唯一の手段）、`sshc open`、`sshc list`、
`sshc connect` の TUI、`link.js` の relink。

## 検査

- **`POST /cli/unlock`**：正しいパスワードで解錠される、間違いは拒む、handoff の
  秘密が無ければ 403。Go の検査で押さえる
- **親の見張り**：「親が居なくなったか」を答える関数に切り、そこに単体検査を置く
- 消える側は、消える検査がそのまま消える

**押さえないもの**：Tray の見た目、`--hidden` での起動、Cmd+Q の確認ダイアログ。
外殻は今も `link.test.js` しか検査を持たない。**ここに検査を新設する価値より、
手で一度確かめる方が安い**と判断した。

## 落としたもの

- ~~**ロックファイルによる単一インスタンス。** アプリが唯一の起こし手になるなら、
  Electron 側のロックで足りる~~ **取り消した。** アプリは唯一の起こし手ではない
  （決定 1 を参照）。`engine.lock` は残っている
- **エンジンの一覧を出す `engine status`。** 2 台目が生まれないなら、数える物が無い
- **ログイン項目の移行コード。** 配布前なので、開発機は手で外す
