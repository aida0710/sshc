# 生体認証で保管庫を開ける (1) — 骨組みと macOS

起動のたびにマスターパスワードを打つ。それは正しい既定だが、**指紋の読み取り機が
付いている機械で、それしか道が無い理由は無い。**

## 生体認証は鍵ではない

先にここを固めておく。**指紋は本人確認であって、鍵ではない。** 指紋から鍵は
出てこないし、出てきてはならない。できるのは、**OS の錠前に秘密を預け、その錠前を
開ける条件として生体を要求する**ことだけである。

したがってこの機能が本当に足すのは、暗号ではなく**依存**である。有効にした時点で、
その端末の保管庫の秘密は「マスターパスワードを知っていること」だけでなく、
「**その OS の錠前が破られていないこと**」にも依存するようになる。だから既定は
off であり、画面はそれを黙って有効にしない。

## 4 つの OS は横並びにならない

| OS | 鍵を預けられる錠前 | 生体そのものが条件になるか |
|---|---|---|
| macOS | Keychain（`SecAccessControl` + Secure Enclave） | **なる** |
| Android | Keystore（`setUserAuthenticationRequired`） | **なる** |
| Windows | Hello（`KeyCredentialManager`） | なる。ただし**プロンプトに HWND が要る** |
| Linux | 無い | **ならない**。keyring の番人はログインセッションであって指紋ではない |

**Linux は対象外にする。** gnome-keyring に置けば体験は揃うが、それは
「守れないものを守れるふりをする」ことである。画面は「この端末では使えない」と言う。

## 誰がどこを持つか

**engine は扉を 1 つしか持たない。** 保管庫を開ける道は今も昔も「鍵を持っていること」
であり、生体はその鍵をどこから持ってくるかの話でしかない。

```
                    ┌── macOS: engine が cgo で Keychain を叩く（cgo は darwin で既に有効）
番人 (Guardian) ────┼── Android: MainActivity が BiometricPrompt と Keystore を持つ
                    └── Windows: 外殻が Hello を出す（HWND を持っているのは窓だけ）
```

`desktop/preload.js` は意図的に空である——「レンダラーはブラウザで動く web と
同一」という約束があるので、**画面から Electron の API は呼べない**。番人が外殻側に
居る OS では、外殻が生体を通してから、既にある handoff 認証の扉
（`POST /cli/vault/unlock`）の隣を叩く。

### 番人の輪郭

```go
// Guardian は、OS の錠前である。**鍵そのものは知らない。**
type Guardian interface {
    // Available は、この端末にその錠前があるかを答える。
    Available() bool
    // Keep は、預ける。以後、取り出すには生体が要る。
    Keep(secret []byte) error
    // Reveal は、生体を通してから返す。人が断れば ErrRefused。
    Reveal() ([]byte, error)
    // Forget は、預かりを解く。
    Forget() error
}
```

## 何を預けるか — **マスターパスワードは預けない**

預けるのは、**その端末でだけ意味を持つ 32 バイトの乱数**（以下 S）である。

```
secrets            マスターパスワードから導いた鍵で封をした保管庫（今まで通り）
secrets.biometric  その鍵そのものを、S の下で封じたもの   ← 足すのはこれだけ
OS の錠前          S                                      ← 生体で守られる
```

- **保管庫の鍵は engine から出ない。** 出るのは S だけで、S は他のどこでも何の
  意味も持たない。
- **人が決めた文字列を預けない。** マスターパスワードを預ければ、その錠前が破れた
  日に失うのは、この保管庫だけでなく、その人がそれを使い回している全部になる。

`envelope` に足すのは 2 つだけである。

```go
// FromSecret は、すでに鍵の強さを持つ 32 バイトを鍵にする。**KDF を通さない。**
// 人が決めた文字列を渡してはならない——乱数として作られた秘密のためだけにある。
func FromSecret(secret []byte) (Key, error)

// Wrap は、この鍵そのものを別の鍵の下に封じる。Unwrap はその鏡像である。
func (k Key) Wrap(under Key) ([]byte, error)
func Unwrap(sealed []byte, under Key) (Key, error)
```

`material` は今まで通り外へ出さない。出るのは封じられた形だけである。

## 流れ

**有効にする**（保管庫が開いている必要がある）

1. 32 バイトの乱数 S を作る。
2. いま持っている保管庫の鍵を S の下に封じ、`sshc/secrets.biometric` へ書く。
3. `guardian.Keep(S)`。ここで OS が「今後は指紋が要る」錠前を作る。
4. S をメモリから消す。

**起動時に開ける**（自動。保管庫が閉じていて、預けてあるときだけ）

1. `sshc/secrets.biometric` を読む。無ければ何もしない。
2. `guardian.Reveal()` → **ここで OS のプロンプトが出る。**
3. 返ってきた S で封を解き、保管庫の鍵を得て、開ける。
4. 断られた・失敗した・錠前が無効になっていた → **黙ってパスワードの画面に戻る。**

**無効にする** — ファイルを消し、`Forget()` する。どちらが先に落ちても、残った方は
次の起動で「片方しか無い」として捨てられる。

**マスターパスワードを変えたとき** — 鍵が変わるので、`secrets.biometric` は開かなく
なる。**その場で消して `Forget()` する。** 画面は「もう一度有効にしてください」と
言う。黙って残せば、次の起動で理由の分からない失敗になる。

**指紋を足された/変えられたとき** — macOS の `biometryCurrentSet` と Android の
`setInvalidatedByBiometricEnrollment` が預かりを無効にする。**これは仕様である**
——登録した指と違う指で開いてはならない。パスワードに戻る。

## API

| 追加 | 何をするか |
|---|---|
| `GET /api/v1/passwords` に `biometric: {available, enabled}` | 画面が出す/出さないを決める。**値は何も返さない。** |
| `POST /api/v1/passwords/biometric` | 有効にする。保管庫が開いていること。 |
| `DELETE /api/v1/passwords/biometric` | 無効にする。 |
| `POST /api/v1/passwords/unlock-biometric` | 開ける。**解錠前に通る扉なので、`security.go` の allowlist に載る。** |

allowlist に載せるものが 1 つ増えることは、それ自体が判断である。この扉は本文を
取らず、成功しても返すのは保管庫の状態だけで、失敗の理由は「断られた」「使えない」
「預かりが無い」の 3 つに畳む。**どの指紋が違ったかも、錠前の中身も、外へ出さない。**

## 画面

- 解錠の画面: 預けてあるなら、**開いた瞬間に自動でプロンプトを出す**。断られたら
  パスワードの欄に戻り、「指紋で開く」を押せば何度でも試せる。
- Secrets の画面: 「この端末で指紋を使う」トグル。**off が既定。** 有効にするときは、
  何が起きるか——秘密がこの端末の OS の錠前にも依存すること——を 1 文で言う。
- Linux と、読み取り機の無い端末: トグルを出さない。**押せないものを見せない。**

## テスト

**Go**

- 有効化が S を預け、`secrets.biometric` を書き、**保管庫の鍵をどこにも出さない**こと。
- 預けた S で開けること。**違う S では開かないこと。**
- 断られた（`ErrRefused`）ときに、保管庫が閉じたままで、パスワードの道が生きていること。
- マスターパスワードの変更が、預かりとファイルの両方を消すこと。
- ファイルだけ在って錠前が空のとき、預かりを捨てて閉じたままにすること（その逆も）。
- 番人は差し替え可能な interface なので、ここまで全部**本物の Keychain 無しで**回る。

**macOS（手で確かめる）**

`docs/manual-acceptance.md` に足す。Touch ID のプロンプトが出ること、断ると
パスワードへ戻ること、指紋を足すと預かりが無効になること。**自動化しない**——
生体のプロンプトは、人が居ることを確かめる仕掛けである。

## スコープ外（次のサブプロジェクト）

- **Android**（サブ 2）。`androidx.biometric` と Keystore、`MainActivity` が番人になる。
  engine が同じプロセスに居るので、mobile bind に口を 1 つ足す。
- **Windows**（サブ 3）。Hello のプロンプトには HWND が要り、それを持っているのは
  Electron の窓だけである。外殻に番人を置き、handoff の扉から engine へ渡す。
- 生体で**個々の秘密**（鍵のパスフレーズなど）を守ること。ここで守るのは保管庫の扉
  だけである。
