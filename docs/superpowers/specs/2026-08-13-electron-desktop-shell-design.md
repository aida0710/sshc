# Electron のデスクトップ外殻

## 目的

`sshc` を、既定ブラウザのタブではなく、自分のウィンドウとアイコンを持つ
アプリケーションとして開く。**入り口をひとつにする。**

## この spec の範囲

外殻と、そのために Go 側へ足すもの。設定エンジン、埋め込みターミナル、vault、
同期のいずれにも触れない。

Windows は対象外である（Go 側がまだ `GOOS=windows` でビルドできない）。

## 決定事項

**1. アプリが唯一の入り口になる。ブラウザ経路は落とす。**

`sshc open` は既定ブラウザではなくアプリを開く。**二つの入り口を保守しない**
——同じ画面へ二通りの道があると、CSP も session も bootstrap も、両方で
確かめ続けることになる。

落とすものは README に書く。**Electron が動かない環境では画面へ到達できない。**
その環境に残るのは CLI である——`sshc <接続先>`、`sshc list`、`sshc connect`
はどれも画面を必要としない。

**2. エンジンはアプリが起こす。ただし「閉じても動かし続ける」を設定にする。**

| 設定 | アプリを閉じたとき | 何が残るか |
| --- | --- | --- |
| 既定（動かし続けない） | エンジンも止める | 何も残らない |
| 動かし続ける | エンジンは残る | 開いているコンソール、施錠していない vault |

**これは利用者が決めることである。** `tmux` に繋いだままウィンドウを閉じたい人と、
閉じたら全部終わってほしい人の両方がいる。

**動かし続けても永久ではない。** vault には既にアイドルの施錠があるので、
放置されたエンジンはそこで鍵を手放す。**この設定は施錠の話を変えない。**

**3. 二重に起こさない。既に居るなら、そこへ繋ぐ。**

起動のたびに `~/.ssh/sshc/cli`（handoff）を読む。**これは新しい仕掛けではない**
——`sshc <接続先>` が既に同じファイルで走っているエンジンを見つけている。

```
アプリ起動
  ├─ handoff を読む
  │   ├─ 生きている  → その URL へ繋ぐ
  │   └─ 居ない／死んでいる → エンジンを起こし、handoff が書かれるのを待つ
  └─ ウィンドウを開く
```

「生きている」の判定は `POST /cli/engine/health` である。**`/api/v1/health` では
ない**——あれは `/api/` の下にあり、すべての `/api/` 要求は
`Sec-Fetch-Site: same-origin` を要求するので、ブラウザでないものは通れない。
最初はそこへ問いに行き、製品が壊れていた。`/cli/` に置くと handoff の秘密で
認証できるので、**「何かが答えた」ではなく「我々のエンジンが答えた」と言える**
——ポートが別のものに再利用されていても、あちらはこの秘密を知らない。

競争は state ディレクトリのロックで止める。二つのアプリが同時に起動しても、
エンジンはひとつになる。

**4. エンジンは detached で起こす。** そうしないと「動かし続ける」が成立しない
——親が死ぬときに道連れになる。標準出力は捨てる。**あの出力には bootstrap
トークン付きの URL が乗る**ので、ログの置き場所として不適切である（`-open=false`
が既にそう決めている）。

**5. Go バイナリは束に同梱する。** アプリの中の 1 つを使い、`~/.local/bin/sshc`
はそこへの symlink にする。**実体が 1 つになるので版がずれない。**

**6. 枠組みは Electron。** Tauri より大きい（150〜200MB 対 10〜15MB）が、
1 台の macOS から macOS と Linux の両方を作れる。Tauri は Rust を対象ごとに
コンパイルし、Linux では WebKitGTK にリンクするため実質クロスコンパイルでき
ない。Linux で Chromium を同梱する分、ディストリごとの WebKitGTK の版差も
踏まない。

**7. 署名は後で足す。** ad-hoc のまま出す。macOS では初回に右クリック→開くが
要る。`release.yml` に継ぎ目だけ空けておく。

**8. 守りは変えない。** CSRF も session も bootstrap も、この spec では触らない。

CSRF が守っているのは「他のオリジンのページ」ではなく、**cookie がポートに
紐づかないこと**である——`127.0.0.1` はそれ自体が site なので、同じアドレスの
別のポートで動くサーバーがこの cookie を受け取る。**レンダラーが自分の origin
から動かないと言い切れる形にしてから**、別の spec で外す。

## Go 側に足りないもの

**`sshc open --print-url`** — いまの `runOpen` は入り口を貰ってブラウザへ渡し、
**URL を決して表示しない**（有効なトークンを運ぶので端末に残さない）。親が
自分で開く場合は、渡す先が端末ではなくその親である。`-open=false` が
「自動化用の明示的なオプション」として同じことをしている前例に倣う。

**`sshc engine start --detached`** — エンジンを起こして handoff が書かれるまで
待ち、書けたら 0 で抜ける。アプリが「起きるのを待つ」ロジックを持たずに済む
——**待ち方を知っているのは Go 側だけ**である。

**「閉じても動かし続ける」の設定** — metadata の `desktop.keepRunning`。
既存の `embeddedTerminal` の隣に置き、設定画面から切り替える。**外殻はこれを
API から読む**——同じ問いに答えるものを二つ持たない。

**`sshc engine stop`** — 走っているエンジンへ終了を頼む。handoff の秘密で
認証する。`keepRunning` が偽のときにアプリが呼ぶ。

## 構成

```
desktop/                        Electron の一式（新）
  package.json
  main.js                       起動・attach or spawn・quit
  preload.js                    何も足さない。contextIsolation のまま
  build.mjs                     electron-builder の設定
cmd/sshc/engine.go              engine start / stop（新）
cmd/sshc/connect.go             open --print-url
internal/httpserver/engine.go   POST /cli/engine/stop（新）
internal/application/…          desktop.keepRunning
Makefile                        desktop-build
```

**レンダラーは今の web をそのまま読む。** `internal/ui/dist` を束に入れるので
はなく、エンジンが配っているものへ繋ぐ——**画面を配る場所を二つ持たない。**

## エラー処理

| 起きたこと | 何をするか |
| --- | --- |
| handoff が無い | エンジンを起こす |
| handoff はあるが health が答えない | 古い handoff。消してから起こす |
| エンジンが起きない | ウィンドウに理由を出す。**白い画面を見せない** |
| ロックが取れない（他のアプリが起動中） | 少し待って handoff を読み直す |
| `keepRunning` を読めない | **止める側に倒す。** 動かし続けるのは明示的な選択である |

## テスト

Electron 自体の自動テストは置かない。**そこに置けるのは「ウィンドウが開いた」だけで
あり、それは Playwright が既に画面について言っていることの劣化版である。**

代わりに Go 側を検査する。

- `sshc open --print-url` が URL を 1 行だけ出し、他に何も出さないこと
- `sshc engine start` が handoff を書き終えてから抜けること
- `sshc engine stop` が handoff の秘密なしでは効かないこと
- **二つの `engine start` が同時に走ってもエンジンはひとつになること**
- `desktop.keepRunning` が metadata を往復すること

手で確かめることは `docs/manual-acceptance.md` に足す——**ウィンドウが開くこと、閉じて
再び開くと同じコンソールが居ること、設定を切ると居ないこと。**

## README の書き換え

「ブラウザで開く」が「アプリで開く」になる。**失ったもの**（Electron が動かない
環境で画面へ到達できないこと）と、**得たもの**（入り口がひとつになり、閉じても
繋いだままにできること）を両方書く。

## ログイン時起動との関係

**二つの仕組みが同じものの寿命を決めている。** ログイン時起動が有効なら、
launchd／systemd がエンジンを起こし直すので、`keepRunning` を偽にしても
ウィンドウを閉じた直後に戻ってくる。**あちらの方が強い。**

争わせない。`engine quit` は設定どおりに止め、OS が起こし直すならそれでよい。
**設定画面がそれを言う**——黙って効かないより、効かないと言う。
