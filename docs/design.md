# 設計のあらまし

**ここにあるのは「なぜそうしたか」である。** 使い方は [README](../README.md) に、
入れ方は [release-install.md](release-install.md) にある。

境界ごとに、何を引き受け、何を引き受けないかを書いてある。**引き受けないことの
方が多い** ——それが決めごとだからである。

## セキュリティ境界

- HTTP サーバーは IPv4 の `127.0.0.1` だけに bind します。LAN、Tailnet、コンテナ外部など、ネットワークへ公開して安全な設計ではありません。
- このアプリケーションは実際の `~/.ssh` を読み書きし、鍵を作り、**自分の画面の中で端末を開き**、リモートホストへ接続します。それぞれの境界は以下の各節にあります。
- **cookie だけでは何の証明にもなりません。** cookie はポートを区別せず、`SameSite` の「サイト」判定にもポートは入らないため、同じブラウザで `http://127.0.0.1:<別ポート>` を開くと session cookie はそちらへも送られます。そこで、読み取りを含む全ての API 要求に `X-SSHC-CSRF` を要求します。このトークンはページのメモリにしか無く、別ポートへは決して送られません。例外は 3 つです。`POST /api/v1/session/bootstrap`（最初のトークンを発行する当のルートなので、提示できるトークンがまだ存在しません。代わりに `Origin` の完全一致を要求します）、`POST /api/v1/session/renew`（リロード直後はトークンが無く、これがトークンを取り戻す手段そのものであるため）、`GET /api/v1/health`。
- bootstrap、session、CSRF の値をログへ出してはいけません。bootstrap は URL fragment に置き、ブラウザが直ちに履歴から除去します。
- 同一マシン上の悪意あるプロセス、侵害されたブラウザ、ブラウザ拡張から秘密を完全には保護できません。将来の秘密鍵 reveal/copy 機能でも、ブラウザ拡張やローカルのクリップボード監視・履歴ツールに対して秘密は脆弱です。
- UI は埋め込みファイルシステムからのみ配信し、URL を OS ファイルパスへ変換しません。存在しない API は SPA へフォールバックしません。

## SSH config エンジンの境界

- `~/.ssh/config` と `Include` 先を正本として読み書きします。無変更の parse/render は byte-for-byte で一致し、コメント、空行、引用、`key=value`、未知のディレクティブを保持します。
- 解釈できない行は `LineUnstructured` として原文のまま保持し、UI からは Raw 編集だけを許可します。推測による整形や削除は行いません。
- 書き込みは解決済みの `~/.ssh` 配下だけに限定します。`..`、シンボリックリンク、外部パスで書き込み範囲は広がりません。読み取りは `O_NOFOLLOW` を使います。
- `Include` が `~/.ssh` の外を指す場合は、グラフ表示と読み取りのみ許可します。
- `%h` など接続先が決まるまで確定しないトークンは展開せず、`include_unsupported_expansion` として報告します。
- 変更は `~/.ssh/sshc/journal/` に予定を記録し、全ファイルを一時ファイルへ書き出して fsync した後に atomic rename します。中断した場合は `~/.ssh/sshc/backups/<id>/` の世代バックアップから復旧するか、staged 内容で完了させるかを選べます。
- 完了した変更は `~/.ssh/sshc/history/` に記録します。バックアップは自動削除しません。
- 複数ファイルの OS レベル完全 atomic commit は存在しないため、部分適用は隠さず pending として提示します。
- ディレクトリ構成要素の入れ替えに対する time-of-check/time-of-use 競合は best-effort でしか防げません。`O_NOFOLLOW` と構成要素ごとの検査を行いますが、同一ユーザー権限で動作する悪意あるプロセスからは完全には保護できません。
- このエンジンは `/api/v1/config/*` として同一オリジンの HTTP API に公開済みです。境界は次節を参照してください。

## Connections UI とグループの境界

- 起動直後の Home はホスト中心のランチャーです。具体的な alias を検索し、お気に入り、グループ、タグを見ながらコンソールを開けます。Home を表示しただけでは DNS、TCP、SSH のどれも開始せず、「接続」を選んだときだけ埋め込みターミナルが開きます。
- Home は設定上の警告、中断した変更、同期状態を要約しますが、それらの編集機能を複製しません。詳細操作は Connections、Diagnostics、History、Sync の各正本画面へ移動します。

- `~/.ssh/config` と `Include` 先を正本として編集します。フォーム編集、任意キー・値編集、ブロック Raw 編集、ファイル全体 Raw 編集はすべて同じ lossless 構文木を更新し、変更していない行は 1 バイトも書き換えません。
- 保存は必ず「読み込んだ内容」を base として送り、その SHA-256 を precondition にします。外部変更があった場合は書き込まず、三者差分を表示します。
- 保存前に再パースと Include グラフ再解決を行い、新たに壊れた行や新たな Include エラーが生じる変更は拒否します。既に存在していた問題は保存の障害にしません。
- UI 専用情報は `~/.ssh/sshc/metadata.json` に保存します。スキーマバージョン、グループの表示情報（色、メモ、表示順、共通設定）、タグ、色、お気に入り、表示順のみで、鍵本文やパスフレーズは保存しません。**どの Host がどのグループに属するかは metadata に保存しません。ディレクトリがその正本です。**
- Host のコメントは metadata ではなく `Host` 行の直上のコメント行として設定ファイルに書きます。sshc を使わずにファイルを読む人にも残るためです。付随するコメントは `Host` 行の直上に連続するコメント行だけで、空行・ディレクティブ・ファイル先頭で切れます。空行で切るのは、ファイル冒頭の見出しコメントが最初の Host ブロックに取り込まれないようにするためです。
- 旧来の metadata の `note` は廃止しました。コメントが未設定のブロックでは編集欄の初期値として表示され、保存すると設定ファイルへ書き出されて metadata からは消えます。
- Host の識別は「正規化した相対パス + 具体的な主 alias」です。改名は config と metadata を同一トランザクションで更新し、対応先が消えた metadata は推測で付け替えず orphan として再関連付けを求めます。グループはディレクトリなので、グループを変えるとパスが変わり、識別も変わります。移動は config と metadata を同一トランザクションで更新するため、識別が変わっても orphan にはなりません。
- Host ブロックの別ファイルへの移動と、グループディレクトリ間のファイル移動・グループの改名は提供しています。journal 付きの削除・改名プリミティブ（`storage.Move`、`storage.Removal`）はサブシステム4で導入済みで、鍵の trash が実際に使っています。Config Explorer からはディレクトリの作成と削除も行えます。削除は空のもののみで、宣言済みグループは `group_is_declared` として拒否し、Groups 画面へ誘導します（グループの改名・削除は領域・共通設定・metadata・鍵を伴う 1 つのトランザクションで、2 つの画面から呼べると 2 箇所で食い違うためです）。**ディレクトリの改名はまだありません** — 中の各ファイルを指す Include 行の書き換えを、複数ファイル分まとめて 1 つの変更に積む必要があるためです。ディレクトリの作成・削除も journal 付きで、`storage.Request` の `Directories` と `RemoveDirectories` として同じトランザクションに乗ります。空かどうかの判定は「今のディスク」ではなく「このリクエスト適用後のディスク」に対して行うので、同じトランザクションで空にしたディレクトリを同じトランザクションで消せます。グループ改名はディレクトリの rename ではなくファイル単位の move の集合ですが、**空になったディレクトリは同じトランザクションで削除します**（深い方から順に）。この操作が空にしたのではないディレクトリ — 宣言されていないサブディレクトリを抱えている場合など — は触らず、`group_directory_leftover` として報告します。
- グループは `~/.ssh/connections/<group>/` ディレクトリです。`~/.ssh/config` には生成マーカーで囲まれた領域を作り、宣言されたグループごとに `Include connections/<group>/*.conf` を 1 行ずつ、深い子グループから先に並べ、最後に `Include groups.sshc.conf` を置きます。単一のワイルドカードにしないのは、`*` が `/` を跨がないため入れ子グループに届かず、読み込み順が glob の辞書順という偶然に決まってしまうためです。マーカー間の行は次回保存時に置き換えられ、その外側は 1 バイトも変わりません。
- **この領域は最初の `Host`／`Match` 行より上に置きます。** `Include` も他のディレクティブと同じくそれが書かれたブロックに属し、OpenSSH は取り込んだファイルの値をそのブロックが一致したときにしか適用しません（パース自体は常に行うため `-v` には `Reading configuration data` が出ます）。無条件に読まれるのは最初のブロックヘッダより上の行だけなので、宣言はそこにしか置けません。既存の領域が `Host` ブロックの内側にある場合は、その場で置き換えず上へ移動します。結果として、グループのファイルはエントリファイル自身の Host ブロックより先に読まれます。同じ alias を両方に書いた場合はグループ側が勝ちますが、それは位置から推測せず、解決済みグラフが `duplicate_alias` として双方の行を示します。
- グループ名は `connections/` からの相対ディレクトリパスで、親子階層はパスそのものが表します（`work/eu` は `work` の中）。`connections/` 直下に置かれたディレクトリでも、`Include` 行が宣言していなければグループではありません。`group_not_declared` として報告するだけで、勝手に取り込むことはしません。この報告と、宣言済みなのにディレクトリが無い `group_directory_missing` は、`/api/v1/config/overview` に載って Groups 画面に注意として出ます。**Connections 画面には出しません** — どちらも宣言とディスクの食い違いで、あの画面から直せるものではないためです。宣言済みで中身が空の `group_empty` も engine は報告し続けますが、**注意としてはどこにも表示しません**。空のグループは作った直後と最後の接続を出した後の正常な状態で、`Include` が 1 つも一致しなくても OpenSSH は困りません。Groups 画面は各グループの行に「メンバー: なし」と書くので、同じことを琥珀で二度言わないという判断です。グループの共通設定は従来どおり `groups.sshc.conf` に通常の `Host` ブロックとして生成し、子グループを親より先に置きます。
- 鍵は `~/.ssh/keys/<group>/` に置けます。鍵の改名・移動、グループの改名では、Include グラフが到達する範囲の `IdentityFile` と `CertificateFile` の行を同一トランザクションで書き換えます。解決できないパス、`~/.ssh` 外の設定ファイルからの参照、Include が設定として読んでしまう移動先、宣言されていないグループは、いずれも半端に適用せず操作そのものを拒否して理由を返します。
- ワイルドカード、否定パターン、`Match`、alias 重複で単純な継承へ投影できない場合も、**答えそのものは確定します**。それが単純ではないという印だけを添えて出所を表示します。
- Effective タブと Diagnostics タブは、この解決器が決めた値とその出所を出します。`Match exec` と `CanonicalizeHostname` を含む設定については値を出さず、理由を出します。
- **実効値の権威はこのアプリケーション自身です。`ssh -G` には委ねません。** 得たものは、設定を読むのに何も実行しなくてよくなったこと（評価前の確認ダイアログが不要になりました）と、`ssh` が無い環境でも同じ答えを出せることです。失ったものは、OpenSSH 自身の答えを画面から直接確かめられなくなったことと、`Match exec`・`CanonicalizeHostname`・`Match final` を使う設定を解決できなくなったことです。`~/.ssh/config` は正本のまま残るので、それらの設定でも端末から `ssh` で接続できます。
- 既定値を持つのは `HostName`（alias 自身）、`User`（ローカルのアカウント名）、`Port`（`22`）の 3 つだけです。**OpenSSH の既定値表を丸ごと持つことはしません** — 版とビルドで変わるものを追い続ける保守が利用者に何も返さないためです。`IdentityFile` の既定を持たないのはその実測結果で、差分試験が macOS と Linux で違う並びを返しました。書かれていないキーワードは答えません。
- **残っている守りは、それぞれ何から守っているかとセットです。** askpass が消えたいま、いくつかは「まだ要る」ではなく「条件付きで要る」ものになりました。

  | 守り | 何から守るか | いつ要らなくなるか |
  | --- | --- | --- |
  | ループバックの TCP listener | 他の機械から届くこと | 画面と CLI が別経路になったとき |
  | bootstrap トークン | 最初のセッションを、残る場所に置かずに画面へ渡す | 残ります |
  | セッション cookie | どのウィンドウからの要求かを言えないこと | 残ります |
  | CSRF ヘッダー | **cookie がポートに紐づかないこと。** `127.0.0.1` はそれ自体が site なので、同じアドレスの別のポートで動くサーバーがこの cookie を受け取ります。token はページのメモリにあってそこへは渡らないので、漏れた cookie 単体を無価値にします | 画面が自分のものだけになり、そこから他の `127.0.0.1` へ移動できないと言い切れるとき |
  | handoff の秘密 | `/cli/connect` に誰でも来られること | CLI が別経路になったとき |
  | ストリームのチケット | WebSocket のアップグレードにヘッダを付けられないこと | 残ります |
  | 一回限りの action token | 確認から実行までの間に対象が変わること | 残ります |

  **条件を書かずに「まだ要る」とだけ言うと、要らなくなった日に誰も気づきません。**

- API は同一オリジンのみです。CORS は有効化せず、**全ての `/api/` 要求が**（読み取りも含めて）`X-SSHC-CSRF` header を要求し、`/api/` 応答は `Cache-Control: no-store` を返します。エラー応答は安定コードと位置情報のみを含み、設定本文は返しません（利用者が解決すべき競合差分を除く）。

## 見た目の境界

- 外観はライトとダークの 2 つで、既定は OS に従います。ヘッダーの「外観」で上書きでき、選択は `localStorage` の `sshc.theme` に記録します。三択（システム／ライト／ダーク）なのは、二択だと OS 設定から出られても戻れないためです。ブラウザの永続ストレージへ書くのはこれと `sshc.language` の 2 つだけで、`e2e/bootstrap.spec.ts` がその 2 つ以外が現れたら落ちる allowlist で守っています。
- 色は 20 個のトークンとして `web/src/index.css` に 1 テーマにつき 1 組ずつ置きます。コンポーネントは `bg-card` のようにトークン名で参照し、`dark:` variant は 1 つも書きません。値の名前は用途であって色ではありません（`card` には別テーマで別の値を与えられますが、`zinc-800` には与えられません）。
- **色は状態のためだけに使います。** accent は**セクションを完了させる操作**に限り、琥珀は注意、赤は失敗と壊す操作、緑はローカルセッションが生きていることを指します。選択されている行やタブに色は付きません。画面に色が付いていれば何か起きている、と読める状態を保ちます。
- accent は画面につき 1 つではなく**セクションにつき 1 つ**です。Sync はバケットの設定とスナップショットの送信という別々の目的を持ち、Keys は鍵の作成・agent への登録・移動・パスフレーズ変更を持ちます。1 つのウィンドウを共有しているだけの別々の目的なので、それぞれを完了させるボタンがそのセクションの accent です。判定は数ではなく結果で行います — **2 つの accent が同じ結果に至ってはいけません。** 実際に起きたとき（ホストにパスワードを与える経路が「保存済みを使う」と「新しく保存する」の 2 つあり、どちらのボタンも「パスワード」としか言っていなかった）、原因は色ではなく言葉でした。2 つを別の操作として名指したことで解決し、色はどちらからも外していません。
- 意図的な例外が 2 つあります。コントロールのフォーカスリングと、チェック済みチェックボックスの印です。どちらも一過性で、どちらも広く定着した慣習で、どちらも「画面が何のためにあるか」ではなく「利用者が今どこにいるか」を指します。
- パレットの規則は `web/src/ui/palette.test.ts` が強制します。Tailwind のパレット名（`text-red-400` 等）、任意値（`text-[#ff0000]`）、inline style の生 hex を走査し、違反をファイルと行番号で名指しして落とします。例外は `palette-exempt` と書いた行だけで、現在の唯一の使用箇所は native の色入力が自前の既定値を必要とする 2 行です。
- **ローカルシェルの開始位置は設定画面で変えられます**（設定画面 →「ターミナル」）。既定は home です。エンジンの作業ディレクトリは継ぎません — あれはエンジンを起こしたものがたまたま居た場所であり（端末から起こせばその作業ディレクトリ、launchd から起こせば `/`）、**利用者はそのどれも選んでいません。** `~/work` と書いた綴りはそのまま保存するので、**home の綴りを焼き付けません** — 別の機械へ持って行っても同じ意味になります。無いディレクトリは保存のときに断ります。保存したあとに消えた場合は home へ倒します — **端末が開けなくなる方が悪い**からです。開始位置は、開けることより弱い要求です。
- **端末で範囲を選ぶと、選択を終えた時点でシステムのクリップボードへコピーします。** 右クリックは貼り付けです。どちらも既定は on で、設定画面 →「ターミナル」から個別に止められ、開いている端末にもすぐ反映されます。右クリック貼り付けと Cmd+V / Ctrl+Shift+V は xterm の paste 経路を通すため、接続先が bracketed paste mode を有効にしていればその印を付けます。**ただし、貼り付ける文字列が安全になるわけではなく、対応しないプログラムでは改行を含む内容がそのまま実行されることがあります。** Cmd+C（macOS 以外は Ctrl+Shift+C）による明示コピーも残します。**素の Ctrl+C はそのまま SIGINT として向こうへ渡します。** xterm の選択はブラウザの選択ではないので、これらは画面側で処理します。
- **開いているコンソールの一覧は一番左のナビゲーションにあります。** `Home`、`Connections`、`Terminal` を上に固定し、その下を「設定」と「ターミナル」のトグルで丸ごと入れ替えます。`Terminal` も同じ固定側にあります。**端末は一画面です** — 接続の一覧の隣ではなく、その代わりに開きます。接続の詳細を端末が覆わないのはこのためです。ターミナルの面から行を選ぶとそこへ連れて行かれるので、戻る道も同じ高さに無いと釣り合いません。「設定」側は従来どおりのセクション一覧です。既定はターミナル側ですが、セッションが 1 本も無ければ設定側から始めます — セッションはプロセスの寿命までしか生きないので、無条件にターミナル側を既定にすると毎回の起動が空の一覧から始まってしまいます。トグルの状態は覚えず、毎回この規則で決まります。
- **コンソールの一覧は状態でグループ分けしません。** 一続きの平らな並びで、行は 2 行です。1 行目が名前、2 行目が「状態 · 行き先」で、種類（ssh / シェル）は書きません — 行き先が `localhost` かどうかがそれを言っています。終了した行も位置を動かしません。ssh が繋がらなかった理由を読める場所はそこしかないので、末尾へ送ると探しにくくなります。
- **行の `···` から、名前の変更・同じ相手にもう 1 本・上下移動ができます。** 並べ替えはドラッグでも行えますが、上下移動をメニューにも置いてあります。既存の drag and drop は矢印キーの経路を持たないので、ドラッグ専用にすると同じ穴を新設することになるからです。名前と並び順は `metadata.json` へ書きません。セッションと一緒に消えます。
- **インスペクタ（右のペイン）を埋めるのは接続とグループの 2 画面です。** 接続では `~/.ssh/config` に書かれるもの（グループ、コメント、alias）が主画面、`metadata.json` にしかないもの（色、タグ、お気に入り、表示順）と注意・継承元が右のインスペクタ。グループでも同じ分け方で、色・表示順・Connections から隠す設定がインスペクタにあり、改名・削除・子グループの追加・共通設定はファイルを書くので主画面に残ります。どちらの画面も**行を選ぶ**とその対象がペインに入ります。残る 8 画面は開閉ボタン自体を出しません — どこでも開けて大半が空のペインは、開ける価値が無いと学習させるためです。
- インスペクタは既定で閉じており、開閉状態はセクションをまたいで保持します。中身に注意がある時だけ開閉ボタンに琥珀の印が付き、その印は読み上げにも「確認が必要な項目があります」として届きます。印が無ければ開ける価値が無いことを意味します。
- インスペクタにキーボードショートカットはありません。macOS の慣習は ⌥⌘I ですが、⌥⌘I は Chromium が開発者ツールとして先に取ります。
- 主ナビゲーションのグループ見出しは見出し要素ではなく `aria-label` 付きのリストです。Playwright はアクセシブル名を既定で部分一致させるため、`鍵とホスト` という見出しがあると `鍵` を指す既存の検索が 2 件に一致して落ちます。見出しの名前空間はパネルのものです。

## 鍵管理の境界

- `~/.ssh` 配下のファイルは内容と権限で分類します。ファイル名だけで秘密鍵と断定しません。`keys/<group>/` 配下も同様に走査します。走査の深さ上限は `~/.ssh` から 8 段（`keys.maxScanDepth`）なので、グループ名は 6 階層までに制限しています。`~/.ssh/sshc/`（backups、trash、journal、history）は走査対象、agent 登録対象、config 候補のいずれからも除外します。
- 通常のソフトウェア鍵（Ed25519、RSA、ECDSA）は Go プロセス内で生成・暗号化します。パスフレーズは argv にも環境変数にも載せません。
- FIDO の `ed25519-sk` と `ecdsa-sk` はハードウェアの操作が必要なため生成しません。実行すべき `ssh-keygen` コマンドだけを表示します。
- **生成できるアルゴリズムの一覧は、このアプリケーションが答えます。** 以前は `ssh -Q key` に「インストール済みの OpenSSH は何に対応しているか」を尋ねていましたが、**それは答えるべき問いではありません** — 画面が並べているのは「ここで生成できる鍵」であり、生成するのは x/crypto です。一覧に載っているものは必ず作れることを `TestEveryInProcessVariantCanActuallyBeGenerated` が検査します。FIDO 鍵だけは `ssh-keygen` が要るので、それが見つかるときだけ載せます。
- パスフレーズ変更は既存の秘密鍵を置き換えます。以前は世代バックアップを作らず（`~/.ssh/sshc/backups/` に鍵本文の複製を残さないため）、その結果として `Rollback` は「復旧できない」と拒否していました。**現在はバックアップを取ります。** 世代バックアップはマスターパスワードで封をするため、平文の鍵が残らなくなったからです。取り消しが最も効く操作でもあります（新しいパスフレーズを打ち間違えると、誰も開けない鍵になるため）。
- 削除は `~/.ssh/sshc/trash/<entry>/` への `rename` です。バイト列を複製せず、元の権限をそのまま保ちます。復元先が埋まっている、または同一 fingerprint の鍵が既に存在する場合は推測せず blocker を提示して拒否します。完全削除はバックアップを取らないため取り消せません。
- 秘密鍵の表示と完全削除は、session cookie と `X-SSHC-CSRF` に加えて一度限りの確認 token（`X-SSHC-Action`）を要求します。token は「確認ダイアログが表示していた内容」の digest に束縛されます。digest はサーバ側で発行時と使用時の両方で計算するため、確認から実行までの間に鍵が差し替わった場合、その token は無効になります。
- **保存済みの答えは、それが答えになる問いにだけ使います。** 秘密鍵のパスフレーズはその接続に選ばれた鍵に、アカウントのパスワードはその alias への password 方式と、keyboard-interactive の「問いがひとつ・画面に出さない」問いに使います。**普通の Linux はパスワードを keyboard-interactive で聞いてくる**ので、そこまで含めないと保存した意味がありません。問いが複数あるもの（2FA）と、答えを画面に出す問いには使いません — それらに対してパスワードは間違った答えです。**保存された答えは古いことがあるので、断られたら人に尋ね直します**（方式ごとに 3 回まで、OpenSSH の `NumberOfPasswordPrompts` と同じ）。同じ答えを二度は送りません。
- **答えを持っていない問いは、握りつぶさず打ち手へ渡します。** 未知のホスト鍵、保存されていない鍵のパスフレーズ、パスワード、2FA は、その接続を開いた端末へそのまま出します。**問いを出す仕組みは 1 つです** — 4 種類の問いはどれも「端末へ書いて端末から読む」という同じことなので、経路を分けていません。答えを端末へ書き戻すことはありません。尋ねる端末が無い経路（認証テスト、公開鍵のリモート登録）では、そもそも尋ねる方式を提示しません。
- **マスターパスワードの誤りは、回を追うごとに遅く答えます**（上限 4 秒）。vault ファイルはコピーしてオフラインで攻撃できるので、中身を守っているのは Argon2id です。これが止めるのは「起動中のアプリに対して、答えられる限りの速さで試す」安い経路だけです。
- **鍵導出は同時に 2 つまでです。** 1 回あたり数十 MiB と複数スレッドを使い、解錠・push・pull がいずれも導出します。上限が無いと、タブが数枚あるだけで数 GB を確保します。
- **リモートから来た封筒には別の上限を使います。** 中のパラメータを決めたのはこちらではないので、見知らぬスナップショットが「パスフレーズが違う」と分かる前に 1 GiB と 16 スレッドを使わせることはできません。
- 秘密鍵の表示応答は `Cache-Control: no-store` で返し、鍵本文はログ行にも history にもエラー応答にも出しません。history には「表示した」という事実と対象パスのみを記録します。
- 画面は表示した鍵本文をコンポーネント状態にのみ保持し、ダイアログを閉じた時点で破棄します。`localStorage`、`sessionStorage`、グローバルオブジェクトのいずれにも書きません。再表示には新しい確認 token が必要です。
- **ssh-agent への登録は `SSH_AUTH_SOCK` の向こうと直接話します。** `ssh-add` は起こしません。鍵の復号はこのプロセスの中で行い、agent が受け取るのは復号済みの鍵です — **外に出る秘密が一つ減りました。** パスフレーズが子プロセスの標準入力を通っていたのは `ssh-add` に読ませる都合であって、プロトコルの要求ではありません。
- パスフレーズを保存するのは、利用者がマスターパスワードを設定した場合だけです。ssh-agent への委譲は従来どおり利用者の明示的な操作で、既定では何も保存しません。保存する場合の境界は次節にまとめます。

## アプリケーションの施錠と秘密の保管庫の境界

- **マスターパスワードを入れるまで、どの画面にも入れません。** 初回起動では設定が初期設定として必須です。`/api/v1` は全て `vault_locked` で拒否します（例外は vault 自身のルート、`GET /api/v1/health`、`POST /api/v1/session/bootstrap`、`POST /api/v1/session/renew` だけ。解錠する前に動く必要があるものです）。ゲートは middleware の 1 箇所なので、後から足したルートが忘れることはできません。`Unlocked` が未設定の server は閉じたままです。
- **保管庫は 12 時間触れられなければ自分で閉じます。どこで走っていても同じです。** 以前はデスクトップだけ時計を外していました。根拠は「engine はアプリの子で、アプリを終えれば道連れに死ぬ」でしたが、**その親が居なくなりました** ——コマンドが engine を起こしてブラウザを開く形では、窓を閉じても engine は生き続けます。忘れられた端末の中で何日も開いたままになりうるなら、それは `sshc engine` と同じ状況であり、そこでは時計が唯一の歯止めです。12 時間は、朝に開いた人が夜まで訊かれず、翌朝には訊かれる長さです。状態の読み取りは「使用」に数えません。開いたタブが 1 つあるだけで開き続けてしまうためです。
- **このゲートは `~/.ssh` を暗号化しません。** config も鍵も OpenSSH が読める場所に平文で置かれたままです。守られるのはこの UI、vault の中身、そして世代バックアップであって、ディスクを持っている相手には効きません。

- 保管庫は `~/.ssh/sshc/secrets` の 1 ファイルです。AES-256-GCM で封をし、鍵はマスターパスワードから Argon2id で導出します。マスターパスワードそのものは保存も送信もせず、復旧手段もありません。忘れた場合、中身は失われます。トレードオフとしてこれを選んでいます。復旧できる保管庫とは、利用者以外にも開ける経路がある保管庫だからです。
- 名前空間は 2 つで、混ざりません。**アカウントのパスワード**（リモートホストへログインするための秘密）と**鍵のパスフレーズ**（ローカルの秘密鍵を開くための秘密）です。ファイル形式、API、画面のいずれでも片方の名前がもう片方の選択肢に現れることはありません。取り違えると、鍵のパスフレーズを次の接続でリモートホストへログインパスワードとして送ることになるためです。
- 秘密には名前を付け、複数のホストや鍵から参照します。値は 1 か所にあるので、更新は 1 回の編集で済みます。まだ参照されている秘密の削除は `credential_in_use` として拒否します。
- API は名前と参照元だけを返し、値は決して返しません。値が読める画面は、侵害されたブラウザから値が読める画面だからです。
- 起動時には何も尋ねません。必要になった画面がその場でマスターパスワードを尋ねます。**解錠した保管庫は、施錠するか engine が終わるか、12 時間触れられなければ閉じます。** 状態の読み取り（画面が開くたびに行う問い合わせ）は「使用」に数えません。開いたタブが 1 つあるだけで保管庫が開き続けることになるためです。
- **世代バックアップは全てマスターパスワードで封をします。** `~/.ssh/sshc/backups/` にあるファイルは、置き換えられた設定ファイルであれ秘密鍵であれ vault 自身であれ、暗号文です。`storage.Manager` には vault ではなく封をする関数だけを渡すので、storage 層は秘密について何も知りません。読み出しは `ReadBackup` の 1 箇所に集約してあり、rollback も履歴からの復元もそこを通ります。
- そのため **rollback と履歴からの復元にはマスターパスワードが要ります**。アプリケーション自体がその後ろにあるので、実際には常に開いています。
- スナップショットは 1 つの固定キー（既定でバケット直下の `workspace.tar.gz.enc`、`path` を設定すればその下）に条件付きで書き込みます。名前が中身を言います。封筒の中は tar.gz で、オブジェクト自体は暗号文です。**固定キーは安全装置です**: `If-None-Match: *`（初回）と `If-Match: <前回の ETag>`（以降）という条件付き書き込みだけが、他マシンの push を黙って上書きしないことを保証しており、それには条件を掛ける対象が 1 つ必要です。日付付きの名前にすると、その保証が消えます。
- push のたびに `snapshots/YYYY-MM-DD-HHMMSS.tar.gz.enc` へ日付付きのコピーも置きます。コピーは先に書き、その後でライブオブジェクトを条件付きで書くので、失敗しても中途半端な状態になりません。**このコピーは無制限に積み上がります**。しかも古いスナップショットには、あとで更新・削除した鍵が入ったままです。バケットの資格情報が漏れたときの被害範囲が時間とともに縮まらなくなるので、`snapshots/` を期限切れにするライフサイクルルールを設定してください。これはバケット側の仕事で、このアプリケーションは消しません。
- S3 の資格情報は同じマスターパスワードで `~/.ssh/sshc/sync-settings` に封をします。この設定ファイルはスナップショットに載せません。バケットへの鍵がそのバケットの中にあってはならないためです。`remotesync.Collect` は載せるものを列挙する方式で、除外は構成上の帰結です（`TestASnapshotCarriesTheVaultAndNotTheKeyToItsOwnBucket` が守ります）。
- **スナップショットを封じるのはマスターパスワードではなく、同期専用の鍵です。** 既定は生成（120 ビット、Crockford base32 の 24 文字）で、自分で決めることもできます。鍵は同じ設定ファイルの中に住み、平文で出るのは作った応答の中の一度だけです。以前はマスターパスワードそのもので封をしていたので、**端末ごとに違うマスターパスワードを使えず、1 台で変えれば他の全端末が締め出されました**。既存のバケットには `POST /api/v1/sync/rekey` が橋を架けます（古い鍵で開き、読んだ ETag を条件に封じ直す。ワークスペースには触れません）。
- **保管庫は封ではなく中身として旅をします。** 出るときにこの端末の封を外し、受け取った端末が自分の封で包み直します（スナップショットの中では `sshc/secrets.json`）。ファイルのまま運べば、受け取った端末は送り主のマスターパスワードでしか開けなくなるからです。アーカイブ自体が同期の鍵で封じられているので、秘密鍵や config と同じ扱いです。何も保存していない保管庫は運びません — 空であることは編集ではないので、2 台目の最初の pull を衝突させません。マニフェストの版はこれで 2 になり、古いビルドは v2 を読まずに断ります。
- **自動同期は、保管庫が開いているあいだだけ 1 分ごとに一巡します。** そして**巡回は保管庫の寿命を延ばしません** — 1 分ごとに設定を読む読み手がアイドルの時計を戻し続ければ、12 時間の自動施錠は永久に来ないからです（status polling を「使用」に数えないのと同じ理屈で、違うのは「誰が尋ねたか」だけです）。期限が来れば保管庫はその場で閉じ、巡回は次に人が解錠するまで止まります。 先に受け取り、それから送ります。動いていないものは取りに行きません（HEAD が ETag だけを返します）。**衝突があるとき、そして適用すれば何かが消えるときは、巡回はそこで止まって待っていると言います** — どちらも人が見るべき分岐です。入切は保管庫の中に残るので、次に起こしたときに黙って再開することはありません。
- **衝突は報告するだけでなく、どちらに寄せるかを選べます。** 「このマシンを残す」は書かないだけで、次の push がこちらを向こうへ運びます。「他のマシンを取る」は置き換えますが、控えが残るので History から戻せます。選んでも書く前に同じプレビューが出ます — 寄せ先は適用ではなく計画を変えます。
- **pull が消すファイルも控えを残します。** 別のマシンで消えたという理由でこのディスクのファイルが消えるとき、押した人はその中身を見たことすら無いかもしれません。そして削除を含む pull は、どこへ控えが行くかを名指しした一文に同意しないと適用できません。

## SSH 実行の境界

- **埋め込みターミナルの SSH 接続は、このプロセスの中で話します。** 外部の `ssh` は起こさず、PTY も確保しません — SSH のチャンネルがそのまま端末です。使う値は上の解決器が決めたもので、設定ファイルを凍結して `ssh -F` に読み直させることもありません。`creack/pty` が要るのはローカルシェルだけになりました。
- **接続のために `ssh` を起こすことはもうありません。** 埋め込みターミナル、`sshc <接続先>`、認証テスト、公開鍵のリモート登録、ホスト鍵の取得 — すべてこのプロセスの中で SSH を話します（利用者が `ProxyCommand` を書いていれば、その綴りは起こします。下に別項があります）。`SSH_ASKPASS` の一式は、それに伴って丸ごと削除しました（ヘルパー、`/askpass` エンドポイント、ワンタイムトークン、プロンプト文字列の照合、環境から 5 変数を取り除く処理）。**あれは OpenSSH がパスフレーズを尋ねる相手を別のプログラムとしてしか指定できないから存在していました。**
- **ProxyCommand は起こします。これは判断を一度ひっくり返した結果です。**

  かつては断っていました。「このアプリケーションは接続のために何も実行しない」という判断で、根拠は「`~/.ssh/config` は正本のまま残るのだから、その人は端末から `ssh` で繋げばよい」という逃げ道でした。

  **その逃げ道は、この道具を使う理由そのものを削っていました。** `cloudflared access ssh`、`aws ssm start-session`、会社の bastion helper —— ProxyCommand を書いている接続先は珍しくありません。それらが一覧に並んでいるのに押すと断られるなら、その人にとってこれは「半分の接続先しか扱えないもの」です。しかも一覧はどれが繋がるかを言わないので、押すまで分かりませんでした。

  **いま起こします。ただし黙っては起こしません。**

  - 起こす綴りは、接続のたびに端末へ 1 行出ます（`[sshc] ProxyCommand を起こします: ...`）。**既定が無言であることの、ただ一つの例外です** — 何が走るかを知らないまま走ることはありませんし、繋がるまで数秒かかる理由もそこにあります
  - 走らせるのは利用者自身の `~/.ssh/config` に書かれた綴りだけです。`ssh` が読むのと同じ 1 行を、`ssh` と同じ規則で解釈します（`%h` `%p` `%r` `%n` の展開、POSIX では `/bin/sh -c "exec ..."`、Windows では `cmd.exe /c`）
  - **`$SHELL` は読みません。** OpenSSH はそれを見てから `/bin/sh` へ落ちますが、あちらは利用者の端末から起きたプロセスです。このエンジンは tmux の中にも systemd の下にも居るので、そこの `$SHELL` は supervisor がたまたま持っていた値です。読めば、同じ設定が「エンジンをどう起こしたか」で違う振る舞いをします
  - **`ProxyJump` と一緒には書けません。** どちらも「どうやって届くか」を決めるので、両方書いた人は二つの違う答えを書いています。`ssh` も断ります（`inconsistent options: ProxyCommand+ProxyJump`）
  - **踏み台の向こうのホップは ProxyCommand を使えません。** そのプログラムはこの機械で走るのであって、手前のホップの中ではありません。走らせても設定が言っている場所には届かないので、断って理由を書きます
  - プログラムが標準エラーへ書いたものは、繋がらなかったときの理由に添えます。`ssh -W` の "Connection refused" はそこにしかありません
  - 接続が終わればプログラムも終わります。パイプを閉じて 2 秒待ち、それでも残っていれば強制します

  **プログラムを起こす場所は数えてあります。** `internal/acceptance` の `TestOnlyTheNamedSubsystemsStartAProgram` が一覧を持っており、`internal/sshclient/proxycommand.go` はそこへ理由と一緒に足した 4 つ目です。

- **このアプリケーションが自分の判断で起こす OpenSSH のプログラムはありません。** 例外は ProxyCommand ひとつで、下に別項があります。`ssh-keygen` は名前を出すだけで、走らせるのは利用者です — ハードウェア鍵の画面が表示する引数の並びであり、`Toolchain.KeyGen()` を呼ぶのは「その項目を一覧に出してよいか」を決めるためだけです。agent への登録は `x/crypto/ssh/agent` で直接行い、生成できるアルゴリズムの一覧はこのアプリケーション自身が答えます。
- **外部プログラムを起こす継ぎ目（`RunOutput`）そのものを削除しました。** ログイン項目を OS に任せたことで `launchctl` / `systemctl` を起こしていた最後の場所が消え、継ぎ目は本番のどこからも呼ばれないまま残っていたためです。**Go 側でプログラムを起こす場所は 3 つあり、いずれも `os/exec` を直接呼びます**: 入口をブラウザへ渡す `cmd/sshc/browser.go`（起こしたら手を離すので、出力を集める継ぎ目を通す必要がありません）、ローカルシェルの PTY を確保する `internal/terminal/pty_unix.go`、そして配布物に載らないビルド CLI の `internal/nativebuild/nativebuild.go`。`internal/acceptance` の `TestOnlyTheNamedSubsystemsStartAProgram` はその全部を一覧として固定しており、**探すのは `exec.Command` です** — 継ぎ目を通らない起こし方こそ気づきたいものだからです（実際、探し方が `RunOutput` だけだったとき、新しい起動が 1 つ素通りしました）。**一覧を持つ形にしているのは、増えたときに気づくためです** — 「OpenSSH が無いこと」を検査すると、OpenSSH でない何かが増えても緑のままになります。**見張りが歩くのは `.go` だけです。** かつては外殻の JavaScript も同じアプリがプログラムを起こす場所でしたが、外殻ごと無くなったので、いまはこの一覧が全部です。
- **落とした機能は、黙って無視せず理由を添えて注意を出します。** `RemoteForward`（相手に listen させる。信頼の向きが逆で、サーバー側の `AllowTcpForwarding` に依存します）、`ForwardX11`（X サーバーがこのプロセスの向こうにありません）、`ControlMaster` / `ControlPath`（プロセス内では意味がありません。接続の再利用は既に持っている `ssh.Client` を使い回すだけです）、`SendEnv`（送る値がこのアプリケーションの環境変数であって利用者のシェルのものではないので、間違った値を送るくらいなら送りません）、`CertificateFile`（証明書を配る組織は、その配布と一緒に `ssh` も配っています）、`LocalCommand`（繋いだ**あと**に手元で何かを走らせる設定で、これは起こしません）。
- **ポート転送（`LocalForward` / `DynamicForward`）と agent 転送（`ForwardAgent`）は動きます。開いているものはコンソールの一覧に出ます。** 転送はこのマシンにポートを開くので、開いていることが見えないまま開きません。`ssh -L` を打った人はそれを覚えていますが、設定ファイルに書いてある転送は接続するたびに黙って開くためです。
- **bind するのはループバックだけです。** `LocalForward 0.0.0.0:8080` や `GatewayPorts yes` で他の機械へ開くことはしません — 常駐するプロセスが同じ機械の他の面（HTTP サーバー、vault）をループバックに閉じているのと同じ判断です。それ以外が書かれていたら束ねて注意を出します。**開けなかった転送があっても接続は続きます** — ポートが埋まっているのは普通の出来事で、それを理由にコンソールごと失う方が困ります。理由は一覧のその行に出ます。
- 転送はセッションの寿命に縛られます。コンソールを閉じれば listener も閉じます — 閉じ忘れたポートは、そのプロセスが死ぬまで埋まるためです。`DynamicForward` は SOCKS5 の CONNECT だけを話します。**agent 転送は鍵そのものを渡しません。渡るのは鍵を使う権利です。**
- 接続の途中で人に尋ねることは 4 つあります（未知のホスト鍵、鍵のパスフレーズ、パスワード、keyboard-interactive）。**保管庫が答えを持っている問いは尋ねません**が、持っていない問いと、保存された答えが断られた後は尋ねます。**どれも同じ橋渡しで端末へ出します。** 答えは端末へ書き戻しません — 書けば画面にもスクロールバックにも残ります。尋ねた鍵のパスフレーズは保存しません。保存は Secrets 画面の仕事です。
- **ホスト鍵が `known_hosts` と食い違ったら必ず断ります。尋ねません。** 尋ねること自体が中間者攻撃の成立条件になるためです。未知のホストは `StrictHostKeyChecking` に従い、受け入れた鍵は Known Hosts 画面と同じトランザクションで書きます。読むパーサーも 1 つです。
- **`ProxyJump` はプロセス内で辿り、`ProxyCommand` は断ります。** 前者は SSH のチャンネルの上に次の接続を載せるだけですが、後者はプログラムを起こします。断られた設定でも `~/.ssh/config` は正本のまま残るので、端末から `ssh` で繋げます。
- **接続できなかった理由は、そのコンソールの中に残します。** 設定そのものが接続を許さない場合（`ProxyCommand`、`Match exec`、解決不能）はセッションを作らずに名前の付いた理由を返します。届かない・認証が通らないといった接続の出来事は、開いたセッションの中でしか語れません。
- 外部プロセスは argv を直接組み立てて実行します。シェル、`sh -c`、文字列連結した AppleScript は使いません。alias、hostname、user は OpenSSH が受理する値であっても信頼しません。
- `Match exec`、`ProxyCommand`、`KnownHostsCommand`、`LocalCommand`、`RemoteCommand` を危険ディレクティブとして構文木から検出し、実際のコマンド文字列を表示します。**設定を読むだけで何かが走ることはありません** — 実効値を決めるのはこのアプリケーション自身で、外部プロセスは起こしません。ゲートが要るのは接続だけです。検出したディレクティブは必ず全て表示します。
- OpenSSH は展開したトークンをシェル向けにエスケープしません。hostname や user の値がそのまま危険ディレクティブのシェルへ届きます。UI と API はこの警告を必ず添えます。
- 接続テスト、`known_hosts` 変更、ホスト鍵の取得、公開鍵のリモート登録は、CSRF header に加えて、対象と操作種別と表示済みコマンドへ紐付いた一回限りの action token（`X-SSHC-Action`）を必要とします。digest はサーバ側で発行時と使用時の両方で計算するため、確認から実行までの間に設定を編集すると token は無効になります。
- 値の出所（provenance）は必ず実在するファイルと行を指します。ワイルドカード、否定パターン、`Match` ブロック、別名の重複などで単純に説明できない場合は「単純ではない」と印を付けます。**印を付けても答えは出します** — 権威はこのアプリケーション自身です。出所を推測して捏造することはありません。
- 到達性チェックは宛先を直接 dial します。`ProxyJump` と `ProxyCommand` は使いません。結果には必ずその旨を表示します。踏み台越しにしか到達できないホストがここで失敗するのは想定どおりです。
- 認証テストはタイムアウトとキャンセルを持ち、出力を上限つきで取得し、forwarding と `LocalCommand` をコマンドライン優先設定で無効化します。無効化できない実行可能ディレクティブが残る場合は、その内容を確認するまで開始しません。
## 画面の境界

- **画面を配るのはエンジンです。** `sshc engine` が HTTP で web を配り、`sshc` がその入口をひとつ刷ってブラウザへ渡します。**画面を配る場所は一つです** — 束の中に別のコピーを持ちません。
- **エンジンを生かしておくのは人です。** `sshc engine` は前面で走り続けます。tmux でも screen でも systemd でも、その計算機でプロセスを持つ作法に任せます。**このアプリケーションは detach しません** — 起こした端末を閉じればエンジンも終わります。それが「止め方が一つである」と言えることの実装そのものです。
- **裸の `sshc` はエンジンを起こしません。** 走っているものへ入口を求めて刷るだけです。居なければ、起こし方（`sshc engine`）を出して 1 で終わります。**二台目は上がりません** — `~/.ssh/sshc/engine.lock` を起動から終了まで握り、握れなかった方は入口の取り方を出して終わります。状態を尋ねてから起こす形にしないのは、同時に打たれた二つが両方「居ない」と読む隙があるからで、そこは構造で塞ぐしかありません。
- **入口は求めるたびに新しく発行されます。** エンジンは起動時にそれを刷りません — 刷れば、エンジンが走っているあいだずっと使えるワンタイムの資格情報が、端末のスクロールバックとログに残ります。
- **ブラウザは開けなくても構いません。** `sshc` は URL を標準出力へ出したうえで、画面のある計算機ならそれを既定のブラウザへ渡します。画面が無ければ渡す先が無いだけで、貼れる綴りは手元に残ります。`sshc open` は渡さずに刷るだけで、書かれた手順の中から呼ぶためのものです。
- **「接続をすべて閉じる」は設定画面にあります**（設定画面 →「開いている接続」）。開いているコンソールと、そのポート転送と、リモートへ貸している agent が一緒に終わります。**エンジンは止めません** — ここが引き受けるのは「繋ぎっぱなしを片付けたい」という用です。取り消しは開き直すことなので、確認は挟みません。
- **エンジンを止めるのは、それを走らせている端末です。** Ctrl-C か SIGTERM で、開いているコンソールも転送も vault も畳んでからロックを外します。
- **cookie はポートに紐づきません。** 同じ `127.0.0.1` の別ポートに居るサーバーがこの session の cookie を受け取りうるので、読み取りにも CSRF トークンを要求します。トークンはページのメモリにあり、そこへは渡りません。
- **デスクトップの束はもうありません。** 配るのは CLI ひとつです（`sshc-<OS>-<アーキ>`）。署名も公証もインストーラも要らず、`curl` で落として `chmod +x` すれば動きます — 隔離の印を付けるのはブラウザ経由のダウンロードなので、そこで止められることもありません。Homebrew の formula はソースから建てます。
- **画面付きのアプリは Android だけです。** あちらは配布の口がストアしかなく、WebView に入口を渡す仕組みも別に要ります。デスクトップでそれを抱える理由は、署名の手間に見合いませんでした。**iOS はやめました** — 外殻も CI も検査も無いまま `ios-bind` という的だけが残っており、壊れても誰も気づけない状態でした。エンジン側（`mobile`）は iOS を知ったままですが、それは gomobile が iOS を対象に取れるという事実であって、出荷する約束ではありません。

## 更新の境界

- **このアプリが自分以外のホストへ通信するのは、更新確認のここだけです。** `https://api.github.com/repos/aida0710/sshc/releases/latest` へ 1 回 GET します。要求はサーバー側から出すので、ページの `connect-src` は `'self'` のままで、「他のオリジンへ一切リクエストを出さない」という e2e も成立し続けます。自動では走らず、画面を開いたときだけです。
- **このアプリは自分自身を置き換えません。** 左下は「新しいバージョンがあります」とリリースページへのリンクを出すだけで、ダウンロードも書き換えもしません。判断も操作も人がやります。
- 自己更新は一度入れて、外しました。ネットワークから取ったバイトで自分を置き換える以上、署名で守る必要がありますが、**その鍵はリリース workflow が読める場所に置く必要があり、それはリポジトリを支配できる相手が読める場所**です。守る側と攻める側が同じ鍵を使うことになり、リポジトリ奪取という現実的な脅威に対しては何も足していませんでした。**複雑さと失敗モード（鍵の交換順を誤ると全インストールが静かに更新不能になる）だけが残る**ので、機能ごと落としました。
- **リリースは 4 つのバイナリを出します**（`sshc-darwin-arm64`、`sshc-darwin-amd64`、`sshc-linux-amd64`、`sshc-linux-arm64`）。このプロジェクトは cgo を 1 行も使っていないので、1 台の macOS ランナーから全部作れます。ただし **darwin だけは `CGO_ENABLED=1` のままにします** — 設定エンジンは `%u` と `%i` を展開するために `os/user.Current()` を読み、cgo 無しの Go は代わりに `/etc/passwd` を読むので、macOS の通常のアカウントでは実行時にそのトークンだけが黙って非対応になるためです。Linux は `/etc/passwd` が本物なので `0` で構いません。**Windows と Android はコードとしては対応していますが、リリース成果物にはまだ載せません** — 署名と配布がこれからだからです。Android は `make android-bind` と `android/gradlew assembleDebug` で手元から作れます。
- リリースには `checksums.txt` を併置します。これは**手でダウンロードした人が転送の破損を確認するため**のもので、バイナリと同じ場所から来るので、その場所が正直かどうかについては何も言いません。**このアプリが取ってくるものは何もないので、検証すべきバイトもありません。**
- ソースから使っている場合の更新は `make update`（`git pull --ff-only` + `make install`）です。

- **インストールは `make install`** です。`~/.local/bin/sshc` へ原子的に入れます（sudo 不要）。**`make uninstall` はそのバイナリを削除するだけです。**
- **版が食い違えば、繋がる前に断ります。** `sshc` と、走っているエンジンの版が違うとき、**いま走っているのがどの実体かを綴りで名指しします** — 古いのがどちらかは、このプロセスには分からないためです。
- **エンジンを生かしておくのは人で、その作法は OS に任せています。** `sshc engine` は前面で走り続けるので、`tmux`・`systemd`（利用者 unit）・`launchd` のどれでも、その計算機でプロセスを持つ作法をそのまま使えます。具体的な綴りは [docs/headless-examples.md](headless-examples.md) にあります。**このアプリケーションは unit もスケジュールタスクも書きません。**

  以前は 2 つの別々の仕組みがありました。ひとつは、アプリケーション自身が `~/Library/LaunchAgents/com.github.aida0710.sshc.plist` と `~/.config/systemd/user/sshc.service` を書き、`sshc service refresh` / `disable` という保守用のサブコマンドを持っていたこと。もうひとつは、デスクトップの束を OS の「ログイン項目」に登録して、その外殻がエンジンを子として起こしたことです。**前者は削除し、後者は束ごと消えました。**

  **いま登録する対象は `.app` の束ではなく、`sshc engine` という前面のプロセスです。** ログイン項目は束を開くための仕組みなので、そこに答えはありません——supervisor に渡すのが正しい形であり、**裸の `sshc` を登録してはいけません**（あれはエンジンを起こさず、走っているものへの入口を刷るだけです）。
- **`sshc list` は `~/.ssh/config` と到達できる `Include` を読み、具体的な接続先 alias を辞書順で 1 行ずつ表示します。** `Host *`、ワイルドカード、否定パターンは接続先の名前そのものではないので表示せず、同じ alias は一度だけ表示します。設定を読むだけで、`ssh` や `Match exec` を実行しません。
- **`sshc connect` は現在のターミナル内に検索TUIを開きます。** alias・設定から投影した `HostName`・`User`・`Port`・metadata のタグを絞り込め、お気に入りを先に並べます。上下キーで選び、Enterで同じ端末を `ssh` に引き渡します。Web UIを起動する操作ではなく、既存の `sshc <接続先>` と同じ保存済み鍵パスフレーズ経路を使います。設定が存在するのに読めない場合は、`sshc list` と同じく「読めなかった」と言い、ホストが無いことにはしません。
- TUI の入力は 1 バイトずつではなく端末が届けた読み取り単位で解釈します。`Esc` はそれ自体がキーであり、同時にすべての矢印キーの先頭でもあるため、読み取りの最後のバイトであるときだけキーとして扱います。扱わないキーは終端バイトまで読み捨てます — そうしないと `Delete` や `Ctrl-矢印` の残骸が検索語に入ります。行は端末の幅で切り、収まらなかった件数は「N more」として必ず表示します。
- サブコマンドの一覧は `sshc -h` と `sshc connect --help` に出ます。`open`、`list`、`connect`、`status`、`help` は alias より先に読まれるので、その名前のホストへはこのコマンドからは繋げません。それが usage に書いてある理由です。
- **`sshc <接続先>` でターミナルから直接繋げます。** **このコマンド自身が SSH を話します** — `ssh` は起こしません。起動中の本体が `~/.ssh/sshc/cli`（0600）に URL と、その起動限りの秘密を書き、このコマンドがそれを読んで、保存済みの答えがあれば受け取ります。**返るのは単回トークンではなく答えそのものです** — トークンにしていたのは引き換える相手が別のプログラムだったからで、要求を出した本人が受け取るなら発行と引き換えを分ける理由がありません。**鍵のパスフレーズもアカウントのパスワードも、同じ連鎖ぶんを受け取ります** — 本体が ProxyJump の連鎖を解決し、そこに現れる alias が使う鍵とアカウントのぶんだけを返します（手前に立つホストもそれ自身が alias で、そこに別の鍵が指定されうるので、行き先だけでは連鎖の途中で手入力を求められます）。**鍵は設定の解決器が決めます** — 実行も DNS も伴わずに決められないとき（`Match exec`、`CanonicalizeHostname`）は何も返しません。**尋ねられた接続に現れないものは返しません** — 保管庫の一覧にはしません。答えを持たない問い（2FA、複数の問い）は今までどおり端末で尋ねます。**この応答が運ぶ秘密は一種類増えました。** このファイルを読める相手は既に vault の暗号文も全ての秘密鍵も読め、どの alias についても保存済みパスフレーズを引き出せるので、信頼境界は動きません — ただし動かないことは自明ではないので書いておきます。プロセスが強制終了して残骸が残っても、指す先のポートには誰も居らず、秘密は次の起動で作り直されます。
- **エンジンが起動していなければ、起こし方を出して降ります。** 起こすのはこのコマンドの仕事ではありません（上の「エンジンの持ち主」を参照）。保存済みの答え無しで繋ぎたいなら `ssh <接続先>` があり、このアプリは `~/.ssh/config` に触れないので常に動きます。
- **vault が施錠されていれば、解錠されるのを待ちます。** 解錠は窓でも、別の端末の `sshc vault unlock` でもよく、どちらも同じエンジンを変えるので、待っていた `sshc <接続先>` はそのまま接続へ進みます。**この経路が自分でマスターパスワードを尋ねることはもうありません** — 尋ねるのは `sshc vault unlock` の仕事で、解錠の入口を二つ持つ理由がないからです（かつてここは `/cli/unlock` へ渡していました。その route は削除済みで、`TestLegacyCLIUnlockRouteIsNotRegistered` が 404 を表明しています）。持ち主による違いは上の「エンジンの持ち主」のとおりで、**desktop は窓を一度だけ前へ出して時間の上限を置かずに待ち、headless は待ちません。**
- **接続は外部の端末アプリケーションではなく、このアプリケーションの画面の中で開きます。** 「接続」を押すと常駐プロセスがこのプロセスの中で SSH を話し、生のバイト列を WebSocket で画面へ運びます。描画は xterm.js です。ローカルシェルは PTY を確保して同じ仕組みで開けます。
- **失ったもの。** macOS の利用者は、自分のフォント・tmux の設定・キーバインドを持つ本物の端末を失います。Terminal.app・iTerm2・kitty・Ghostty・WezTerm・「その他のアプリ」を選ぶ設定と、AppleScript とバンドル ID の表（`internal/platform/macos/terminal.go`）は削除しました。**得たもの。** Linux にはこれまで端末起動が存在せず、コマンド文字列を表示して利用者が自分で実行するしかありませんでした。この仕組みが初めてそれを与えます。接続が即座に失敗したときの ssh のメッセージも、ウィンドウごと閉じてしまう端末を心配せずに読めます。
- **ブラウザのタブに任意コード実行が生まれます。** これがこの変更のいちばん大きな代償です。以前は、Terminal を開く操作にワンタイムの action token を要求していました。**埋め込みターミナルはそれを要求しません。** 条件はマスターパスワード（vault ゲート）だけです。したがって、解錠されている間にページを乗っ取れた者は、確認ダイアログを一度も出さずに任意個のシェルを開き、そこで何でも実行できます。これは「新しいゲートを作らなかった」のではなく、**既にあったゲートを外した**という判断です。ゲートを残す設計もありえましたが、端末を一本開くたびに確認を求めるのは、端末という道具の使われ方と噛み合いません。
- **PTY は常駐プロセスの側で生きます。** タブを閉じてもリロードしてもセッションは残り、繋ぎ直すとスクロールバックが再生されます。終わるのは、子プロセスが終了したとき、人が閉じたとき、アプリケーションが終了したときだけです。終了したセッションも一覧に残ります（新しい方から 20 本）。**ssh が接続できなかった理由を読める場所は、そこしかない**からです。
- **スクロールバックはメモリのみで、ディスクへ一切書きません。** 端末の出力には、保存済みパスワードを使った接続の痕跡も、リモートが表示した何もかもが混ざります。世代バックアップも journal も history もリモートスナップショットもこれを受け取りません。`TestTheScrollbackNeverReachesTheStateDirectory` が `~/.ssh` 全体を走査してそれを表明します。1 セッションあたりの上限は既定 256 KiB（16 KiB–4 MiB）、同時に開けるのは既定 50 本（1–200）で、**どちらも設定画面 →「ターミナル」から変えられます**（保存先は `metadata.json` の `embeddedTerminal` です）。**空欄は「設定されていない」であり、既定と同じ値ではありません** — 既定を書き戻すと、既定を変えた日にその人だけが取り残されるので、空欄は書きません。上限に達した状態で開こうとすると `terminal_session_limit` として拒否します。**黙って古いセッションを閉じることはしません。**
- **WebSocket は `/api/` の外（`/terminal/stream`）にあります。** ブラウザは WebSocket のハンドシェイクにカスタムヘッダを付けられないため、`/api/` 配下すべてに `X-SSHC-CSRF` を要求するこのサーバーでは、そこに置いたアップグレードは必ず弾かれます。代わりに、直前の CSRF 付き要求（`POST /api/v1/terminal/sessions`）が発行した**使い捨てのチケット**で認可します。チケットはひとつのセッション ID に束縛され、10 秒で失効し、一度しか使えません。無効・期限切れ・使用済みのいずれも、**アップグレードせずに 403** を返します。アップグレード時には `Origin` の完全一致も確認します。`/cli/connect` が `/api/` の外にあるのと同じ規則です。
- **CSP で緩めたのは `style-src` だけで、それは実測の結果です。** xterm.js は文字の実寸を測ってから、その寸法を持つ規則を `<style>` 要素として差し込み、DOM レンダラーは各セルへ `style` 属性を書きます。nonce を渡す口はありません。したがって `style-src 'self' 'unsafe-inline'` にしています。**`script-src 'self'` と `require-trusted-types-for 'script'` は一文字も緩めていません。** xterm.js の配布物（5.5.0 と 6.0.0 の両方）には `innerHTML`、`insertAdjacentHTML`、`document.write`、`new Function`、`eval`、Worker、blob URL が **0 件**で、Trusted Types に触れる経路がそもそも存在しないためです。失ったものは「HTML を注入できる者は CSS も注入できる」ことで、得たものは端末が描画できることです。前者に必要な注入点をこのアプリケーションは持ちません（React がエスケープし、`dangerouslySetInnerHTML` はどこにもなく、スクリプトは依然として止まります）。`connect-src 'self'` は同一オリジンの `ws://` を許すので変更していません。end-to-end はこの二つを、CSP 違反が 1 件も出ないことで毎回確かめます。
- **プロセス内で SSH を話すのに要るものは `internal/app` が一箇所で組み立てます。** 埋め込みターミナルも `sshc <接続先>` も認証テストも公開鍵のリモート登録も、同じ鍵・同じ `known_hosts`・同じ解決器を使います。二箇所で組み立てると、片方だけが vault を見る日が来ます。
- **ローカルシェルは ssh 接続ではありません。** `localhost` は Home の接続一覧に出しません。あの一覧は `~/.ssh/config` の投影であり、`localhost` はそこに存在しないからです。入口は左ナビのターミナル側にある「ローカルシェル」だけです。シェルは `$SHELL`（絶対パスで、実在し、実行可能な場合のみ）、次に `/bin/zsh`・`/bin/bash`・`/bin/sh` の順に探します。`PATH` は見ません。argv[0] には先頭にハイフンを付けてログインシェルとして起こします。
- 埋め込みターミナルは安全な文字集合の alias に限ります。それ以外は `unsafe_alias` として拒否します。`sshc <alias>` で繋ごうとした場合も、拒否される理由を先に一言添えます。
- **「自分の端末へ貼るためのコマンド」を出す機能はありません。** 以前は `POST /api/v1/terminal/command` がその文字列を返していましたが、外部の端末アプリケーションを起こさなくなった以上、必要なのは `sshc <alias>` と打つことだけです。同じ文字列を画面から配るために API と画面を持つ理由がなくなりました。
- ホスト鍵の取得結果は本人性を証明しません。常に「未検証」と表示し、別経路で取得した fingerprint の一致か、明示的な承認がある場合だけ追加します。
- `known_hosts` の変更は `storage.Manager` を通し、journal と世代バックアップを残します。削除は表示していた行の digest を伴い、ファイルが変化していれば衝突として拒否します。解析は無損失なので、指定された行以外は 1 バイトも変わりません。
- 公開鍵のリモート登録は POSIX shell を持つ環境に限定し、固定のリモート処理へ公開鍵を標準入力で渡します。ユーザー入力をリモートシェル文字列へ補間しません。対応外環境では手順の表示だけを行います。
- 応答に載せる `ssh` の出力は上限つきで、ホームディレクトリのパスを `~` に置換してから返します。利用者のアカウント名を応答本文へ持ち出さないためです。
- 自動テストは実リモートと実 `~/.ssh` を使いません。例外は二つです。一時ディレクトリ内の安全な fixture に対する `ssh -G -F` の差分試験（`ssh` が無い環境では skip）と、`/bin/echo` を本物の PTY で起こす 1 本の検査です。前者は製品が使う経路ではなく、この解決器の答えが本物の OpenSSH と一致することを確かめるためだけに `ssh` を起動します。後者はリモートにもユーザーの設定にも触れません。

## 強化とリリースの境界

- リクエスト本文には二段の上限があります。middleware の `MaxRequestBodyCeiling`（2 MiB）が全 `/api/` 要求の天井で、各ハンドラーはさらに小さい上限を持ちます。宣言された `Content-Length` が天井を超える要求はハンドラーへ届く前に 413 で拒否し、長さを宣言しない chunked 要求は読み取り自体を天井で打ち切ります。本文を読まないルート（`/api/v1/diagnostics/config` や `/api/v1/keys/{keyId}/trash`）にも同じ天井が掛かるのは前者のためです。
- 外部コマンドの出力は `platform.MaxCapturedOutput`（64 KiB）で打ち切られます。認証テストの stderr は `MaxReportedOutput`（8 KiB）までに制限して表示します。
- `make fuzz` は `FUZZ_TARGETS` に列挙した全 target を順に実行します。`go test -fuzz` は一度に 1 target しか動かせないため、1 行で書くと最初の target しか回りません。target を追加して一覧に加え忘れると `TestMakefileFuzzTargetsCoverEveryFuzzFunction` が失敗します。
- fuzz の対象は、設定パーサーのラウンドトリップ、Include パターン展開、`known_hosts` リーダー、実効値の解決、`ssh -G` 出力パーサー、HTTP リクエストデコーダー、リモートスナップショットのリーダーの 7 つです。いずれも実 fixture を seed にしています。
- 入口の URL を出すのは `sshc` と `sshc open` だけで、どちらも求められたときに 1 つずつ発行します。`sshc engine` は入口を出しません。旧版の `--own-engine` と `-open=false` はどちらも未定義であり、別名も互換の受け皿もありません。
- 配布物は UI を埋め込んだ単一バイナリです。`otool -L` はシステムライブラリのみを表示し、同梱ランタイムはありません。`make e2e` は毎回ビルドし直した実バイナリを Playwright で駆動するため、埋め込み済み UI が古いままだと E2E が失敗します。
- `make verify-generated` は `api/openapi.yaml` から Go と TypeScript の型を再生成し、コミット済みの生成物と一致しなければ失敗します。生成物を手で編集してはいけません。
- 自動テストは実際の `~/.ssh`、ssh-agent、リモートホストへ一切触れません。実バイナリを起動する試験でも `HOME` は一時ディレクトリです。実際に外部へ影響する操作（実接続、実 `authorized_keys` 変更、実ホストへのホスト鍵取得）は `docs/manual-acceptance.md` の手動試験に分離しています。`internal/sshclient` は 127.0.0.1 に立てたプロセス内の SSH サーバーと本物の握手を行いますが、そこもリモートではありません。
- 設計 §12 の完成条件は `go test ./internal/acceptance -run TestDesignCompletionConditions -v` で一覧できます。各条件について、それを証明するテスト名とコマンド名、そして自動化が届かない範囲を出力します。13 行のうち 7 行が自動テストのみで成立し、5 行は自動化が越えてはならない境界で止まり、1 行は OpenSSH が入っている場合にのみ証明されます。
- `internal/acceptance` はテストファイルのみで構成され、配布バイナリには含まれません。`TestNoTestOnlyPackageReachesTheShippedBinary` がそれを検査します。
- ログへの秘密混入検査は `app.Build` へ渡した logger だけを見ています。グローバルの `slog` 既定 logger へ書くと検査を素通りするため、新しいログは必ず注入された logger を使ってください。
