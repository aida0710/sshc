# 実行先

サイドバーの下の［実行先］で、ターミナルをどのsshcエンジンで動かすかを選べます。SSHの接続先（たとえば常時動いているサーバー）でsshcエンジンを常駐させておくと、このPCのブラウザからそのsshcエンジンのターミナルを使えます。ブラウザやこのPCを閉じても、ターミナルは接続先で動き続けます。エージェントを長時間動かしておく使い方に向いています。

変わるのはターミナル（セッションと[ワークスペース](./workspace)）だけです。Connections、SFTP、Vault、設定はこのPCのままです。

## 使い方

1. 接続先に、このPCと同じバージョンのsshcを入れ、`sshc service install`などでsshcエンジンを常駐させます。
2. このPCのターミナルで、一度その接続先へ接続してホスト鍵を確認します。パスフレーズやパスワードが要る場合は、Connectionsで保存しておきます。
3. サイドバーの下の［実行先］を開き、［sshcエンジンを追加…］から接続先を選びます。
4. 一覧で接続先を選ぶと、ワークスペースとセッションがそのsshcエンジンのものに替わります。ターミナルの見出しには、どの接続先で実行中かを表示します。

一覧の［…］から、［sshcエンジンの情報…］、［別タブで画面をまるごと開く］（接続先のsshcエンジンの画面を別のタブで開く。`sshc open <alias>`と同じ）と、［一覧から外す］を選べます。一覧から外しても、接続先のsshcエンジンとそのターミナルは止まりません。

選んだ接続先のVaultがロックされていると、そのVaultのパスワードを尋ねます。パスワードは、このPCのsshcエンジンがSSH接続の中で接続先のsshcエンジンへ渡すだけで、このPCには保存しません。［キャンセル］したときは、Workspacesの下の［ロックを解除…］からいつでも解除できます。

## sshcエンジンの情報

［sshcエンジンの情報…］では、接続先のsshcエンジンのバージョン、Vaultの状態、動いているセッションの数を表示します。ここから次の操作ができます。どれも接続先のターミナルをすべて終了させるので、実行の前に確認します。

- ［更新］: 接続先で`sshc update --yes`を実行します。このPCを先に更新したあと、接続先をそろえるのに使います。
- ［再起動］: 接続先で`sshc service restart --yes`を実行します。sshcが管理するserviceとして動いているsshcエンジンに限ります。
- ［停止］: 接続先で`sshc stop`を実行します。もう一度使うには、接続先で`sshc open`か`systemctl --user start sshc`を実行します。

［更新］と［再起動］のあと、パスワードを設定したVaultはロックされます。Vaultの行の［ロックを解除…］から解除できます。

接続先の`sshc`が書いた出力の末尾を、ダイアログの中に表示します。

## 条件と制限

- 接続先のsshcは、このPCと同じバージョンである必要があります。違う場合は、接続先で`sshc update`を実行するよう表示します。
- 接続先のSSHサーバーが、接続先の`127.0.0.1`へのTCP転送を許可している必要があります（`AllowTcpForwarding`が`yes`か`local`）。
- 接続先にVaultがまだ無いときは、［別タブで画面をまるごと開く］で作ってください。
- ポート転送、コマンドの一括送信、クイックコマンドは、このPCで動くターミナルだけで使えます。
- 選んでいない実行先の通知（未読の印）は表示しません。
- 接続先はmacOSかLinuxに限ります。

## しくみ

このPCのsshcエンジンが、接続先へSSH接続を1本だけ開き、その中でターミナルの操作と入出力を取り次ぎます。どちらのマシンでも、待ち受けは`127.0.0.1`だけです。接続先のsshcエンジンへは、接続先の`sshc`コマンドと同じ方法で入り、ブラウザの登録は増やしません。
