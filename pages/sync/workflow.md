# Push・Pull・履歴

sshcは同期時に自動マージを行いません。ローカルとリモートのリビジョンを比較し、どちらを送るのか、受け取るのかを明示します。

## 通常の流れ

1. **バケットの状態を更新**して、最新のスナップショットと履歴を取得
2. **変更を確認**して、追加、変更、削除の内容を確認
3. ローカルを正とするなら**Push**、リモートを正とするなら**Pull**
4. 競合や削除がある場合は、内容を確かめてから操作を選択

`sshc sync now`は設定された同期方向に従い、安全に判断できる操作だけを自動で実行します。

## 自動同期

自動同期は1分ごとにリモートの更新を確認します。この確認ではアップロードしません。sshcで設定を変更した場合は、最後の変更から5秒間ほかの変更がなければ1回だけPushします。外部エディターによる変更は次の受信確認で検出し、同じ5秒待機を経てPushします。リモート側が更新されていれば、Pullできるか、停止すべきかを先に判断します。

## 強制操作

Force Push／Pullには、最後に確認したETagとリビジョンにだけ使える短時間有効のトークンが必要です。その後に別の端末がリモートを更新していれば、操作は拒否されます。途中でバケットを変更した場合も、以前の確認結果を新しい保存先へ流用できません。

## 履歴

sshcはS3バケットを直接確認し、最新のスナップショットと日付付きの履歴を図で表示します。履歴の一覧は復号せずに取得できますが、内容の差分確認や復元には同期キーが必要です。

## CLI

```sh
sshc sync
sshc sync push --json
sshc sync pull --json
sshc sync now --json
sshc sync auto on
```

CIや画面のないホストでは`--json`を使い、終了コードと一つのJSONオブジェクトの両方を確認してください。
